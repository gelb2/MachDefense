# 포팅판 치트 검증과 재개발 비교 계획

2026-11-04 사용자 지시. 포팅판의 별도 치트앱과 시뮬레이터로 전체 기능을 검사한 다음 소스 재개발을 시작한다. 사용자가 플레이 중인 아이폰 일반 포팅판은 종료·재설치·저장 변경을 하지 않는다.

## 현재 근거

현재 Xcode 타깃은 일반 포팅판 하나다. 원본 ARMv7 실행 파일을 호환 실행기로 구동한다. 치트앱·치트맵은 아직 없다. 원본 QTable 해독과 슬롯 생성·전투·저장 경로는 실행됐다. 맵·저장 각 필드와 전체 콘텐츠 개수는 추가 확인이 필요하다.

HeavyMach 1의 `docs/cheat-stage-check.md`에서는 무적·탄약 보충으로 실제 교전·승리·진행 저장을 검사했다. 코어 검사와 실제 앱의 메뉴·재실행 검사는 따로 수행했다. MachDefense에도 이 구분을 적용한다. HeavyMach 1의 수치·주소·맵 형식은 가져오지 않는다.

## 구현 순서

1. **기능 목록 작성.** 원본 화면·버튼·데이터 표·함수를 대조해 프로필, 맵, 유닛, 공격, 강화, 옵션, 도움말, 결과 화면을 목록화한다. 표시된 기능별로 테스트 ID와 결과를 연결한다. 폐쇄된 외부 서비스와 광고 비표시 정책은 따로 기록한다.
2. **치트앱 분리.** `MachDefense Port Cheat` 타깃과 `com.gelb2.machdefense.compatibility.cheat` 식별자를 만든다. 원본 IPA는 변경하지 않는다. 테스트용 저장·맵 사본은 별도 앱 컨테이너와 Git 제외 로컬 경로에서만 쓴다. 일반 앱에는 치트 설정을 포장하지 않는다.
3. **테스트 시작 조건 생성.** 원본 슬롯 읽기·쓰기와 맵 로딩 구조를 확인한다. 새 프로필, 자금 부족, 충분한 자금, 강화 직전·최대 단계, 각 스테이지 시작, 클리어 직전 상태를 만든다. 데이터 사본으로 구성 가능한 항목을 먼저 구현한다. 불가능한 항목만 치트 빌드의 제한된 런타임 설정으로 제공한다. 변경 필드·원본 해시·초깃값을 남긴다.
4. **짧은 기능 검사 맵 구성.** 원본 맵 형식을 확인한 뒤 필요한 유닛·공격·생산 조건을 짧게 재현하는 맵을 만든다. 이 맵은 기능 검사에 사용하고, 원본 캠페인의 각 맵과 전환은 원래 배치로 별도 실행한다.
5. **시뮬레이터 전체 검사.** 아래 항목을 실제 앱 입력으로 확인한다. 조건 설정만 치트로 단축한다. 게임 결과·보상·클리어 플래그를 직접 쓰고 클리어 처리에 성공했다고 판정하지 않는다.
6. **실기기 검사.** 시뮬레이터에서 확인한 설치·입력·키보드·전환·음향·저장 경로를 iPhone/iPad에서 확인한다. 사용자 일반 슬롯은 건드리지 않는다. 물리 기기의 프레임·메모리·발열은 실기기 측정으로 남긴다.
7. **포팅판 기준 확정.** 호환 오류를 고친 빌드와 기능별 입력·초기 상태·결과·영상·저장 사본을 보존한다. 미검사와 실패 항목이 어떤 기능인지 명시한다. 게임 진행을 막는 오류를 해결한 뒤 재개발로 넘어간다.
8. **소스 재개발과 대조.** 준비된 소스·에셋만으로 빌드하는 앱을 만든다. 같은 프로필·맵·자원·입력 조건을 포팅판과 재개발판에서 실행해 생산·이동·공격·강화·승패·보상·저장·화면·음향을 대조한다. 원본 화면 기준 대조 후 넓은 화면 대응을 별도 검사한다.

## 기능별 검사

| 범위 | 실제로 확인할 동작 |
|---|---|
| 프로필 | 생성, 이름 입력·삭제·취소·확인, 빈 이름·길이 경계, 슬롯 선택·전환, 원본에 삭제 기능이 있으면 삭제, 종료 후 유지 |
| 생산·교전 | 원본에 있는 모든 생산 항목·공격, 자원 차감·회복, 생산 대기, 배치·이동·타깃·피격·파괴, 기지 피해 |
| 강화 | 기지·유닛·장비 각 강화, 자금 부족·충족, 선행 조건, 최대 레벨, 실제 비용·능력치·외형 변화, 닫기·재열기·재실행 |
| 캠페인 | 모든 원본 스테이지의 실제 승리·패배, 결과·보상, 다음 스테이지 해금·진입, 재도전, 마지막 스테이지 이후 화면 |
| 저장 | 명시적 저장·종료, 재시작, 여러 슬롯의 독립성, 진행·강화·자금 복원, 실패·취소 후 값 보존 |
| 메뉴·모달 | 원본의 모든 메뉴·옵션·도움말·버튼, 모달 중 배경 입력과 게임 시간, 일시정지·재개 |
| 생명주기 | 백그라운드·복귀·잠금·해제·음향 중단 후 복귀, 종료·재실행 |
| 화면·음향 | 원작 부품·애니메이션·UI·효과음·음악, 입력 위치와 표시 위치, 시뮬레이터와 실기기 차이 |

무적·자원 고정은 피해·패배·비용 검사를 가릴 수 있으므로 해당 검사에서는 끈다. 충분한 자금을 한 번 설정하고 실제 구매 전후 차감을 검사한다. 클리어 직전 조건은 마지막 적이나 기지가 남은 상태에서 실제 전투로 승리하도록 구성한다. 독립 맵 검사가 끝나면 연속 스테이지 전환과 앱 재실행도 검사한다.

## 증거와 완료 기준

검사 기록에는 앱 종류·빌드 SHA·원본 SHA·기기/OS·맵/슬롯·치트 조건·입력·예상·실제 결과·저장 전후 해시·스크린샷/로그 경로를 담는다. 시뮬레이터 코어 결과와 화면 버튼 결과를 혼합하지 않는다. 각 실패는 호환 실행기, 테스트 설정, 원작 관측 동작, 재개발 구현 중 어디에서 발생했는지 대조한다.

기능 목록의 전체 개수를 원본에서 확정하고 통과/실패/미검사 개수를 함께 남긴다. 재개발판은 원본 IPA가 없는 환경에서 빌드·실행을 확인한다. 브랜치는 현재 `feat/ios-compatibility`에서 작업하며 feature→develop→main 규칙을 따른다. 원본 IPA와 추출 실행 파일·포팅앱 패키지는 외부에 올리지 않는다.
