# AH-10 로켓·공습 파츠 분리

2026-11-09. 승인된 AH-10의 정면·좌우 선회 7개 그림에서 로켓 발사대와 공습 미사일 발사대의 픽셀을 분리했다. 기존 기체를 새 그림으로 교체하지 않았다. 두 무장 노드는 `tileCount=0`인 비표시 발사점에서 실제 7타일 그림을 사용하는 파츠가 됐다. AH-10의 표시 파츠는 6개에서 8개로 늘었다.

## 실제 조립과 보존

[제작 명세](../../Art/Aircraft/parts-separation-20261109/ah10/manifest.json)와 [분리 도구](../../tools/prepare_ah10_parts.py)는 승인 입력, 픽셀 소유 영역, 준비 PNG와 최적화 자원의 해시를 기록한다. 제작 단계 재합성은 입력과 바이트가 같고, 중복 알파 픽셀은 0이다. CgBI로 저장한 세 자원을 해독해 합쳐도 기존 게임 몸체의 RGBA 238,336바이트와 같다.

`WorldCombat`의 기존 구현은 이 두 발사대를 기체 방향에 고정하고 주퇴를 0으로 둔다. 이 동작을 유지했다. 따라서 별도 회전 무장을 만들거나 가려진 받침을 새로 그릴 필요가 없었다. 앞선 생성 후보는 이번 게임 자원에 적용하지 않았다. 독립 회전·새 주퇴를 추가하면 생길 수 있는 몸체 빈 영역 문제와 현행 고정 무장의 동작을 구분한다.

기존 공통 파츠 조립·MCB·이미지 표·타일 표와 Apple PNG 최적화를 사용한다. 헬기 전용 선회 그림 선택에 두 고정 파츠만 추가했다. 원작 공통 조립·전투·이동·렌더러는 수정하지 않았다. 다른 헬기의 그림과 승인된 AH-10의 크기·색·선회 형상도 보존한다.

최종 채택본은 각 파츠의 76×112 셀과 7타일 간격을 유지한다. 새 두 텍스처의 POT RGBA 크기는 합계 1MiB이며, AH-10 한 기당 표시·그림자 제출이 4개 늘어난다. 압축 이미지 파일 증가량은 기존 몸체 대비 2,407바이트다.

세로 여백을 줄여 256KiB로 만든 두 후보를 시험했지만, 웹 화면에서 50~61픽셀의 차이가 생겼다. 투명 여백을 32행으로 늘린 후보도 해결하지 못했다. 두 후보는 채택하지 않았고 최초 전체 캔버스 분리본으로 복원했다. [복원 해시](ah10-parts-20261109/restored-fullcanvas-sha256.json), [첫 crop 실패](aircraft-parts-20261109/ah10-web-ycrop-rejected.json), [두 후보와 최종 선택](aircraft-parts-20261109/ah10-web-summary.json). 공용 렌더러를 바꿔 차이를 숨기지 않았다.

## 총구와 검사

이미지 피벗을 옮겨도 기존 총구 위치가 유지되도록 socket 0과 발사 소켓을 함께 보정했다. 10레벨·3배율·3방향·7선회·2무장의 [1,260개 조건 검사](ah10-parts-20261109/core-tests.log)에서 기존 총구 좌표와 같았다. 기존 240개 레벨 조립 비교와 Aircraft·Definition·Armament·FireEffects·Handling 5검사도 통과했다.

정면 제작 좌표의 기존 총구는 로켓 (55,22), 공습 (74,74)다. 같은 행의 그림 끝보다 각각 7px·6px 앞에 있다. 가장 가까운 알파 픽셀까지의 거리는 각각 약 5.385px·6px다. [좌표와 거리](ah10-parts-20261109/muzzle-gap-distances.json). 이번 분리는 이 기존 발사 위치를 보존했으며, 그림 끝에 새로 맞췄다고 보고하지 않는다.

[최종 웹 검사](aircraft-parts-20261109/ah10-web-summary.json)는 Chrome·WebKit에서 4종×10레벨을 각각 600 tick 실행했다. 발사·피해·회피·소리가 발생했고 저장 쓰기는 0, 오디오 컨텍스트 수명 변화는 0이었다. 공격 중 20장 캡처는 기준과 픽셀이 같다. 정지·선회 14장 중 12장은 같고 나머지 2장은 −24도 AH-10 가장자리의 3픽셀에서 채널값이 최대 1/255 달랐다. 원작 탱크와 다른 세 헬기 영역의 차이는 0이다. 합성 순서에 따른 반올림으로 추정하지만 원인을 확정하지 않았다.

[보존 대조](aircraft-parts-20261109/ah10-web-preservation.json)에서 기준 Sources/Resources 2,681개 중 변경은 AH-10 몸체, 헬기 확장 정의 2개, 표 2개, 헬기 전용 표시 helper뿐이다. 새 무장 PNG 2개는 별도로 추가했다. 정규 웹 패키지의 그림 3개·정의 4개도 최종 Resources와 같다.

## 100기 전투 계측

[전체 조건과 측정값](aircraft-parts-20261109/ah10-web-performance.json). Mac의 Chrome/ANGLE Metal에서 검사 전용 장면을 사용했다. 네 헬기 각 25기와 수동 표적 100개를 두고 실제 무장·이동을 유지했다. 표적은 반격하지 않으며 캠페인·아이폰 측정은 아니다. 제품 소스 변경 없이 검사 전용 Main의 발사 허용 인수만 바꿨다. 플레어 끔·켬 각각 600프레임을 기준→후보→기준→후보 순서로 측정했다.

| 비교 회차 | 플레어 | 기준 GPU p95 | 후보 GPU p95 |
|---|---|---:|---:|
| 1 | 끔 | 6.81ms | 10.77ms |
| 1 | 켬 | 9.96ms | 11.54ms |
| 2 | 끔 | 8.43ms | 8.73ms |
| 2 | 켬 | 8.37ms | 11.21ms |

후보 GPU p95가 대응 측정에서 모두 높았다. RAF 간격 p95는 양쪽 모두 16.7~16.8ms였으며 긴 프레임도 발생했다. 후보의 25ms 초과 간격은 각 실행에서 2~3회, 최대 약 50~67ms였다. 전체 성능 동등이나 프레임 저하 없음으로 판정하지 않는다. 두 교대 측정과 통제하지 않은 호스트 부하만으로 차이 전체의 원인을 확정하지 않는다. GPU 쿼리는 게임의 그리기 명령 범위이며 브라우저 합성·디스플레이 지연을 포함하지 않는다.

측정 중 heap은 128MiB로 유지됐고 저장 쓰기는 0이었다. 기준·후보 모두 첫 측정에 기존 `Efx_Flame.png` 업로드가 1회 있었고 다음 플레어 측정에는 0이었다. 준비 전 RAF 시각이 섞인 최초 진단값은 최종 비교에서 제외했다. WebKit은 해당 GPU 타이머를 지원하지 않아 GPU 수치를 만들지 않았다.

## 이어지는 작업

4종 Lv.1–10의 새 강화 외형, 추가 도색·질감·입체감, 기존 움직임을 보존한 표적 밀착 방지와 최종 시각·성능 검사가 남아 있다. 이번 분리는 AH-10의 비표시 무장 파츠 연결이며 전체 헬기 작업 완료가 아니다. 게임 main·운영 PWA·아이폰 배포는 수행하지 않았다.
