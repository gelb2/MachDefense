# 레이저 포탑의 해금 상태

2026-11-07 사용자 질문에 따라 원본 패키지 3개의 `MachRegen.tble`을 읽고 현재 `Resources/Tables/MachRegen.tsv`와 비교했다.

세 원본 모두 `//LaserTurret 20`으로 주석 처리돼 있다. 현행 테이블도 같다. `DataTable`은 `//` 행을 건너뛰며 `Settlement::addBuild`는 이 테이블의 활성 행에서만 새 유닛을 뽑는다. 초기 보유 유닛 4종에도 레이저 포탑은 없다.

변경 전 복원판은 특정 미션에 레이저 포탑을 고정 배정하지 않는다. 미션 최초 클리어 때 난수 `%40 <= 9` 조건을 통과하면 미보유 유닛 중 가중 추첨한다. 레이저 포탑은 목록에 없으므로 일반 진행으로 획득할 수 없다. 그림·무장·강화 데이터는 존재해 치트나 해당 유닛을 보유한 복원 데이터에서는 사용할 수 있다.

앞선 부품 연결은 보상표·초기 보유 목록·정산 코드를 변경하지 않았다. 이후 사용자가 일반 해금 추가를 지시해 아래 규칙을 구현했다.

## 추가한 해금 규칙

발칸 보유 + 미션 30 클리어가 기준이다. 발칸이 늦게 나오면 그다음 클리어에서 레이저를 준다. 30 이후 기존 저장은 프로필 선택 시 바로 지급한다. 44미션 이후 사용자도 같은 규칙을 적용한다. 발칸 추첨 자체를 변경하지 않아 모든 사용자가 반드시 40 이전에 받는 규칙은 아니다. 신규 레이저는 Lv.1이며 보유한 레이저의 레벨과 INSTALL 상태를 초기화하지 않는다.

미션 정산에서는 기존 새 유닛 보상창으로 표시한다. 기존 저장에 소급 지급할 때는 인벤토리에 추가한다. 이미 설치한 유닛이 7개 이상이면 기존 획득 처리처럼 미설치 상태로 추가하고 강화 메뉴에서 INSTALL할 수 있다. 기존 유닛의 상대적 순서·레벨·설치 상태는 유지한다. 신규 유닛만 원작의 종류·가격순 삽입 규칙으로 넣는다.

| Lv.1 표 값 | 라이플 | 미사일 | 발칸 | 레이저 |
|---|---:|---:|---:|---:|
| 생산 셀 | 200 | 300 | 600 | 200 |
| 강화 크레딧 | 200 | 300 | 1,000 | 200 |
| 탄당 피해 | 20 | 100 | 20 | 20 |
| 사거리 | 220 | 240 | 300 | 220 |
| 연사 수 | 14 | 3 | 40 | 14 |
| 발사 간격(초) | 0.18 | 0.45 | 0.08 | 0.18 |
| 내구력 | 600 | 1,300 | 1,300 | 1,500 |

레이저는 원작부터 Gun 타입이며 Plasma02/05.wav와 ExplodePlasma를 사용한다. 이름 때문에 광선 타입으로 바꾸지 않았다. 발칸보다 저렴하고 연사량·사거리가 작다. 기존 유닛들을 경험한 뒤 추가 선택지로 받도록 30미션을 택했다. 이 배치는 이번 사용자 지시에 따른 판단이며 원작에 존재한 미션 지정은 아니다.

## 검증

- C++ 관련 검사 9개 통과: Menu, Settlement, GameSession, SaveFailure, SaveTransfer, TransferMenu, Level10Data, TransferLevel10, LaserUnlock.
- 0·29·30·39·44·79·80 진행도, 발칸 보유/미보유, 중복 지급, 기존 Lv.10 레이저 보존, 64개 난수의 30미션 보상, 기존 유닛 순서·설치 상태 보존을 검사했다.
- 실제 공용 메뉴 입력으로 선택 → 지급 → 저장, 저장 실패 시 되돌리기 → 재시도, 코드 복원 → 선택 → 지급을 검사했다. 저장 형식은 바꾸지 않았다.
- 아이폰 저장 백업의 로컬 복사본에서 1개 지급과 복원 코드 왕복을 확인했다. 사용자 기기의 저장은 이 검사로 변경하지 않았다.
- 1–10레벨의 생산 큐·운반 봇·포탑 조립·발사·대상 피해·기존 음원 호출·렌더 자원 존재를 검사했다. 운반 봇은 치트 검사에서 도착 위치로 옮겨 조립을 진행했다. 음원 호출 검사는 스피커 출력 청취를 대신하지 않는다.
- 새 WebAssembly 치트 빌드를 Chrome·WebKit에서 실행해 아이폰 저장 복사본의 지급, 다른 슬롯·자금 보존, 600틱 추가 쓰기 없음, 재실행 후 중복 지급 없음을 확인했다. 이 검사 시점에는 기기 앱을 업데이트하지 않았다. 이후 설치 결과는 아래에 기록했다. 운영 PWA는 아직 변경하지 않았다.

로컬 검사 자료는 `.local/laser-unlock/`, 구현 검사는 `Tests/LaserUnlockTests.cpp`, 브라우저 검사는 `Web/tests/laser-unlock.mjs`에 있다.
