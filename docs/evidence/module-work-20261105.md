## 원본 대조와 수정

WeMade 1.0.3 ARMv7 SHA-256: `6ec47ea094abaa31bab10058fe47bb25d46c6038b2e88a7da2629899f84af112`. 기존 REA/Ghidra 분석 프로젝트를 읽기 전용으로 열어 누락된 오디오·텍스처 함수를 추가 확인했다. REA MCP의 Java 탐지에서 프로세스 목록 오류가 나왔으며, 설치된 같은 Ghidra/JDK의 로컬 headless 실행으로 분석했다. 바이너리와 디컴파일 출력은 저장소 밖에 보존했다.

| `0x48ddc`, `0x49200` | 초기화 후 컨텍스트 유지, 기존 source를 stop/play | 기존 재사용·컨텍스트 유지 수정 보존. 포팅판의 OpenAL Soft 1.22.2 소스를 해시와 함께 반입해 정적 링크 |
| `0x49a20` | AudioFile에서 PCM 원본 바이트 읽기. 모노/스테레오, 8/16비트 보존 | ExtAudioFile의 일괄 PCM16 변환 제거. 77 WAV를 원래 형식으로 업로드 |

현재 준비된 PNG 948개는 전부 8비트 RGBA다. 원본의 낮은 비트 깊이 이미지용 RGB565 분기는 이 자원 집합에 해당하지 않는다. 이미지·음원 파일 자체는 변경하지 않았다.

피격음 위치도 원본 `GobHvMach::onDamage`의 카메라 상대 좌표와 제곱근 계산으로 수정했다(`0x141a2`–`0x14216`). 음수 좌표에서 NaN이 나오면 원본 OpenAL처럼 이전 source 위치를 유지한다. `HostServices.playSoundAt`으로 전달하며 음원 선택·난수·피해 계산은 유지했다. ActionAudio 검사가 좌표 1·2와 음수 입력을 확인한다.

## 모듈 구조와 분리 확인

원본 오디오·텍스처 수정은 `f623eba`에 먼저 커밋했다. Core 58개 파일을 Contracts·Data·Simulation·Session·Presentation·Validation로 옮겼다. 이동 직후 include 경로를 제외한 본문이 일치함을 확인했다. [이동 목록](module-file-moves-20261105.json).

그다음 Battle과 World에서 스폰·이동·표적·지형·피해·경제·그리기·검증 함수를 나눴다. 월드 갱신과 난수 호출 순서는 유지했다. 현재 CMake 공용 코어 목록은 39개 cpp다. 포구 계산과 화면 부품 조립은 같은 MachineModels를 사용한다.

효과음은 `Sources/Audio/OpenALEffects`로 분리했다. Apple의 MDAudio는 파일 디코딩·AudioQueue 음악·생명주기를 연결한다. 메뉴·HUD·강화·도움말·치트 UI는 계속 Core의 원작 에셋·SpriteFont·Button·Frame으로 구성한다.

C++ 검사 34개가 통과했다. 160개 조건·144,000틱의 분리 전·파일 이동 후·함수 분리 후·최종 기록은 모두 일치했다. 비교에는 액터·탄환·난수·그리기 명령·저장 바이트·음원 호출 순서가 포함된다. 원작 피격음 위치 복원은 별도 좌표 검사로 확인했다.

Apple 전체 검사에서는 오디오 4개·게임/메뉴 14개·렌더러 8개를 실행한다. 80미션과 191강화행 반복 검사에서는 음악 전환 요청을 대조하고, 압축 음악의 실시간 출력은 별도 3곡·반복·복귀 검사에서 확인한다. 대량 검사마다 음악 큐를 수백 번 닫고 여는 시간은 게임 계산 검사에서 제외했다. 효과음·GPU·디스크 저장은 실제 출력을 사용한다.

중간 실행에서 WAV 77개를 기존의 80개(음악 포함)로 기대하던 검사 실패를 수정했다. 당시 실행은 중단했고 수정 후 다시 검사했다.

## 성능 측정과 누수 검사

iPad 전체 검사 중 1,800프레임 측정은 50초 제한에 걸렸다(1,503프레임). 나머지 25개 검사는 통과했다. 프레임 측정을 끝까지 수집하도록 검사 대기 한도를 120초로 바꿨다. 제품의 시간·렌더링 코드는 바꾸지 않았다.

Instruments Time Profiler 30초 기록에서 메인 스레드 표본 25,801개 중 MDRenderer 경로가 99.13%, 시뮬레이터 GLRendererFloat가 91.33%였다. OpenALEffects.play 표본은 0개다. 별도 3초 프로세스 샘플도 GLRendererFloat의 삼각형/픽셀 처리에 집중됐다. 시뮬레이터의 OpenGL CPU 렌더링이 이번 지연의 주된 원인이다.

`leaks`는 37,975개 할당 노드·40,007KB를 검사해 누수 0건을 보고했다. 10분 전투에서는 텍스처 업로드가 13개로 유지됐다. 60~120초 메모리 최솟값은 117,229,776바이트, 마지막 60초 최솟값은 129,534,280바이트였다. 중간에 화면 관측 도구가 접근하면서 접근성 번들이 로드됐고, 마지막 3분은 약 129.5MB에서 유지됐다. 30초마다 월드를 재시작하고 오디오 중단·복귀와 drawable 재생성을 총 19회 실행했다. 처음 시작을 포함하면 20회다. 실제 메뉴를 20회 왕복한 검사는 아니다. 실제 iPad의 GPU 성능과 최종 출력음 확인은 후속 검사다.

원본 수정 후 코어 분리 전후 기록 외에 일반/치트 세션도 비교했다. 같은 저장과 입력으로 미션 진입·생산·일시정지·복귀를 진행했을 때 TEST 버튼을 제외한 프레임 명령·음원·저장 값이 일치했다. 일반 모드는 치트 명령을 거절했다.


iPad 재측정은 1,800프레임을 64.25초에 수집했다. 대기·기관총·적 포탄·동시 사격 순서의 프레임 간격 p95는 34.09·41.65·41.73·50.80ms, CPU 처리 p95는 25.25·29.12·29.12·38.58ms였다. iPhone 검사의 같은 순서 CPU p95는 15.73·19.23·19.34·23.48ms였다. 시뮬레이터에서 60fps 통과로 판정하지 않는다. 실제 기기 결과와 분리해 보존한다. 로그는 `ipad-cadence-retry.xcresult`, `ipad-module-time.trace`, `ipad-module-leaks.txt`, `ipad-soak.xcresult`다.


## 설치 앱 직접 조작

iPad Air 시뮬레이터에서 원본 패키지 없는 별도 빌드의 일반 앱을 설치했다. 화면을 직접 눌러 MODCHECK 프로필 생성 → Stage 1 → 도움말 닫기 → 기관총·미사일 생산 → 메뉴 → Save & Exit를 실행했다. 생산 대기열·셀 차감·자원 부족 딤·유닛 출현을 확인했다. 프로세스를 종료하고 다시 실행해 프로필을 불러왔고, 42,496바이트 저장 파일이 종료 전과 일치했다. 일반 앱에는 TEST 버튼이 없었다.


치트 앱에는 같은 시험 저장을 복사했다. 기존 시험 저장은 먼저 백업했다. Stage 1에서 TEST 패널을 열어 크레딧 1,000 추가·셀 500 충전·SAVE 버튼을 눌렀고 화면 값 갱신을 확인했다. 검사 후 일반·치트 앱 프로세스를 종료하고 시뮬레이터 홈 화면을 확인했다. 실제 iPhone·iPad 설치본과 사용자 저장은 변경하지 않았다.
