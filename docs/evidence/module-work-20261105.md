## 원본 대조와 수정

WeMade 1.0.3 ARMv7 SHA-256: `6ec47ea094abaa31bab10058fe47bb25d46c6038b2e88a7da2629899f84af112`. 기존 REA/Ghidra 분석 프로젝트를 읽기 전용으로 열어 누락된 오디오·텍스처 함수를 추가 확인했다. REA MCP의 Java 탐지에서 프로세스 목록 오류가 나왔으며, 설치된 같은 Ghidra/JDK의 로컬 headless 실행으로 분석했다. 바이너리와 디컴파일 출력은 저장소 밖에 보존했다.

| 원본 근거 | 확인한 동작 | 수정 |
|---|---|---|
| `0x48ddc`, `0x49200` | 초기화 후 컨텍스트 유지, 기존 source를 stop/play | 기존 재사용·컨텍스트 유지 수정 보존. 포팅판의 OpenAL Soft 1.22.2 소스를 해시와 함께 반입해 정적 링크 |
| `0x49a20` | AudioFile에서 PCM 원본 바이트 읽기. 모노/스테레오, 8/16비트 보존 | ExtAudioFile의 일괄 PCM16 변환 제거. 77 WAV를 원래 형식으로 업로드 |
| `0x48e84`, `0x49bb8`, `0x49d38` | BGM은 AudioFile/AudioQueue. 압축 패킷 버퍼와 반복 재생 | MP3를 OpenAL 버퍼로 만들던 처리 제거. 음악 큐와 효과음 경로 분리 |
| `0x4b590`, `0x4b22c` | 이미지 바깥을 투명하게 지운 2의 거듭제곱 텍스처와 실제 콘텐츠 크기별 UV | NPOT 이미지 패딩·UV 처리 복원. 포팅판의 PNG premultiply 소수점 절삭 적용 |

현재 준비된 PNG 948개는 전부 8비트 RGBA다. 원본의 낮은 비트 깊이 이미지용 RGB565 분기는 이 자원 집합에 해당하지 않는다. 이미지·음원 파일 자체는 변경하지 않았다.

위치 효과음은 별도 대조 항목이다. `GobHvMach::onDamage`의 카메라 상대 위치 계산과 현재 중앙 재생의 차이를 발견했다. 음원 순서·피해 계산을 바꾸지 않고 후속 대조해야 한다. 이번 라이브러리 교체만으로 이 항목까지 완료했다고 집계하지 않는다.

## 변경 전 검사

- C++ 33개 통과. Release, 같은 macOS arm64 컴파일러.
- iPhone Air 시뮬레이터 전체 검사에서 뒤쪽의 구매 검사와 실시간 전투 검사가 오디오 초기화에 실패했다. 80미션 진행·저장과 강화·무장 검사 결과는 로그에 보존했다. 무음인 실행의 프레임 수치를 정상 오디오 성능으로 사용하지 않는다.
