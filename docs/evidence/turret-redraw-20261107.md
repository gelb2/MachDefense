# 포탑 재시안과 레이저 해금 앱 — 2026-11-07

공용 몸체 Lv.6–10 5개와 무장 6종 Lv.6–10 30개를 다시 그렸다. 원작 Lv.3·4·5, 추가 부품, 몸체와 무장 조립 모습을 같은 배율로 비교했다. 새 그림은 검토용이며 현재 설치한 앱의 그림은 교체하지 않았다.

## 사용자 후속 검수 — 표면 질감

사용자는 HeavyMach1에서 원작 텍스처를 따르도록 지시했던 점을 상기시키며 이번 시안이 표면 질감을 간과했다고 지적했다. HeavyMach의 `integrate-game-art`와 `Art/GroundAA/20261028-texture-proposal/prompts.json`에도 원작 금속 재질·짧은 마모·명암 면을 따르고 과한 흠집·노이즈를 피하라는 조건이 있다.

현재 시안은 색과 외곽을 맞춘 뒤에도 금속 내부가 매끈하고 밝은 띠가 연속적으로 이어진다. 원작의 잘게 끊긴 밝은 면, 얼룩진 중간톤과 어두운 틈을 충분히 맞추지 못했다. 비교 파일의 Lanczos 축소도 픽셀 경계를 섞으므로 생성 그림과 축소 과정 각각을 대조해야 한다. 이는 아직 질감 문제의 원인을 하나로 확정한 결과가 아니다.

몸체·라이플의 표면만 다시 그리는 시도를 추가했지만 몸체에 배경 얼룩이 생겼고 충분한 개선을 확인하지 못했다. 이 두 출력을 채택하지 않았으며 로컬 작업 자료로 보존했다. 다음 수정은 큰 시안의 매끈함을 기준으로 삼지 않고 원작 3·4·5단계와 같은 픽셀 크기의 금속 면·마모·명암 경계를 기준으로 한다. 무작위 노이즈나 새 실시간 효과를 더하는 방식으로 대체하지 않는다.

## 달라진 그림

원작 PNG를 최근접 보간으로 8배 확대해 생성 도구에 제공했다. 작은 금속 면과 불규칙한 경계 픽셀이 보이는 참조를 사용했다. 라이플의 굵은 포신, 발칸의 어두운 덩어리, 넓고 매끈한 음영을 줄였다. 몸체는 원작의 회녹색 링·은색 판·왼쪽 황토색 부품을 따랐다. 단계별 차이는 작은 판과 금속 띠에 한정해 이전 시안보다 작다.

새 그림에도 차이가 남는다. 라이플은 원작보다 세로 폭이 2–3px, 이온은 3px, 레이저는 5–6px 넓다. 레이저의 가는 포신 사이 빈 공간과 밝은 금속 면도 더 맞춰야 한다. 실제 크기에서는 단계별 차이가 약하므로 조립 상태의 구분도 보강 대상이다. 아래 35개를 게임 교체 완료로 처리하지 않는다.

## 레이저 해금 앱 설치

iPhone과 iPad에 정식·치트 앱 4개를 설치하고 실행했다. 설치 결과와 실행 결과는 모두 성공이다. 정식·치트 앱의 서명도 검사했다. 버전 표시는 기존 0.4(4)이며 실행 파일에 레이저 해금 변경을 포함했다.

아이폰의 기존 저장에서 프로필 선택 후 LaserTurret Lv.1이 추가됐다. 기존 12개 유닛의 레벨·순서·설치 상태를 비교했다. 진행도·자금·점수도 프로필 선택 전후 같았다. 저장 바이트를 해석해 비교한 결과, 새 인벤토리와 선택 시각·체크섬 외의 변경은 0바이트였다. 사용자가 직접 미션에 진입해 레이저포탑이 보인다고 확인했다.

발칸포탑 보유 + 미션 30 클리어가 지급 조건이다. 신규 진행은 기존 새 메크 획득 화면으로 알린다. 이미 조건을 지난 저장은 프로필 선택 시 인벤토리에 추가한다. 사용자는 이 동작을 확인하고 수용했다. 보상 화면과 Lv.1 레이저 그림은 원작 자원을 사용한다.

아이패드 정식·치트와 아이폰 치트 저장은 설치 전후 바이트가 같았다. 아이폰 정식 저장은 사용자가 그 사이 플레이해 자금과 점수가 증가했으므로 설치 직후 저장과 프로필 선택 후 저장을 별도로 비교했다. 오래된 백업으로 되돌리지 않았다.

iPad는 설치·실행·타이틀 표시를 확인했다. Device Hub가 ‘The connection was invalidated.’ 오류를 반환해 이번 수정본의 직접 터치·음원 청취 검사는 완료하지 못했다. C++ 9개와 로컬 Chrome·WebKit 검사는 앞서 통과한 동일 코드의 결과를 사용한다. 치트 검사 프로세스는 종료했다. 홈 화면 복귀의 최종 화면 확인은 남아 있다.
