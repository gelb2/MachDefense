## 설치와 게시

- iPhone·iPad에 정식·치트 앱 4개를 설치했다. 앱 내부 버전은 0.4(4)다. 각 저장을 설치 직전에 백업했고 설치 직후 바이트가 같았다.

## 운영 PWA

정식 산출물 `cf230badbf0c7bae`를 gh-pages `d57312c`에 게시했다. GitHub Pages 실행 `42263994352`가 성공했고 운영 주소에서 다음을 확인했다.

- Chrome·WebKit 정식 빌드: 복원 코드 왕복, 잘못된 코드 거절과 기존 저장 보존, 미션 진입, 백그라운드 복귀, GPU 복구, 오프라인 재실행, 오래된 탭의 저장 덮어쓰기 거절을 통과했다. 페이지 오류는 0건이다.
- Chrome·WebKit에서 실제 휠 입력으로 생산 목록을 움직이고, 설치 유닛의 Lv.10 강화창과 UNINSTALL 버튼을 확인했다.
- 기존 `5a81e986a50014a6` 캐시와 저장을 가진 Chrome 프로필을 사용했다. 첫 탭 재열기에서는 새 build.json과 이전 실행 데이터가 함께 관측돼 검사가 실패했다. 브라우저 프로세스를 종료하고 같은 프로필로 다시 실행한 뒤에는 WeaponInfo·MachList·BaseUpgrade가 최신 파일과 SHA-256이 같았다. 이전 저장도 바이트가 같았고, 오프라인 재실행·이전 캐시 제거를 확인했다.

새 서비스 워커 활성화와 이미 열린 게임의 교체 시점은 다를 수 있다. 이번 검사에서 브라우저 완전 재실행 후 갱신은 확인했다. 첫 탭 재열기의 전환 시점과 플레이 중 업데이트 안내는 후속 조사로 남긴다. 게임 실행 중 강제 새로고침은 추가하지 않았다.

검사 원본은 로컬 `.local/level10-hud-20261107/`의 `browser-regression-*-normal.json`, `production-level10-*.json`, `release-update-first-reopen-failure.json`, `release-update-verify.json`에 보존했다. 개인 저장은 게시하지 않았다.
