# 10레벨 확장과 생산 목록 스크롤 검사

2026-11-07 · `feat/title-hud-original-audit`

포탑 6종, 기지 공격·방어, 특수공격 5종에 59단계를 추가했다. 기존 INSTALL·UNINSTALL을 유지하면서 설치된 모든 유닛을 생산 HUD에서 스크롤할 수 있게 했다. 생산 대기열은 기존처럼 7개다. 순서 편집은 후속 과제다.

[성장 수치](../research/level10-plan-20261107.md) · [HUD 설계](../research/production-hud-scroll-20261106.md) · [남은 과제](../usability-todo.md)

## 구현

- 테이블의 열 구조와 기존 단계 성능을 유지했다. 기존 행은 최종 단계 8행의 다음 강화 가격만 변경했다.
- 원본 `PartsInfo.mcb`·`MachInfo.mcb`는 그대로 둔다. 추가 부품 39개·조립 33개는 같은 Chunk 형식의 `Level10Parts.mcb`·`Level10Machines.mcb`로 읽는다.
- 추가 단계의 유닛·포신·발사체·효과음은 원작 최종 단계 자원을 쓴다. 특수공격의 새 ItemId도 기존 Icon 참조로 연결한다.
- 특수공격 강화 비용은 보유 탄약 수를 포함해 64비트 정수로 계산한다. 큰 보유량 때문에 비용이 음수로 돌아가는 경우를 막았다.
- 가격표·아이콘·금속 틀·이름·딤·누름 효과와 터치 영역을 함께 이동한다. 고정 HUD는 유지한다. 보이는 행만 그리며 목록 끝을 지나 빈 공간으로 이동하지 않는다.
- 드래그는 생산 탭과 구분한다. 비용 부족이나 생산 대기열 포화로 비활성화된 행에서도 스크롤할 수 있다.
- 브라우저의 휠·트랙패드는 생산 목록 위에서 같은 스크롤 함수를 호출한다. 전장 카메라의 휠·키보드 이동은 별도 과제로 남는다.
- 기각된 타이틀 후보는 앱 자원에서 제외하고 조사 문서 폴더에 보관했다. 타이틀은 기존 배경 처리를 사용한다.

## 공용 코드

CMake/CTest 40개를 통과했다. 원본 테이블 대조는 기존 8행의 강화 가격 외에 변경이 없음을 확인했다. 원본 MCB 해시도 같았다.

레벨 검사에는 5슬롯 전체 단계 구매·자금 차감·상한·복원 코드 왕복, 큰 보유량의 비용 계산, 포탑 120조건, 기지 200조합, 특수공격 100조건을 포함했다.

사거리 수정 후 iPad 검사 2개를 다시 통과했다. 강화창의 ATK.·Range·DEF. 숫자 240프레임과 구매·복원·스크롤을 검사했다. 전투 299프레임과 전투 중 스크롤 300프레임 모두 간격 p99 16.67ms·25ms 초과 0회였다. CPU p95는 각각 5.31ms·5.52ms였다.

iPhone·iPad에 v0.4 정식·치트 앱 4개를 설치했다. 각 앱의 설치 직전 저장을 백업했고 설치 직후 바이트가 모두 같았다. 배포 앱에는 XCTest 플러그인을 넣지 않았다. 4개 앱 모두 실행·종료를 확인했고 두 기기는 홈 화면으로 돌렸다.

## 검사에서 고친 것

비활성 유닛 행에서 드래그할 때 매 게임 틱의 버튼 갱신이 드래그까지 취소했다. 생산 탭 가능 여부와 스크롤을 분리했다. 이동 사이에 게임 틱을 넣어 자금 부족 상태에서도 목록 끝까지 이동하고 마지막 유닛을 생산하는지 다시 검사했다.

추가 성능 검사에서는 미션 시작 버튼의 좌표와 측정 전 메뉴 저장 횟수를 잘못 가정했다. 실제 버튼 위치를 사용하고 측정 구간의 저장 횟수 증가를 검사하도록 고쳤다.

기존 검사 두 곳은 설치 7개·기지 강화 7단계를 고정값으로 사용했다. 원작 단계의 기대값은 남기고, 승인된 추가 단계와 설치 개수 조건을 반영했다.
