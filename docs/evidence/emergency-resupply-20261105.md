## 구현

- 기존 자금 버튼에서 원작 에셋으로 지원 창을 연다. 영문 3항목과 CLAIM·CLOSE, 다음 지급 시간, 남은 자원을 표시한다.
- 전투 시간 30/45/60초 고정 주기로 반복한다. 미수령분을 누적하고 셀의 부분 수령 잔액을 보존한다. 혼합 지원의 크레딧을 두 번 주지 않는다.
- 지원 창에서 전투를 멈춘다. 백그라운드에서 돌아오면 CLOSE를 눌러도 메뉴의 Resume을 눌러야 전투가 재개된다.
- 원작 글꼴로 GENERAL J·ADMIRAL B·MARSHAL P의 영문을 순차 표시한다. 본문을 누르면 전체 문장이 나온다.
- `EmergencySupport`와 `SupportDialog`를 공통 Core에 추가했다. 기존 슬롯 구조·저장 지점·자연 셀 생산·전투 타이머는 유지했다. 별도 OS 타이머·네이티브 버튼·파일 쓰기는 추가하지 않았다.

## 기기 설치·직접 조작

최종 정식·치트 앱을 각각 iPhone·iPad에 설치했다. Xcode Clean Build 후 만든 앱이며 XCTest 플러그인을 포함하지 않는다. 로컬 개발 서명 설정은 설치 후 프로젝트에서 제거했다.

실제 iPad 치트 앱의 Stage 2에서 자금 버튼을 직접 눌렀다. 첫 크레딧 수령으로 1,910→1,931, 다음 주기와 혼합 수령으로 1,931→1,962가 됐다. Missile 2기를 생산해 셀을 사용한 뒤 지원을 받았다. 셀 464/500에서 36개를 받고, 지원 잔액 12개가 남았다. 혼합 지원은 10Cr만 받고 셀 24개가 남았다. CLOSE 후 생산과 전투가 재개됐고, 다시 열어도 수령한 크레딧이 되살아나지 않았다.

iPhone 정식 앱은 설치 후 실행됐고, 실제 화면에서 Stage 23과 긴급지원 창·ADMIRAL B 메시지를 확인했다. 직접 수령 조작은 iPad에서 수행했다. 이후 Device Hub와 Xcode 창이 화면 도구에서 사라져 iPad 정식 앱의 추가 직접 터치와 iPhone 치트 앱의 독립 실행 확인은 마치지 못했다. iPad 정식 앱은 CLI 실행·종료가 성공했다. 두 기기의 치트 앱 자동 검사 결과는 위와 같다.

검사한 iPad 치트 저장을 원래 백업으로 복원한 뒤 다시 내려받아 바이트 일치를 확인했다. iPad 정식·iPhone 치트 저장도 검사 전 백업과 일치했다. iPhone 정식 앱은 화면에서 진행도가 늘어난 것을 확인해 이전 백업으로 덮어쓰지 않았다. 현재 저장을 추가 백업했고 사용 중인 앱을 그대로 두었다. iPad의 검사 앱은 종료했다.
