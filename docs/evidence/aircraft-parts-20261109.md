# 벨루가 파츠 분리와 AH-10 후속 제작

2026-11-09. 벨루가 파츠 분리, AH-10 무장 그림 제작, 웹 검증을 세 작업자가 병렬로 진행했다. 원작 코드·에셋과 기존 헬기 이동·회피 수치는 보존 대상이다.

## 벨루가

승인된 정면과 좌우 선회 7개 자세에서 몸체·좌우 날개·기존 두 엔진의 픽셀을 분리했다. 새 디자인이나 도장을 덧붙이지 않았다. 제작 입력과 분리 경계, 겹침 없는 재합성 검사는 [제작 명세](../../Art/Aircraft/parts-separation-20261109/beluga/manifest.json)에 있다. 공통 파츠 정의·소켓·층 순서로 기본 기체와 Lv.1–10 모두에 연결했다. 표시 파츠는 6개에서 9개가 됐다.

헬기 전용 선회 선택은 분리된 세 고정부품도 해당 자세의 그림을 선택한다. 기존 정면 그림을 다시 눌러 변형하지 않는다. 원작 공통 렌더러와 이동·회피 소스는 바꾸지 않았다. 그림 준비는 기존 Apple PNG 최적화를 사용한다.

[코어 검사 5개](aircraft-parts-20261109/core-tests.txt)는 조립·40레벨·무장·발사 효과·조종 동작을 확인했다. [실제 소비 조사](aircraft-parts-20261109/art-audit.json)는 벨루가의 날개·엔진이 사용되는지 확인한다. 기능 검사 통과는 질감·입체감 개선이나 사용자 미감 승인을 뜻하지 않는다.

세 파츠의 공통 크롭과 정수 소켓 보정으로 원본 위치를 유지했다. 왼쪽·오른쪽 날개는 각 140×55, 엔진은 140×45이며 각각 7칸이다. 기존 POT RGBA 계산에서 추가 세 텍스처의 크기는 합계 768KiB다. 최초 풀캔버스 분리안의 3MiB에서 줄였다. X·Y를 모두 크롭한 320KiB 후보에서는 벨루가 그림자 경계가 9~44픽셀 달라져 채택하지 않았다. X축 폭을 원본과 같게 유지한 최종 후보는 Chrome·WebKit 7자세씩 총 14화면이 기준 캡처와 픽셀 단위로 같다. 준비 이후 추가 텍스처 업로드와 페이지 오류는 0이다. 표시·그림자 제출은 기체당 6개 늘어나므로 대량 전투의 CPU/GPU 비용을 미측정 상태에서 영향 없다고 판정하지 않는다.

[CPU 표시 자료 생성 비교](aircraft-parts-20261109/cpu-summary.json)에서 100기·16도 선회의 라운드 평균 중앙값은 0.162ms에서 0.243ms로 늘었다(3회 교대, 회당 200프레임). 원작 공통 경로에 3개 파츠를 추가한 비용이다. 이 정적 벤치는 GPU·브라우저 FPS·전투 전체 성능을 측정하지 않았다.

[최종 웹 검사](aircraft-parts-20261109/web-summary.json)는 Chrome·WebKit에서 4종×10레벨을 레벨당 600 tick씩 실행했다. 발사·피해·회피·저장 쓰기 0·오디오 수명 유지가 통과했다. [보존 대조](aircraft-parts-20261109/web-preservation.json)에서 원작 이미지·다른 세 기체 PNG·이동·수치·무장 코드의 변경은 없다. 중간 Chromium 동시 실행은 시작 준비 timeout으로 실패했고 최종 두 브라우저를 순차 실행해 통과했다.

## AH-10과 남은 범위

AH-10 로켓·공습 발사대는 몸체 그림에 포함돼 있다. 무장 부분을 그대로 떼어 회전 파츠로 연결하면 기존 몸체에 빈 부분이 생기고, 선회 그림과 독립 무장의 투영이 달라진다. [분리 후보와 검수 기록](../../Art/Aircraft/ah10-parts-20261109/candidate-review.json)을 만들었다. 후보에는 무장 중복과 승인 형상 변경이 남아 채택하지 않았다. 나머지 6개 선회 자세도 필요하다. 현재 AH-10 게임 자원은 변경하지 않았다.

4종의 레벨별 새 외형, 도색·질감·입체감 개선, 기존 이동을 보존한 표적 밀착 방지, 최종 시각·성능 검증은 남아 있다. 이번 벨루가 분리는 미사용 파츠 연결의 수정이며 전체 헬기 과제 완료가 아니다.
