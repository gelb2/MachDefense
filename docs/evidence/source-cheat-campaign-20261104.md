# 치트 앱과 캠페인 검사 · 2026-11-04

`feat/source-reimplementation`에서 구현했다. 일반 앱과 같은 C++ 코어를 사용하며 별도 번들과 저장 컨테이너를 사용한다. 사용자의 실제 기기 포팅판과 저장은 변경하지 않았다.

## 치트 화면

원작 System Menu·버튼 이미지와 Trebuchet 글리프를 공통 렌더러로 그린다. TEST 화면 5쪽에서 프로필 생성, 80개 미션 선택, Cr·셀, 기지 강화 6종, 생산 장비·레벨·장착, 특수공격·수량·장착, 아군/적 생성·체력, 양쪽 기지 파괴를 조절한다. 화면을 열면 전투가 멈추며 기존 터치를 취소한다. 일반 앱에서는 검증 명령이 동작하지 않는다.

값 변경은 메모리에서 처리한다. SAVE TEST SLOT, 결과창, 기존 저장 종료 등 저장 시점에 파일을 쓴다. 발사·피격·전투 tick은 파일을 쓰지 않는다.

## 이번에 고친 문제

- 셀 20에서 100을 빼면 음수가 되어 예외가 발생했다. 0을 하한으로 적용했다.
- 전투 중 직접 검증 명령이 선택한 프로필 대신 슬롯 0을 바꿀 수 있었다. 실행 중인 Session 슬롯으로 맞췄다.
- 결과 저장 실패 후 Next Stage가 재시도 없이 이동했다. Next·Retry·Select Stage에서 미저장 결과를 먼저 저장한다. 연속 실패하면 결과창에 머문다.
- TEST 오류창이 패널 뒤에 가려지고 뒤의 버튼이 눌렸다. 오류창을 마지막에 그리며 입력을 먼저 받도록 했다.
- 진형 아이콘에 임의로 연결했던 후퇴 동작을 제거했다. 원본의 진형 아이콘 핸들러 5개는 명령을 실행하지 않는다. 별도 후퇴 명령 0은 원본 거리 120 조건대로 구현했지만 새 버튼을 만들지 않았다.

## 원본 대조와 남은 검사

원본 함수 주소·효과·잔해·진형 분석은 [소스 분석](source-analysis-20261104.md)에 연결했다. 원본 패키지에도 Efx_EMP.png가 없으며 다른 그림으로 대체하지 않았다. 원본이 가진 효과와 실제 표시되는 그림을 구분한다.

같은 저장·난수 조건의 포팅판/새 앱 전투 대조, 객체 갱신 순서와 복합 상태 순서, 일반 난이도 진행, 장시간 메모리·프레임·생명주기 검사가 남았다. 전체 검증 후 iPhone·iPad 화면을 확장한다. 현재는 320×480 논리 화면이다.

로컬 로그: `.local/final-core-tests.log`, `.local/save-failure-result.log`, `.local/source-build-release/Testing/Temporary/LastTest.log`. 저장 실패 수정 전 실패 로그와 회귀검사를 보존한다. 시뮬레이터 캡처는 `.local/source-cheat-*.png`다. 원본 패키지·실행 파일·개인 저장은 보고 사이트에 포함하지 않는다.

최신 일반·치트 Apple 증분 빌드도 성공했다. iPad 재설치 후 슬롯2 TEST·1,000Cr 유지와 미사일 생산을 확인했다. 마지막 탄환 부착 효과·레이저 번개는 Apple 빌드와 코어 검사까지 완료했고, 원본과의 화면 비교는 남았다. OpenGL ES/OpenAL deprecated 경고는 남아 있다. 시험 앱을 종료하고 홈 화면을 확인한 뒤 시뮬레이터를 모두 종료했다.
