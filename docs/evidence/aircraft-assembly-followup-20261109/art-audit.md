# 헬기 파츠·외형 소비 대조

2026-11-09. [검사 스크립트](../../../tools/audit_aircraft_assembly_consumption.py)가 실제 준비 MCB, PartsList·TileList, 조립 작성 JSON, PNG 헤더와 로더를 읽었다. [입력 해시와 전체 결과](art-audit.json). 이 검사는 파일 연결을 확인하며 새 미술 적용·시각 검수·성능 검증을 대신하지 않는다.

| 기체 | 조립 노드 / 표시 파츠 | 실제 연결된 그림 | 남은 외형·조립 문제 |
|---|---|---|---|
| 스카웃 | 4 / 4 | 몸체, 기관포, 미사일, 로터 | Lv.1–10의 표시 이미지 구성이 동일하다. 단계별 외형이 없다. |
| 샤이엔 | 6 / 6 | 몸체, 팬 2개, 전방 장식 파츠, 좌우 미사일 | `ADuctGun`은 type 0의 표시 파츠다. 현행 무장은 미사일 2개 파츠에 연결된다. Lv.1–10 외형은 동일하다. |
| 벨루가 | 6 / 6 | 몸체, 팬, 기관포 2개, 미사일 2개 | `ATransportWingL/R`·`ATransportEngine` 정의와 PNG가 있지만 실제 기본 조립에는 쓰이지 않는다. 기존 몸체에 포함된 날개·엔진을 별도 파츠로 분리하는 작업이 남았다. Lv.1–10 외형도 동일하다. |
| AH-10 | 8 / 6 | 몸체, 기관포, 미사일, 캐논, 로터 2개 | 로켓·공습 미사일 노드는 type 4지만 `tileCount=0`, `PartsDummy.png`로 그림이 없다. 실제 무장 그림·파츠·총구 대응을 끝내야 한다. Lv.1–10 외형도 동일하다. |

작성 시점의 준비 결과에는 기본 4개와 레벨별 40개를 합친 44개 기체 정의가 MCB에 있고 로더의 `appendMachineVariant` 호출은 제거됐다. 이는 병렬로 진행한 정의 데이터 수정 결과이며, **레벨별 새 외형을 완성했다는 뜻은 아니다.** 네 기체 모두 10레벨의 표시 이미지 목록을 비교하면 고유 구성은 1개다.

몸체 4개에는 정면과 좌우 6단계의 7칸 시트가 연결돼 있다. 현재 선회 각도 선택 코드와 시트 격자·파일 해시는 결과 JSON에서 추적한다. 스크립트는 좌우 그림이 자연스러운지 또는 원작과 질감이 같은지 판정하지 않는다. 몸체 안에 합쳐진 부위에 기존 별도 PNG를 그대로 추가하면 중복될 수 있으므로 단순히 미사용 파일을 연결해서 해결된 것으로 처리하지 않는다.

원작 `PartsInfo` 463개와 `MachInfo` 126개 정의는 대조 입력으로 읽었다. 같은 PNG 확장자·MCB 포맷·공통 조립 함수를 쓴다는 사실만으로 원작의 제작·조립·렌더링 전 절차 준수를 주장하지 않는다. 이번 감사는 승인 에셋과 원작 파일을 수정하지 않았다.

실행: `python3 tools/audit_aircraft_assembly_consumption.py`. 후속 자원 변경 뒤 다시 실행하면 JSON을 현재 소비 상태로 갱신한다.
