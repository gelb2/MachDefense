## 적용

회피 구현을 `6937e40`에 보존한 뒤 `feat/aircraft-visual-repair-20261108`에서 수정했다. `pack_aircraft_approved.py`가 보존된 승인 원본에서 몸체·무장·로터를 내보낸다. 새 생성 그림을 만들지 않았다. 소형과 건쉽의 기존 마모·위험 표식을 유지했고, Orca는 회색, 폭격형은 상아색·회색·적색 표식을 사용한다.

무장의 결합점과 총구를 확대된 부품에 맞췄다. 좌우 기울임은 같은 부품을 변형하며 부착점과 총구에 같은 변환을 적용한다. 기울임 메시에서 빠졌던 nearest 필터를 Apple·Android·Web 렌더러에 연결했다. 기존 메시의 기본 필터는 유지한다. 좌우가 같은 모양으로 줄어들던 기울임에 방향별 차이를 넣었다.

소형 로터 60×60, 건쉽 로터 66×66은 승인된 날개형 로터의 고해상도 원본에서 포장했다. 원반형으로 바꾸거나 회전 속도를 조정하지 않았다.

## 실제 검사 중 발견해 고친 것

1. 무장을 키운 뒤 총구가 포신 끝보다 안쪽에 남았다. 네 기체 무장의 끝 좌표 검사로 잡아 수정했다.
2. 생산창에 큰 기체를 같은 배율로 그려 가격표와 이름을 덮었다. 원작 조립 출력의 경계를 한 번 계산해 원래 아이콘 칸에 맞춘다. 같은 경로를 사용하는 강화·획득 미리보기도 적용된다. 전장의 크기는 유지한다.
3. 첫 비교 화면의 기준 탱크와 화면 방향 설정이 잘못됐다. 최대 적 탱크 E_Tank_32와 실제 게임의 세로 화면으로 다시 캡처했다.

## 최종 빌드

실제 iPad에 검사 플러그인을 제거한 MachDefenseCheat를 다시 설치했다. 앱 번들에 xctest가 없고 항공기 PNG가 현재 Resources와 바이트 단위로 같음을 확인했다. devicectl 실행 성공과 타이틀 화면을 확인했다. Device Hub의 추가 터치·회전 명령은 연결 무효 오류가 나므로 직접 터치 검사를 완료했다고 보고하지 않는다. Android CheatDebug도 빌드 성공했다. Android 기기 재설치와 iPhone 재설치는 이번 작업에서 하지 않았다.

회피·이동·피해 관련 파일 9개를 보존 커밋과 대조해 변경 없음도 확인했다. 최종 iPad 앱 프로세스는 CLI로 종료했다. 종료 뒤 홈 화면 직접 확인은 Device Hub 연결 오류 때문에 완료하지 못했다.
