# 추가 레벨 부품 연결과 크기 검사

2026-11-07. 사용자가 채택한 부품 44개를 실제 게임 데이터에 연결했다.

## 연결한 그림

| 대상 | 단계 | PNG 수 |
|---|---|---:|
| 공용 포탑 몸체 | 6–10 | 5 |
| 소총·미사일·벌컨·이온·레이저·플라즈마 무장 | 각각 6–10 | 30 |
| 기지 몸체·기관총·레이더 | 각각 8–10 | 9 |

원작 PNG를 덮어쓰지 않고 새 파일을 추가했다. PartsList·TileList와 Level10Parts·Level10Machines가 이 그림을 읽는다. 기존 부품의 회전 중심, 총구, 연결점, 배율과 그리는 순서를 유지했다. 공격력·사거리·저장 형식·플랫폼 실행 코드는 이번 그림 연결 때문에 수정하지 않았다. 같은 브랜치에서 앞서 수정한 미사일·이온·플라즈마의 추가 레벨 효과 수치는 이 앱에도 들어간다.

## 크기와 조립

`tools/pack_level10_art.py`가 승인 시안의 각 부품을 같은 비율로 축소한다. 원작의 투명 여백을 포함한 캔버스를 그대로 쓰며, 포신은 기존 총구 쪽 끝을 기준으로 배치한다. 가로와 세로를 따로 늘리지 않았다. 보이는 그림의 길이·폭은 원작과 최대 2픽셀 차이였다. 단계가 올라갈 때마다 자동 맞춤으로 축소하지 않는다.

벌컨은 두 포신 사이 간격이 원작보다 넓던 그림을 V4로 보정했다. 몸체의 링·장갑 배열은 무장 뒤에서도 단계별로 구별된다. 실제 GPU 캡처에서 소총·미사일·벌컨·이온·레이저·플라즈마를 원작 5레벨, 추가 6–10레벨 순서로 놓고 네 방향을 비교했다. 기지는 원작 7레벨과 8–10레벨을 비교했다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| 공용 CTest | 41개 통과, 176.47초 |
| iPhone 시뮬레이터 | 조립·강화 HUD 2개 통과 |
| 실제 iPad Air | 조립·강화 HUD·실시간 전투 3개 통과, 44.71초 |
| 실제 iPhone Air | 조립·강화 HUD 2개 통과, 26.60초 |
| 조립 검사 | 포탑 144자세, 포탑 6장·기지 1장 GPU 캡처 |
| 강화·HUD 검사 | 130행, 구매 117건, 거절 143건, 저장·코드 재로드 130건, 렌더 화면 133개 |

실기기 검사는 XCTest 호스트로 실행했다. iPad에서 14종 생산 목록과 10레벨 전투를 600프레임 실행했다. 첫 프레임을 뺀 간격 표본은 599개이며 두 구간 모두 p99 16.67ms, 25ms 초과 0회였다. 전투 구간의 CPU p99는 5.60ms, HUD 스크롤을 함께 한 구간은 7.80ms였다. 스크롤 구간 메모리는 146.06–146.33MB였다. 검사 중 저장 쓰기는 0회였다.

원본 캔버스·연결점·총구·회전 배율의 동일성도 C++와 실제 렌더 검사에서 대조했다. 원작 단계의 그림을 그대로 둔 상태로 추가 단계만 새 파일을 참조한다.

## 최종 앱 설치

iPhone·iPad에 일반·치트 앱 4개를 무선으로 설치하고 모두 실행했다. 테스트 플러그인은 최종 앱에 포함하지 않았다. 설치 전후 네 저장 파일은 바이트가 같았다. iPhone 일반 앱의 슬롯 화면과 치트 메뉴 터치를 확인했다. iPad는 XCTest 기능 검사를 통과했으며 최종 앱 두 개의 시작 화면도 확인했다. Device Hub의 iPad 직접 터치는 반응을 확인하지 못했다. 두 기기의 앱을 종료하고 홈 화면으로 복귀했다.
