# 헬기 자원 처리와 검증 누락 경위서

2026-11-09. 작성 주체: 구현을 수행한 Codex.

Codex는 원작의 파일·최적화·정의 데이터·파츠 조립·렌더링 절차를 따르라는 지시를 충분히 이행하지 않았다. 헬기 이미지를 일반 PNG 준비 경로에 넣고, 헬기 정의를 C++ 안에서 구성했다. 공통 로더와 조립 함수를 사용하고 크기·무장·발사 검사를 통과한 사실을 근거로 삼았지만, 원작 최적화와 시각·성능 동등성을 확인하는 검사를 빠뜨렸다. 이 구현 선택과 검증 누락의 책임은 Codex에 있다. 사용자가 의견을 밀어붙여 발생한 문제나 사용자의 지시 부족으로 기록하지 않는다.

## 작업과 누락

| 작업 | 확인된 구현 | 누락한 절차 |
|---|---|---|
| 원작 자원 준비 | `efc5d4a`부터 CgBI의 BGRA·사전 곱셈 알파를 일반 PNG로 변환 | 원본 CoreGraphics·색 프로필·실제 출력과 변환본의 전체 동등성 |
| 헬기 에셋 적용 | 생성 그림을 크롭·축소한 일반 RGBA PNG를 사용 | 원작 최적화 과정을 기준으로 한 준비·파일·로딩 비용 대조 |
| 헬기 파츠·조립 정의 | `AircraftModels.hpp` 내부에서 Chunk를 만들고 공통 파서에 추가 | 원작 정의 데이터 작성·읽기 절차에 맞춘 추가 파일 구성 |
| 헬기 색조와 도장 | 색상 함수를 적용한 뒤 `38903e4`에서 PNG에 고정 | 색조 승인과 별도로 필요한 질감·면별 명암·경계 대조 |
| 기울임 | 같은 정면 이미지의 꼭짓점을 변형 | 각도별 측면·가림·음영을 그린 선회 스프라이트 |
| 검사·완료 보고 | 기능·크기·해시·알파·웹 전투 검사 결과를 제시 | 해당 결과가 증명하지 않는 원작 제작·최적화·시각·CPU·GPU 동등성의 명확한 분리 |

사용자는 실기기에서 헬기의 평면적인 질감과 종이 같은 선회를 발견했다. 이후 파츠 조립과 파일 형식, 원작의 최적화, CPU·프레임 영향의 조사를 지시했다. 원작 절차를 먼저 확인하고 적용 여부를 검증할 책임을 사용자의 발견과 후속 질문에 의존하게 만든 것이 이번 작업의 문제다.

## 이런 처리가 반복된 작업상의 원인

Codex는 준비된 일반 PNG를 편집 도구와 기존 로더에 연결하기 쉬운 경로로 사용했다. 공통 코드 재사용을 파일·데이터 생성부터 실제 화면까지의 전체 절차 준수와 혼동했다. 크기·무장 기능의 성공을 질감과 최적화까지 확인한 것처럼 넓게 다뤘고, 승인된 색조를 처리하면서 입체감·샘플링·알파·프로필을 별도의 비교 대상으로 끝까지 확인하지 않았다. 실제 조립에 연결되지 않은 이미지도 파일 반영 개수에 포함해 설명하면서 파일 존재와 화면 소비의 차이를 충분히 드러내지 않았다.

현재 조사한 로더는 CgBI 처리 옵션도 갖고 있다. 따라서 ‘CgBI를 읽을 수 없어서 일반 PNG가 필수였다’는 기술적 이유는 성립한다고 확인되지 않았다. 기존 일반 PNG 작업 흐름에 맞춘 선택을 원작 절차보다 앞세운 판단과 검증 누락을 기록한다. 당시 기록에 없는 내부 동기나 외부 시스템의 강요를 이유로 만들어 책임을 돌리지 않는다.

## 확인된 영향과 아직 측정하지 않은 영향

원본 PNG 948개는 모두 CgBI다. 복원 자원 준비 코드는 알파 역산과 색 메타데이터 제외를 수행한다. 최근 설치에 사용한 Release 앱의 대표 원작·헬기 이미지 6개 모두 일반 PNG로 들어 있다. 이 사실은 원작 최적화 경로의 재현 여부를 기존 유닛과 헬기 모두에서 확인해야 한다는 뜻이다.

대표 원작 이미지 5개를 현재 stb로 직접 해독한 값과 준비 PNG의 해독값은 같았다. 재사전곱셈에는 최대 1의 RGB 차이가 있었고, 보간·알파 순서의 CPU 산술 모델에서는 경계 색 차이가 확인됐다. 이 일부 해독 검사를 근거로 사용자가 확인한 질감 차이를 부정하지 않는다. 원작 CoreGraphics 출력·실제 GPU 합성과 전체 화면은 별도 확인이 필요하다.

일반 PNG 도입과 에셋 준비 차이가 파일 읽기·해독·변환, 최초 업로드, 메모리와 프레임에 미칠 수 있는 영향을 사전에 분리 검증하지 않았다. 현재 실기기의 포맷별 CPU·GPU·프레임 저하량은 측정하지 않았다. 기존 캐시·웹 성능 검사로 이 누락을 완료 처리하지 않는다. [기술 조사와 재현 자료](../research/aircraft-cgbi-20261109.md)에 확인 범위와 남은 검사를 적었다.

## 정정과 후속 조치

원작자의 파일 준비·최적화·정의·파츠·로직 생성·조립·렌더링 절차를 정본에 명시했다. Codex의 편의나 의견으로 이를 대체하지 않는다. 전체 대조는 `MD-AIRCRAFT-ASSET-PARITY-01`, CgBI·시각·CPU·프레임 검사는 `MD-AIRCRAFT-CGBI-PERF-01`, C++ 헬기 로직 전수진단은 `MD-AIRCRAFT-LOGIC-AUDIT-01`로 관리한다. 좌우 선회 스프라이트 재제작과 입체감 조사는 기존 TODO에 연결했다.

이번에 완료한 범위는 파일·코드 조사, 대표 해독 검사, 메모리 계산, TODO·경위서·기술 보고서 작성이다. 원작 절차에 맞춘 헬기 정의·최적화 경로 복원, 전체 시각 비교와 실기기 성능 계측은 아직 완료하지 않았다. 이번 기록 작업에서 원작 코드·에셋과 현재 앱을 변경하지 않았다.
