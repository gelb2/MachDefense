# Web·PWA 구현과 검사 — 2026-11-06

`feat/web-pwa`에서 기존 C++ 게임을 WebAssembly로 빌드하고 WebGL2·브라우저 입력·음향·IndexedDB·PWA 캐시를 연결했다. 기준 develop은 `ae08521`이다. develop/main 병합과 게임 공개 배포는 하지 않았다.

## 기존 플랫폼과 수정 범위

기준 2,972개 파일의 SHA-256을 다시 대조했다. Apple·Android 실행기, 효과음 모듈, 게임 계산, 기존 자원은 같다. 기존 파일 중 바뀐 것은 다음 4개다.

| 파일 | 추가한 내용 |
|---|---|
| Sources/Core/Contracts/Game.hpp | 복원 지원 여부·텍스트 입력·복원 저장 서비스. 기존 호스트의 지원 여부 기본값은 false |
| Sources/Core/Presentation/Menu.hpp | 복원 창과 입력 상태 |
| Sources/Core/Presentation/Menu.cpp | 슬롯 화면의 GET CODE / ENTER CODE와 원작 버튼을 쓰는 확인 창 |
| Sources/Core/Session/GameSession.cpp | 플랫폼 복원 서비스 전달 |

추가 코덱은 `Modules/SaveTransfer`, 웹 실행기는 `Web`, 시작 페이지·캐시·저장 연결은 `Distribution/Web`에 있다. 공용 복원 UI를 켜지 않은 기존 Apple·Android의 게임 동작을 기준 커밋과 비교했다. 160조건·144,000틱의 Frame·전투·음향·저장 추적 결과가 바이트 단위로 같았다. iOS 시뮬레이터 정식 빌드와 Android 일반·치트 Debug 빌드도 성공했다. 이번 작업에서는 설치된 네이티브 앱을 교체하지 않았다.

## 복원 코드와 아이폰 저장

MD1 형식은 버전 1·CRC32·길이 제한이 있는 PackBits·Base64url을 사용한다. 원본 42,496바이트와 미확인 바이트를 모두 보존한다. 서버·계정·salt·암호화는 없다. 슬롯 선택 화면의 GET CODE와 ENTER CODE는 원작 SysMenu_Btn·게임 글꼴·Button으로 그린다. 코드 입력과 복사에만 브라우저 텍스트 입력창을 사용한다.

현재 UI는 원본 5슬롯 전체를 복원한다. 단일 슬롯 선택과 확장 설정, Apple·Android의 복원 UI 연결은 후속 과제다. Apple·Android의 현재 메뉴에는 새 버튼이 나타나지 않는다.

사용자 아이폰에서 저장을 읽기 전용으로 복사했다. 첫 슬롯은 Stage 36, 11,959 Cr, 생산 항목 12개, 특수공격 5개였다. 이 파일을 같은 공용 코덱으로 변환한 1,432자 코드를 브라우저에 입력했다. 복원 직후 저장 42,496바이트가 원본과 같았고 Stage 36 전투·저장 재실행도 확인했다. 검사 후 아이폰 저장을 다시 읽어 처음 복사본과 같은 것을 확인했다. 원본 저장과 복원 코드는 Git·보고 사이트에 넣지 않았다.

## 실행·저장·음향

- 같은 Core의 Frame을 WebGL2가 그린다. 이미지 디코딩과 GPU 업로드는 캐시에 보관한다. 게임 버튼은 DOM으로 옮기지 않았다.
- 효과음은 기존 `Sources/Audio/OpenALEffects`를 Emscripten OpenAL로 연결한다. 음악만 Web Audio 출력에 연결한다. 음원 선택·전투 계산은 공용 코드가 처리한다.
- 일반·치트 IndexedDB를 분리한다. 기존 저장 지점에서만 기록한다. 트랜잭션 완료 후에만 저장 성공을 반환하며 두 창의 오래된 값 덮어쓰기를 거부한다.
- 복원 전 저장을 별도 restoreBackup에 남긴다. 일반 저장은 그 백업을 덮지 않는다.
- PWA 자원 캐시와 진행 저장 DB를 분리한다. 자원별 SHA-256을 검사하고 새 버전은 기존 창이 닫힌 뒤 활성화한다. 자원 캐시가 없어지면 다시 받고 진행은 유지한다.

도구: Emscripten 6.0.13, Playwright 1.65.0, WebKit 27.2, macOS의 설치된 Google Chrome. 구형 Playwright WebKit 26의 오프라인 탐색은 내부 오류가 났으며 최신 WebKit에서는 같은 검사가 통과했다. 해당 실패 로그도 보존했다.

브라우저 흐름 검사의 첫 실행은 도움말에 존재하지 않는 OK 버튼을 찾다가 실패했다. 원작 도움말 닫기 영역과 SummaryBtn_Retry / SummaryBtn_NextStage를 사용하도록 검사 코드를 고쳐 통과했다. 게임 코드는 이 검사 실패 때문에 변경하지 않았다.

화면 해시는 미세한 실수 차이에도 달라진다. 첫 차이는 Stage 1의 872틱에서 E_Tank_Wpn_01.png의 세로 좌표였다. 전체 필드를 추가 대조한 [수치 결과](web-frame-comparison-20261106.json)와 `Web/tests/frame-parity.cpp`, `compare-frame.py`를 남겼다. 최대 차이는 0.001보다 작았고 이미지·메시·레이어 등 비실수 값은 모두 같았다. 게임 소스와 수치 계산은 변경하지 않았다.

## 남은 확인

실제 iPhone·iPad·Galaxy의 PWA 설치·터치·잠금 복귀·음향·장시간 성능은 아직 검사하지 않았다. 현재 게임 서버는 Mac localhost에만 열려 있다. 모바일 설치에 쓸 비공개 HTTPS 주소를 마련하는 작업이 남았다. Mac WebKit 검사를 iOS 실기기 검사로 기록하지 않는다.

120Hz 화면에서의 속도, 메모리·장시간 발열 검사는 남았다. Tauri Mac은 아직 구현하지 않았다. 기존 생산 HUD·길찾기·레벨10 과제는 그대로 유지한다.
