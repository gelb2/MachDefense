# MachDefense 복원 절차 점검 — 2026-11-04

MachDefense에는 원본 분석·게임 아트 연결·자동 검사·실기기 검사용 스킬이 있다. 최근 오류에서 확인한 문제는 원본의 호출과 상태를 새 코드에 빠뜨리거나 잘못 연결한 것, 그리고 검사 항목이 그 차이를 확인하지 않은 것이다. 필요한 스킬 파일이 없어서 발생했다는 근거는 찾지 못했다.

HeavyMach 1보다 오류가 많다는 수량 비교는 아직 할 수 없다. 두 프로젝트의 같은 개발 단계·같은 검사 범위를 기준으로 한 결함 집계가 없다. 다만 MachDefense에서는 사용자가 정식 앱을 플레이하면서 안내·딤·효과음·로딩 화면·복귀 입력·완료 표시 오류를 연달아 발견했다. 앞서 수행한 검사로 이 항목들을 잡지 못했다.

## HeavyMach 1에서 가져온 절차와 빠진 연결

HeavyMach 1의 [복원 계약 사본](../reference/heavymach1/policies/restoration-contract.md)은 이미지·타일·메뉴 순서·효과음·애니메이션 보존과 실제 화면·음향 비교를 요구한다. [음향 정책 사본](../reference/heavymach1/policies/runtime-policy.md)은 원본 OpenAL 버퍼·소스의 재사용과 호출 순서를 명시한다. [아트 연결 스킬 사본](../reference/heavymach1/skills/integrate-game-art/SKILL.md)은 파일 이름만 보고 채택 자원을 고르지 않고 실제 소비 경로를 확인하도록 한다.

MachDefense에는 이 문서와 스킬을 복사했고, 실제 게임 객체·시험 저장·GPU·오디오를 연결하는 XCTest도 만들었다. [초기 자동검사](apple-automated-sweep-20261104.md)는 구매 값과 80미션 상태 전환, 생산·특수공격의 결과를 빠르게 확인했다. 그러나 원본의 전체 화면·음향 반응 목록을 먼저 만들고 각 항목을 검사에 연결하는 작업은 끝내지 못한 상태였다.

특히 다음 두 종류의 검사를 구분해야 한다.

- 값과 상태 검사: 비용 차감, 생성 수, 승패, 다음 미션, 저장 재읽기. 기존 검사의 유효한 결과다.
- 원본 화면·음향 대조: 버튼 상태별 그림, 안내·딤·일러스트, 동작별 음원과 시작·종료 시점, 실제 출력. 이번 사용자 플레이에서 누락이 드러난 범위다.

80개 미션을 통과해도 같은 공용 결과 화면의 일러스트와 효과음이 한 번 빠지면 모든 미션에서 누락된다. 반복 수를 늘리는 것만으로 이 차이를 찾을 수 없다. 기대값에 그 표시와 음향 조건이 들어 있어야 한다.

## 보강할 절차

새로운 범용 스킬을 추가하는 것보다 현재 `restore-machdefense`와 검사 절차에 다음 연결을 넣는 것이 우선이다. 아래 절차를 `restore-machdefense` 스킬에 반영했다.

1. **원본 행동별 목록을 만든다.** 화면·컨트롤 ID·입력 단계·상태 변경·이미지/타일·효과음·음악·생성/해제 시점을 한 행에 적는다. 일반 버튼, 생산·강화, 전투, 결과·다음 미션까지 같은 목록을 쓴다.
2. **원본 요청과 실제 자원을 함께 확인한다.** 호출한 파일이 없으면 없는 것으로 기록하고 포팅판 화면을 본다. 비슷한 이름의 자원으로 임의 대체하지 않는다. 코드에 요청이 있다는 사실과 실제 화면에 출력된다는 사실을 구분한다.
3. **검사 기대값을 원본에서 얻는다.** 새 구현이 내보내는 개수와 파일 목록만 검사하지 않는다. 포팅판 관측·원본 함수의 조건과 기대값을 연결한다. UI는 누름 전·누르는 중·해제·선택·취소·비활성, 음향은 성공·거절·중복 호출 조건을 포함한다.
4. **출력까지 확인한다.** 이미지 이름·음향 호출 횟수 뒤에 GPU 캡처와 실제 녹음 비교를 연결한다. 오디오 `playCount` 증가나 `musicPlaying` 값은 스피커에서 올바른 음원이 들렸다는 검사를 대신하지 않는다.
5. **플랫폼 수명 변경을 따로 검토한다.** 오디오 컨텍스트·GPU·앱 중단·입력의 소유와 상태 전이를 표로 적는다. 초기화→사용→중단→복귀→종료를 검사하고, 호출마다 만든 자원·컨텍스트 전환·파일 접근이 있는지 확인한다.
6. **수정한 행동 전체를 다시 검사한다.** 예를 들어 로딩 그림을 복구하면 소리·입력 차단·미션 교체·저장·중단 복귀를 함께 확인한다. 기존 빠른 검사도 유지하되 실제 전환 종료를 기다리도록 한다.
7. **화면 확장 전에 남은 원본 차이를 정리한다.** 사용자 관측, 원본과 같은 동작, 재구현 오류, 미확인을 나눠 기록한다. 같은 항목을 TODO·원본 대조표·테스트·보고서에 연결한다.

새 이미지 제작 스킬이나 새 UI 프레임워크가 이 오류들을 해결하는 데 필요한 것은 아니다. 원작 에셋·게임 렌더·음향 자원을 소비하는 기존 코드에서 빠진 연결을 복구하고 검사를 추가한다.
