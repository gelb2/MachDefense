# 포탑 단계별 몸체·무장 변경

원본 세 판본의 `MachInfo.mcb`와 포탑 PNG 35개를 직접 읽었다. 세 판본의 해당 파일은 서로 같으며, 저장소에서 사용하는 원본 자원과도 바이트가 같다. 실행 화면을 새로 캡처한 검사는 아니다. [파일 해시·조립 트리·픽셀 대조](turret-original-stage-change-20261107.json).

## 원작 교체 규칙

Rifle·Missile·Vulcan·Ion·Laser·Plasma 모두 Lv.1~5에서 해당 단계의 몸체와 무장을 함께 참조한다.

| 레벨 | 공용 몸체 | 각 계열 무장 |
| --- | --- | --- |
| 1 | Turret_b_01 | Turret_{계열}_01 |
| 2 | Turret_b_02 | Turret_{계열}_02 |
| 3 | Turret_b_03 | Turret_{계열}_03 |
| 4 | Turret_b_04 | Turret_{계열}_04 |
| 5 | Turret_b_05 | Turret_{계열}_05 |

확보한 원본의 이 포탑 6종에서는 몸체와 무장을 번갈아 교체하는 규칙이 없다. 원작 몸체 Lv.3→4는 외곽 범위가 같고, 보이는 영역의 2,025픽셀 중 157픽셀만 달라진다. 장갑의 작은 변화는 무장에 가려질 수 있다. 파일 참조가 바뀌어도 조립 외형의 차이가 항상 크지는 않다. 다른 단계의 픽셀 차이는 위치 이동도 포함하므로 외형 변화의 크기로 해석하지 않는다.

## 이전 시안의 문제

몸체를 같은 크기 안에서 패널·통풍구로 구분하려 했으나, 조립하면 무장에 가려져 차이가 작았다. 원작의 교체 규칙을 근거로 변화량을 정한 결과가 아니었다.

미리보기의 `fit()`은 그림을 추정 회전축 주위에서 원작 경계 안에 넣는 최솟값 배율을 사용했다. 생성 그림의 비율·회전축 차이에 따라 단계마다 축소됐다. 이온 무장 길이는 원작 69에 비해 Lv.6 61.9, Lv.10 48.2였다. 기존 검사는 원작 경계를 넘는지만 검사해 이 축소를 놓쳤다. 같은 크기라고 설명한 것은 잘못됐다. [이전 측정](../../Art/Level10/20261107/body-preview-calibration-v1.json).

## 수정 시안

원작 Lv.5만 참조해 공용 몸체 5단계와 무장 6종의 5단계를 다시 그렸다. 몸체의 변화는 측면 장갑·뒤쪽 기계부·넓은 통풍구·보강대에 배치했다. 무장은 원작의 포신 길이·방향과 두 무장의 배치를 기준으로 다시 그렸다.

조립 미리보기는 각 계열 원작 Lv.5의 길이를 사용한다. 높이와 너비에 서로 다른 배율을 적용하지 않는다. 원본 그림 비율을 유지한 상태의 길이와 폭을 각 칸에 표시한다. 기존 최솟값 자동 맞춤은 제거했다.

길이는 맞췄지만 생성 그림의 폭까지 정확히 일치하지는 않는다. 예를 들어 Vulcan은 원작 43에 비해 시안 44.5~46.7이다. 게임 자원으로 연결하기 전에 폭과 세부 도트·피벗을 맞춰야 한다. 이번 결과는 조립 시안이며 운영 게임에 연결하지 않았다. [수정 시안과 프롬프트](../../Art/Level10/20261107/README.md), [수정 측정](../../Art/Level10/20261107/body-preview-calibration.json).

Chrome에서 신규 35개 부품의 길이, 비율 보존, 텍스처 잘림, 조립 36칸과 무장 전환·회전·초기화를 확인했다. 데스크톱과 393px 모바일에서 표시를 검사했다. 이 검사는 남은 폭 차이를 합격 처리하지 않는다.
