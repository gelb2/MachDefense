# 샤이엔 장갑과 무장 하우징

샤이엔 Lv.1–10에 독립 장갑 10개와 미사일 하우징 10개를 연결했다. 각 장갑은 중립·좌우 선회 7자세를 갖는다. 기존 몸체·팬·꼬리·전방 장식·총구와 기체 크기는 보존했다. 사거리·레벨 수치·무장 구성·이동·회피는 이 변경에서 수정하지 않았다.

장갑은 원작 파츠 조립 경로의 고정 부품으로 붙는다. RGBA 제작 입력을 CgBI PNG로 준비하고, 기존 MCB 정의를 통해 읽는다. 실행 중 부품을 복제하지 않는다. 왼쪽 4발과 오른쪽 3발의 무장 이름·총구를 유지하며, 레벨별 하우징 그림만 지정했다. 전방 `ADuctGun`은 기존 장식이다.

장갑 셀은 28×14, 몸체 기준 시작점은 (35,37)이다. body socket 0과 자체 socket (6,0)을 연결해 배치했다. 70개 자세 모두 승인 몸체의 투명 외곽 안에 있다. 하우징의 알파와 발사관 쪽 10열은 CgBI 준비 후에도 기존 자원과 같다. [제작 자료와 준비 도구](../../Art/Aircraft/upgrades-20261109/cheyenne/README.md).

확인 결과:

- 정의·파츠 소비·전체 헬기·조작·캠페인·샤이엔 7발 발사 검사 6개 통과. [기록](cheyenne-upgrades-20261109/core-tests.txt).
- Chrome·WebKit 각각 10레벨×7자세를 표시했다. 두 브라우저 모두 새 이미지 20개를 실제로 읽었고, 한 번 표시한 뒤 자세·레벨을 반복할 때 추가 텍스처 업로드는 0이었다.
- 총 140개 화면에서 샤이엔 영역 밖 픽셀이 스카웃 수정본과 완전히 같다. 원작 적 탱크·배경·나머지 세 헬기를 포함한다. [픽셀 비교](cheyenne-upgrades-20261109/web-preservation.json).
- 두 브라우저에서 4종×10레벨 전투·피해·사운드·회피를 확인했다. 전투 중 저장 쓰기 0이며 AudioContext 생성·종료 횟수는 검사 시작 이후 늘지 않았다. [Chrome](cheyenne-upgrades-20261109/chromium-combat.json), [WebKit](cheyenne-upgrades-20261109/webkit-combat.json).
- 원작과 다른 기체의 정의·이전 이미지 바이트를 보존했고, 웹 패키지에 들어간 26개 관련 자원이 현재 자원과 같다. [대조](cheyenne-upgrades-20261109/preservation.json).

[Lv.1 정면](cheyenne-upgrades-20261109/level-1-pose-0.png), [Lv.10 정면](cheyenne-upgrades-20261109/level-10-pose-0.png), [Lv.10 우선회](cheyenne-upgrades-20261109/level-10-pose-6.png). 실제 화면 9장과 확대 그림에서 장갑이 팬·조종석·발사관을 가리지 않는 것을 확인했다. [시각 검토](cheyenne-upgrades-20261109/visual-review.txt). 레벨 차이는 작은 등판과 하우징에 국한된다. 전체 기체 실루엣을 바꾸지는 않는다.

새 이미지 전체의 POT RGBA 계산량은 180KiB다. 장갑은 기체당 표시 부품 1개와 그림자 포함 제출 2회를 추가한다. 최종 4종 통합본의 GPU 시간 비교는 별도로 진행한다. 이 커밋은 샤이엔 외형 연결이며 AH-10·벨루가 강화 외형, 스카웃 기본 표면, 표적 접근 수정의 완료를 뜻하지 않는다. iPhone 설치와 main 배포는 이 변경에서 수행하지 않았다.
