# Base Upgrade 단계별 효과와 셀 생산 조사 — 2026-11-05

원본 WeMade 1.0.3과 재개발판의 `BaseUpgrade`, `WeaponInfo` 표는 바이트 단위로 같다. 원본 ARMv7의 셀 증가·시간 갱신 명령과 현재 C++ 계산도 대조했다. 검사한 10단계에서 자료형 차이나 시간 경과에 따른 셀 생산량 감소는 발견하지 못했다.

## 현재 아이폰 저장에서 보이는 차이

검사 전 백업을 읽으면 Build Time Lv.5, Cr Research Lv.5, Cell Research Lv.5, Cell Storage Lv.3이다. Cell Research Lv.5의 증가량은 1.4배, Cell Storage Lv.3의 용량은 1,000셀이다.

60fps일 때 셀은 초당 약 16.8개 늘어난다. 초기 12개/초보다 40% 많지만, 용량은 초기 500셀의 두 배다. 자연 생산만으로 빈 저장고를 채우면 초기 약 41.7초에서 현재 약 59.5초로 길어진다. 현재 같은 용량 1,000셀에서 Cell Research Lv.4→5의 차이는 초당 15.6→16.8셀, 약 7.69%다. 150셀짜리 유닛 한 대를 마련하는 시간은 약 9.62→8.93초다.

이는 표와 계산으로 확인한 차이다. 사용자가 느낀 모든 지연을 용량 증가로 확정한 것은 아니다. 실제 플레이 중 프레임 간격이 길어지면 이 게임의 틱 기반 자연 생산도 늦어진다. 이번 iPad 기관총 구간에서는 p99 16.67ms를 기록했다.

## Build Time·Cr Research·Cell Storage

Build Time은 유닛의 기본 생산 시간에 곱한다. 대기열에 넣는 시점에 시간이 정해지므로, 이미 생산 중인 유닛에는 이후 구매한 단계를 다시 적용하지 않는다. Lv.10은 기본 시간의 64%이며, 시간 단축은 36%다.

Cr Research는 적이 떨어뜨리는 크레딧의 수량에 곱한 뒤 정수로 절삭한다. 크레딧 드롭 확률과 광물의 셀 수량은 그대로다. Cell Storage는 보관 용량이다. 전투 중 셀을 지불하는 임시 용량 확장은 이 값의 2~6배이며 생산 속도를 올리지 않는다.

## 자료형과 시간 계산 대조

| 항목 | 원본 ARMv7 | 재개발 C++ |
|---|---|---|
| 게임 시간 | 64비트 부동소수점, 매 틱 `double(0.0166f)` 증가 | `double time_`, 같은 증가값 |
| 다음 셀 증가 시각 | 32비트 부동소수점 | `float nextCellTime_` |
| 셀 잔량·증가량 | 32비트 부동소수점 | `float cells_`, `float rate_` |
| 증가 조건 | 게임 시간이 다음 시각 이상이고 셀이 용량 미만 | 같은 조건 |
| 다음 증가 시각 | `float(gameTime + double(0.08f))` | 같은 계산 |
| 강화 반영 | 구매 후 `updateBaseUpgrade`가 현재 단계 Param 반영 | 구매 후 `refreshBaseUpgrades`가 현재 단계 Param 반영 |

0.08초가 매 틱의 0.0166초와 정확히 나누어지지 않아 셀 증가는 5틱마다 발생한다. 따라서 60틱/초에서 초당 12회다. 30틱/초로 떨어지면 실제 초당 생산도 절반이다. 이번 조사에서는 게임 시간을 벽시계 누적 방식으로 바꾸거나 원작의 성장 수치를 조정하지 않았다.

## 새로 실행한 검사

- 실제 게임 World를 사용한 강화 효과 검사: 폰·패드 좌표 108조건, 구매 456회, 크레딧 수집 40회, 광물 수집 40회, 용량 상한 20조건, 외형 전환 30조건 통과. 사용자 저장 쓰기 0회.
- 현재 `MachDefenseCore`의 BattleClock을 10단계 × 61분 × 3,600틱 실행했다. 원본 어셈블리의 부동소수점 연산·반올림 순서를 옮긴 비교 계산과 매 틱 시간·셀 잔량·다음 시각이 일치했다.
- 시작·10분·30분·60분 시점에서 각 3,600틱의 생산 횟수는 모두 720회였다. 상한 영향을 피하려고 분마다 시험 셀 잔량만 0으로 돌렸다. 게임 시간은 계속 누적했다.
- Lv.5는 각 측정 구간 1,008.00708셀, Lv.10은 1,583.99158셀이었다. float 덧셈 오차는 이 조건에서 1분당 0.009셀 미만이다. 단계별 효과를 정수로 잘라 버리거나 시간이 지날수록 생산이 둔화되는 현상은 재현하지 못했다.

61분은 틱을 빠르게 실행한 가상 진행 시간이다. 원본 앱과 재개발 앱을 실제 기기에서 각각 한 시간씩 실행한 결과는 아니다. 실제 원본 앱의 동일 구간 생산량 영상 대조는 후속 검사로 남긴다.
