# Apple 자동검사 — 2026-11-04

HeavyMach 1의 iOS XCTest처럼 실제 게임 객체에 입력을 보내고 GPU 렌더러·오디오·시험 저장 파일을 연결했다. iPhone Air iOS 26.5 시뮬레이터에서 세 검사가 모두 통과했다. 빌드와 실행을 합쳐 33.083초 걸렸다.

## 결과

| 검사 | 실행한 범위 | 결과 |
|---|---|---|
| 강화 구매 | 기지 6종, 초기 유닛 4종, 초기 특수기술 3종을 게임 버튼으로 구매 | 포팅판 관측값과 잔액 985,430Cr·점수 274 일치. 구매 중 파일 쓰기 0회. Save & Exit와 재읽기 통과 |
| 80개 미션 | 실패→재도전→승리→보상→다음 미션, 미션마다 저장을 읽어 새 GameSession 생성 | 80/80 통과. 검사 반복문 23.683초. 효과음 호출 3,279회 |
| 생산·특수공격 | 생산 정의 110개와 특수공격 27단계를 phone/pad 좌표 조건에서 각각 실행 | 생산 220건, 운반봇 배치 60건, 특수공격 54건 통과. 3.730초 |

생산·공격 검사에서는 자금 부족, 일시정지, 생산 시간, 기체 조립, 운반봇의 포탑 배치, 특수공격 수량 차감·자격·탄환·폭발을 검사했다. 생성 프레임 14,154개의 이미지 크기와 좌표를 확인했고, 그중 885개를 실제 GPU에 제출했다. 효과음 호출은 135회였다. 생산·공격 중 저장 파일 쓰기는 0회였다.

캠페인 검사는 기지에 피해를 직접 주어 실패·승리를 발생시킨다. 자연 전투와 실시간 프레임 측정은 별도로 진행한다. 이번 실행은 소스판의 자동검사다. 원본 포팅판에서 직접 확보한 구매 결과를 기대값으로 사용했으며, 포팅판을 동시에 자동 조작한 것은 아니다. [포팅판 관측과 대조](port-source-parity-20261104.md).

## 실행

```sh
python3 tools/run_apple_sweep.py --simulator 97CA5646-36BB-47A9-919A-D78DD632A439
```

다른 Mac에서는 `xcrun simctl list devices available`에 나온 시뮬레이터 UDID를 지정한다. 결과는 `.local/apple-sweep/<실행시각>/`의 `summary.json`, `xcodebuild.log`, `result.xcresult`에 남는다. 실패하거나 지정한 세 검사 중 하나라도 누락되면 명령이 실패한다. 각 검사는 별도 임시 저장 파일을 사용하고 끝나면 삭제한다.

이번 증거는 `.local/apple-sweep/20261104-211017-073511/`에 있다. XCTest 종료 후 Device Hub에서 시뮬레이터 홈 화면을 확인했다. 사용자 실기기 저장은 사용하지 않았다.

## 구현과 남은 범위

- `Apple/Tests/MenuRenderTests.mm`: 실제 GameSession 입력, MDRenderer, MDAudio, 디스크 저장·재읽기.
- `Tests/ContentSweep.hpp`: 기존 코어 검사의 생산·특수공격 검사를 공유한다. 기존 CoreContent 검사도 3.32초에 통과했다.
- `tools/run_apple_sweep.py`: 세 검사 실행과 결과 수집.
- 게임 제품 소스와 에셋은 이번 변경에 포함하지 않았다.

전체 강화의 각 단계·최대 단계 구매, 모든 일반 무장의 발사·명중, 난수와 입력 시점을 맞춘 포팅판 교전 대조, 실기기 성능·음향 지연·메모리 검사는 남았다. 다음 검사는 기존 자동 실행에 항목을 추가하고 실패한 항목의 화면을 확인한다.

참고한 HeavyMach 1 구현은 `Tests/iOS/HMSaveParityTests.mm`과 `HMMenuParityTests.mm`이다. 실제 게임 객체·시험 저장·관측한 원본 값의 비교 방식을 가져왔다.
