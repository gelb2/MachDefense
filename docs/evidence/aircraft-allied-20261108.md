## 좌우 전환의 감속·정지·재가속

사용자 후속 지시: 실제 헬기처럼 좌→우, 우→좌 이동 전환 때 서서히 감속하고 정지한 뒤 반대로 이동한다. 기존 시험본의 선회만으로는 이 조건을 충족하지 못했다.

네 기체에만 속도 벡터와 가속도 제한을 적용했다. 최고속도 도달까지 약 0.5초, 최고속도에서 정지까지 약 0.4초를 시험값으로 사용한다. 반대쪽 명령을 받으면 먼저 현재 속도를 0으로 줄인다. 속도 0인 한 시뮬레이션 틱을 거친 뒤 반대로 가속한다. 원작 지상·공중 유닛은 기존 이동 함수를 계속 사용한다. 기체 종류별 실제 항공역학 수치를 재현한 값은 아니다.

좌→우·우→좌 양쪽의 속도 증가·감소 상한, 정확한 정지 프레임, 반대 부호로의 가속을 자동 검사한다. 웹 전투 영상과 네 기체의 시간별 X/Y 위치·속도·감속 상태 1,320프레임을 기록했다. 소형·중형·덕트·수송형에서 각각 9·9·8·11회의 좌우 전환을 확인했고 모든 전환이 속도 0을 거쳤다. [속도 검사 결과](aircraft-allied-20261108/inertia-check.json). 기체 기울임 그림은 별도 후속 작업이다.

## 미션 55의 헬기 밀집과 피격 — 2026-11-08

사용자는 소형 헬기만 생산해 미션 55를 플레이했을 때 쉽게 죽고, 생산 좌표와 회피 방향이 겹치며, 탄환을 피한 것처럼 보인 뒤 피해를 받는다고 보고했다. 회피 방향을 적 중심의 12시~11시로 넓히도록 지시했다.

### 확인과 수정

`ProductionQueue::tick`은 원작 부품 조립 메크에만 무작위 X 좌표를 주고 있었다. 새 항공기는 이름으로 조립하는 유닛이라 X=0에서 생산됐다. 새 항공기에도 메크와 같은 출발 폭을 적용하고, 별도 난수 상태로 위치를 분산했다. 원작 포탑 운반기와 메크의 생성 처리는 유지했다. 이 위치 선택이 기존 적 생성·보상 난수를 소비하지 않는지 검사했다.
