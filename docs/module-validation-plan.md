# 모듈화 전후 치트앱 검증 계획

2026-11-05. 계획 작성. 모듈 분리와 아래 재검사는 아직 실행하지 않았다.

## 기준과 순서

같은 모듈화 브랜치에서 **원작 대조·수정 → 수정본 검증·커밋 → 모듈 분리 → 동일 검사** 순서로 진행한다. 비교 기준은 원작 방식으로 수정하고 검증한 커밋이다. 현재 오류가 있는 구현을 그대로 정답으로 삼지 않는다. 사용자 승인 화면 확장·영어 전용·광고 제거는 유지한다.

원작 대조에는 위메이드 1.0.3 포팅판과 원본 함수·데이터 근거를 사용한다. 분리 전후에는 같은 SDK·최적화·시뮬레이터·자원·시험 저장·난수·틱 수·입력 순서를 사용한다. 결과가 다르면 첫 차이가 발생한 틱과 호출을 찾는다. 의도한 수정의 기대값 변경은 해당 수정 커밋과 원본 근거를 남긴다.

1. 기존 실패 조건과 시험 저장을 보존한다.
2. 렌더·이미지·오디오·UI 처리의 원작 차이를 고치고 관련 검사를 실행한다.
3. 수정 기준점에서 전체 검사를 실행하고 비교 자료를 저장한다.
4. 모듈별 분리 때 직접 영향을 받는 검사를 실행한다.
5. 분리 완료 후 iPhone 시뮬레이터 → iPad 시뮬레이터에서 전체 검사와 일반 앱 회귀를 실행한다.
6. 실기기 음향·프레임·중단 복귀는 사용 가능한 iPad에서 마지막으로 확인한다. 사용 중인 iPhone은 조작하지 않는다.

## 치트앱 사용 방법

치트는 미션·크레딧·셀·강화·장비·적 배치·체력을 준비한다. 생산·구매·사격·피해·결과 처리는 일반 앱과 같은 함수를 실행한다. 시험별 독립 슬롯을 사용하고 끝나면 입력·음향·세션을 정리한다. 사용자 저장을 덮어쓰지 않는다.

| 방식 | 사용처 | 확인하는 것 |
|---|---|---|
| 코어 빠른 검사 | 수치·상태·저장·80미션 자동 교전 | 실제 게임 코드에 고정 조건을 넣고 결과 비교 |
| 치트앱 호스트 XCTest | 실제 GPU·오디오·파일 저장과 대량 조건 | 같은 게임 코드와 실제 출력 연결의 동작 |
| 설치 앱 직접 조작·실시간 실행 | 터치 전달·창 전환·생명주기·소리·프레임 | OS 입력과 사람이 보는 화면·듣는 소리 |

XCTest의 터치 함수 호출과 화면 직접 조작은 각각 기록한다. 빠르게 여러 틱을 처리하는 검사와 실제 속도 성능 측정도 구분한다.

## 기존 검사와 추가할 부분

현재 `tools/run_apple_sweep.py`는 `MachDefenseRendererTests` 스킴의 검사 **6개만** 선택한다. 전체 검증에는 아래 범위도 포함한다.

- 기존 6개: 포팅판 관측 구매, 80미션 승패·진입·저장, 전체 생산·특수기술, 전체 강화 단계, 전체 무장 정의, 짧은 실시간 전투.
- 추가로 선택할 기존 검사: RendererTests 전체, AudioTests 전체, MenuRenderTests의 화면 확장·핵폭탄·기지 강화 실제 효과·피격음 순서·음향 복귀·영문 메뉴·피드백 버튼·생산 딤/설치 안내.
- CTest 전체와 `NaturalCampaignTests` 실행. NaturalCampaign은 강화 장비·셀 보충·아군 기지 체력 보강을 사용하는 치트 조건 자동 교전이다.
- 신규 준비: 분리 전후 틱별 상태/난수/그리기 순서 비교, 원작 이미지 처리 경계값, 미션 3·4·10·11·밀집 터렛·화면 밖 표적 고정 입력, 장시간/재진입 수명, 실제 출력음 비교, 일반/치트 앱 동일 무치트 조건 비교.
- 원본 표의 ID·단계별 실행 목록을 생성해 검사 결과와 대조한다. 미실행 항목을 출력하고 자동화하지 못한 항목은 직접 검사·근거를 명시한다.

기존 6개 재실행 명령은 `python3 tools/run_apple_sweep.py --simulator <확인한 UDID>`다. 전체 실행기는 추가 목록과 분리 전후 비교를 연결하도록 보강할 예정이다.

## 성능 판정·일반 앱 확인

시뮬레이터 성능 측정은 한 대씩 진행한다. 같은 Mac·모델·OS·빌드 설정·화면 크기·동시 유닛 수로 기준점과 완료본을 각각 3회 비교한다. 기존 게임 목표 간격을 유지한다. 로그는 메모리에 모으고 종료 후 기록한다.

전투·발사·피격·타이머 갱신으로 발생하는 저장 쓰기는 0회여야 한다. 준비 완료 후 같은 무기의 반복 사용에서 디코딩·GPU 업로드·오디오 버퍼 생성이 증가하면 원인을 조사한다. 새로운 자원의 최초 등장은 따로 집계한다. 반복적인 끊김이나 지속적인 메모리 증가가 새로 생기면 통과시키지 않는다. 측정 변동은 같은 조건 재측정과 Time Profiler·Allocations로 구분한다.

일반 앱의 시험 프로필에서 생성→첫 전투→생산→강화→실패/재도전→승리→다음 미션→저장 종료→재실행을 직접 실행한다. 치트앱은 치트 값을 바꾸지 않은 같은 조건으로 비교한다. 두 앱의 규칙 코드·자원도 대조한다.

실기기에서는 기관총·동시 사격·음악/효과음·중단 복귀를 확인한다. 시뮬레이터 결과를 실기기 프레임으로 보고하지 않는다. Android·웹·PWA·Tauri는 구현 후 같은 공통 시험 입력에 해당 플랫폼 저장·렌더·음향 검사를 추가한다.

일반/치트 빌드 성공, 전체 정의·단계 검사 누락 없음, 승인 수정 외 동작·저장 차이 없음, 화면·소리·입력 통과, 새 성능 회귀 없음으로 판정한다. 기존 미해결 버그는 ID와 결과를 남긴다. 모듈 분리 완료와 원작 기능 전체 복원 완료는 각각의 검사 결과로 판단한다.
