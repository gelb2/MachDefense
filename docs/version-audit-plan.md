# 전체 판본 조사와 소스 재개발 계획

2026-11-04 최신 사용자 요청. 소스 재개발에 앞서 MachDefense의 일반·HD·배급사별 판본과 모든 확인 가능한 버전·빌드 번호를 조사한다. 신규 앱은 영어만 지원한다. 이미지에 포함된 글자, 게임 렌더러가 그리는 텍스트, OS 입력창과 안내도 영어로 제공한다. 원본 다국어 분석은 원본 영문 표시를 찾기 위한 조사다. 다국어 제품 기능은 개발하지 않는다.

## 현재 근거

확보한 파일은 indieapps 1.0.3·1.0.5와 WeMade 1.0.3이다. 현재 포팅 기준은 indieapps 1.0.5다. 별도 MachDefense HD 파일은 아직 확인되지 않았다. 사용자는 캐나다·미국 구매판이 유닛 이름까지 영문이었다고 확인했다. 현재 포팅판에서 전투·미션 클리어·패배 후 미션 선택 복귀도 확인했다. 상세는 [관측 기록](port-observations-20261104.md)을 따른다.

초기 외부 목록 검색에서 [TouchArcade의 Mach Defense 항목](https://toucharcade.com/games/mach-defense)은 호환성을 `HD Universal`로 표시한다. 별도 HD 상품인지 유니버설 지원 표기인지 패키지·과거 상품 식별자로 추가 확인한다. 이 목록만으로 별도 HD판이 있다고 판단하지 않는다. [추가 보관 목록](https://test.iklassika.ru/catalog.php?author=&bit_64=0&category=&ios_version=&page=43&search=&show_compatible=0&type=games)의 Heavy MACH: Defense 1.0.3/1.0.5 표기도 기존 파일과 동일한지는 미확인이다.

## 조사 순서와 방법

1. **판본 목록 확정.** Internet Archive 모음과 추가 보관 기록, 당시 상품·업데이트 기록을 검색한다. 상품명·배급사·App Store ID·번들 ID·표시 버전·빌드 번호·지원 기기·출처·확보 여부를 표로 만든다. 같은 버전 이름이라도 실행 파일과 자원 해시가 다르면 별도 빌드로 비교한다. 존재 기록만 있고 구하지 못한 판본은 미확보로 남긴다. 모든 출시 빌드를 확보했다고 단정하지 않는다.
2. **패키지 전수 비교.** 확보한 모든 파일의 무결성·Info.plist·실행 파일 구조·전체 자원 목록과 해시를 읽는다. 원본은 저장소 밖에서 보존하고 추가 원본도 외부 원본 보관소에만 둔다. 같은 파일은 중복으로 분석하지 않고 달라진 파일을 추린다.
3. **영문·그림 조사.** 유닛·부품·버튼·이름·가격·도움말의 이미지와 테이블을 비교한다. 원본 픽셀 크기·크롭·피벗·알파·영문 글자의 존재를 확인한다. 언어별 완성 이미지, 문자열 합성, 단일 언어 패키지 중 어떤 방식인지 파일과 코드로 확인한다.
4. **원본 코드 비교.** 로컬 REA와 기존 LLVM 분석 근거로 자원 선택, 생산 버튼 합성, iPhone/iPad·Retina 분기, 국가·언어·저장 슬롯, 맵·유닛·강화·승패·저장을 추적한다. 함수 주소와 사용 자원을 판본별로 연결한다. 동일 버전 번호를 코드 동일성의 근거로 삼지 않는다.
5. **차이가 있는 기능 실행.** 시뮬레이터의 별도 호환 앱·저장 사본에서 영어 조건으로 같은 장면을 비교한다. 가격·유닛명·화질·업그레이드·승패·저장을 우선 검사한다. 정적 비교로 발견한 차이와 재현 실패에 따라 실행 범위를 넓힌다. 사용자 아이폰 앱과 저장은 변경하지 않는다.
6. **재개발 기준 결정.** 게임 로직의 기준 판본, 영문 자원의 출처, 고해상도 자원의 출처와 선택 이유를 작성한다. 판본을 섞을 때 게임 수치·좌표·파츠 연결·맵 진행의 차이를 확인한다. 최신 버전이라는 이유만으로 전체를 채택하지 않는다.
7. **소스 재개발 계획 작성.** 원본 함수/데이터와 신규 모듈 대응표, 에셋 준비와 바인딩 절차, 플랫폼 경계, 구현 순서, 포팅판 대조 검사를 구체화한다. 새 앱은 IPA·호환 런타임 없이 소스와 준비된 에셋만으로 빌드한다. iPhone/iPad 유니버설과 공용 에셋 조건은 [에셋 계획](universal-assets-plan.md)을 따른다.

## 조사 산출물과 착수 판단

판본 목록, 코드·자원 차이표, 영문 표시와 가격/화질 원인, 채택 판본·에셋 명세, 기능별 재개발·검사 계획을 남긴다. 미확보 판본과 확인하지 못한 동작은 해당 표에 남긴다. 기준 판본과 에셋 선택에 영향을 주는 미확정 사항을 검토한 뒤 재개발 착수 여부를 판단한다.

포팅판의 모든 버전에서 모든 미션을 먼저 완주하는 절차와 판본 전수 비교는 구분한다. 이미 확인한 플레이 결과는 재사용한다. 전체 기능·캠페인 검사는 [치트 검증 계획](compatibility-cheat-validation-plan.md)에 보존하고 재개발 대조에 활용한다. 현재 단계는 판본 조사이며 소스 재개발 완료나 착수로 보고하지 않는다.
