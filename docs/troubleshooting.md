# 트러블슈팅

## 기지 기관총 효과음마다 오디오 출력을 중단한 오류 — 2026-11-04

사용자는 iPad에서 적 탱크 포탄은 정상인데 기지 기관총이 발사될 때마다 화면이 끊기고 소리가 밀린다고 보고했다. 발사 때 파일을 쓰는지, 탄환을 계속 새로 할당하거나 이미지를 다시 만드는지 확인하도록 지시했다. HeavyMach 1처럼 Instruments와 프레임별 ms 측정으로 모든 무기를 검사하도록 요구했다.

새 Apple 오디오 구현은 효과음을 재생할 때 OpenAL 컨텍스트를 설정하고, 함수가 끝나면 이전 컨텍스트로 되돌렸다. 초기화가 끝난 뒤 이전 컨텍스트가 비어 있었으므로 효과음마다 컨텍스트를 설정했다가 해제했다. 이 과정에서 iPad의 오디오 출력이 시작·중단됐다. 원작은 초기화 때 컨텍스트를 설정한 뒤 유지했다. 새 구현에 추가한 수명 관리가 원작과 달랐다.

실제 iPad Air 13-inch M2, iPadOS 27.0.1의 Time Profiler에서 `MDAudio play` → `Scope` → `AudioUnitGraph` → `RemoteIO Start/Stop` → 시스템 응답 대기를 확인했다. 게임의 메인 스레드가 이 호출에서 기다렸다. 기록 길이는 184.14초이며 대기 스레드 수집을 켰다. 개별 발사 지연은 이 기록의 누적 샘플 가중치로 계산하지 않았다.

`MDAudio.mm`을 수정해 게임이 활성 상태일 때 컨텍스트를 유지한다. 같은 컨텍스트를 다시 설정하지 않으며, 효과음 재생의 불필요한 rewind도 제거했다. 비활성 전환에서 효과음·음악을 멈추고 컨텍스트를 해제하며 복귀할 때 연결한다. 음원과 OpenAL 버퍼·소스는 시작 시 준비해 재사용한다.

수정본을 iPad 치트 앱에 설치하고 기존 IPADTEST 슬롯의 2번 미션을 실행했다. 사용자는 이전 기관총 프레임 드랍이 개선된 모습을 보고 오디오 컨텍스트 원인과 일치한다고 확인했다.

### 수정 후 측정

프로파일러를 붙이지 않고 타이틀·슬롯·미션 진입·전투를 248.82초, 14,912프레임 수집했다. 측정값은 메모리에 모으고 홈 화면으로 나간 뒤 CSV 한 번으로 저장했다.

| 항목 | 결과 |
| --- | --- |
| 프레임 간격 p50 / p95 / p99 | 16.667 / 16.667 / 16.667 ms |
| 효과음 호출 | 644회, 406프레임 |
| 효과음이 있는 프레임의 오디오 호출 합계 p50 / p95 / p99 / 최대 | 0.045 / 0.161 / 0.204 / 0.340 ms |
| 게임 저장 파일 쓰기 | 0회 |
| 25ms 초과 프레임 간격 | 7회 |
| 가장 긴 프레임 간격 | 93.083 ms |

가장 긴 구간에는 텍스처 최초 업로드 35개, 게임 계산 44.365ms, 렌더 제출 49.051ms가 있었다. 해당 프레임의 오디오 호출은 0.135ms였다. 화면 전환과 새 효과의 첫 표시에서 발생하는 자원 준비 비용을 후속 검사한다. 기관총 반복 재생 문제와 별도로 남은 항목이다.

자동 검사는 효과음 100회 반복, 컨텍스트 유지, 비활성 해제·복귀를 포함한 오디오 XCTest 2개가 통과했다. 관련 코어 회귀 7개도 통과했다. 모든 무기·강화 단계의 실기기 측정과 오디오 중단 후 복귀 검사는 진행 중이다.

### 발사 경로에서 확인한 사항

- 기지 기관총은 직접 피해와 기존 256개 효과 슬롯을 사용한다. 기관총 발사마다 새 투사체를 만드는 경로가 아니다.
- 전투와 발사에서 저장 파일을 쓰지 않는다. 1,200 tick 회귀 검사와 위 실기기 측정에서 확인했다.
- 스프라이트는 OpenGL로 그리며 텍스처를 재사용한다. UIKit으로 매 발사 이미지를 만드는 경로는 없다.
- 전투 오류창·보상창에서 표·폰트 파일을 반복 읽던 별도 오류도 찾아 초기 로드로 옮겼다. [파일 접근 검사](evidence/render-save-audit-20261104.md).

관련 코드: `Sources/Platform/Apple/MDAudio.mm`, `MDApplication.mm`, `Apple/Tests/AudioTests.mm`. 원작 분석 위치: `SoundManager::init` 0x4aafc, 컨텍스트 초기화 0x48ddc, `SoundManager::play` 0x4af28.

로컬 측정 자료: `.local/ipad-source-audit/cheat-physical-cpu.trace`, `cpu-samples.xml`, `audio-fixed-frames.csv`, `audio-fixed-summary.json`. 원본 실행 파일과 분석 덤프는 저장소 밖에 보관한다.

## 포팅판에는 있고 소스판에 빠진 점수·레이더

동일 저장으로 기지 강화 6종을 대조하면서 전투 HUD의 누적 점수와 레이더 표식 누락을 발견했다. GameSession은 누적 점수 대신 이번 전투의 점수를 넘겼고, GameHUD는 레이더 배경만 그렸다. 원본 슬롯 점수와 RaderMark·MovePath 표시를 연결했다. 원본 함수 주소, 같은 조건의 저장 비교와 검사 결과는 [대조 기록](evidence/port-source-parity-20261104.md)에 있다.

## 강화창 CLOSE 뒤 그림이 남음

위메이드 포팅판과 같은 구매를 비교하던 중, 소스판의 CLOSE가 전투를 재개하면서 강화창 그림을 남기는 문제를 확인했다. GameSession의 hidden 상태가 UpgradeDialog에 전달되지 않았다. 닫는 처리에 표시·입력 상태 갱신을 추가했다. 유닛·특수기술 창의 닫기, 화면 제거, 전투 재개와 저장 횟수를 검사한다. 수정 전 실패와 수정 후 관련 3종 통과를 [포팅판 대조 기록](evidence/port-source-parity-20261104.md)에 남겼다.
