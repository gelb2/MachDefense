# 트러블슈팅

Codex가 원작과 다르게 구현한 오디오 처리와 누락한 화면·효과음이 있었다. 사용자가 설치본을 플레이하며 차이를 발견했고, 원본 대조와 계측을 지시해 수정했다.

## 차단 원인을 모른 채 후속 업무지시 거부 — 2026-11-08

Codex는 차단 이유를 알지 못한 채 사용자의 업무지시를 거부했다. 도안의 글씨를 모두 지우고 계속 작업하라는 지시도 실행하지 않았다.

Cheyenne 이미지 생성 요청은 출력 단계에서 `HTTP 400 / moderation_blocked / violence`로 차단됐다. Codex는 구체적인 원인을 확인하지 못했다. 사용자가 “이미지에서 글씨 다 지우고 다시 진행해”라고 지시하자, Codex는 이를 차단 우회로 해석해 거부했다. 글씨 제거 편집은 호출하지 않았으며, 해당 편집 자체가 도구에서 거절된 증거도 없었다. 이후 원인을 모른다는 설명과 잘못을 인정하는 답변만 반복했고 작업을 수행하지 않았다.

Codex는 경위서 초안에서도 직접 한 거부를 “사용자가 지적한 일”로 표현했다. 사용자가 다시 지적한 뒤 Codex의 행동을 사실로 직접 기록하도록 고쳤다. 글씨 없는 도안과 새 Cheyenne 그림은 없고, AH-10의 비율 차이도 남았다. 이 기록 작성으로 아트 작업이 해결된 것은 아니다. [지시·거부 답변·오류·미완료 범위 경위서](evidence/aircraft-instruction-refusal-20261108.md).

## 신규 유닛 승인 시안 불이행·허위 완료 보고 — 2026-11-08

Codex는 사용자가 컨펌한 시안을 적용하겠다고 답한 뒤 다른 생성 그림을 적용하거나 몸체 기준을 잘못 맞췄다. 그 상태를 승인 시안의 형태·색·비율이 반영된 것처럼 보고했다. 사용자가 수차례 직접 지적해야 했다. 승인 불이행과 허위 완료 보고를 그림 수정 내역과 함께 기록한다.

Codex가 만든 추가 레벨 포탑은 원작과 다른 어두운 색·매끈한 표면·무기부 비례로 사용자의 재작업 지시를 받았다. 헬기 작업에서는 승인 그림을 다른 생성 그림으로 바꿨고, 크기 기준의 메크 레벨과 건쉽 중앙 동체·전체 폭을 잘못 적용했다. 색·로터·기울임·총구·아이콘 크기 문제도 있었다. 사용자가 반복해서 지적한 내용과 파일에서 확인한 오류, 수정·미완료 상태를 [전체 기록](evidence/new-unit-art-errors-20261108.md)에 모았다.

마지막 건쉽 중앙 동체 재생성 요청은 `HTTP 400`, `moderation_blocked`, `violence`를 포함한 한 번의 오류 응답으로 실패했다. 입력 단계 차단이며, 정확히 어느 입력이 원인인지는 응답에 없었다. 세 항목의 뜻과 응답 원문도 같은 기록 마지막에 보존했다. 현재 건쉽 비율은 요구를 충족하지 못했다. 기능 자동검사의 통과를 외형 완성으로 보고하지 않는다.

## 오디오 세션의 메인 스레드 호출 — 2026-11-05

Codex가 작성한 Apple 실행기는 화면 연결·활성 전환·오디오 중단 처리에서 AVAudioSession의 setCategory/setActive를 메인 스레드로 호출했다. OS 오디오 서비스 응답을 기다리는 동안 게임 입력과 그리기도 멈출 수 있었고, Xcode에서 메인 스레드 호출 경고가 발생했다.

세션 설정·활성화·비활성화를 하나의 직렬 큐로 옮겼다. 요청마다 세대 번호를 붙여 늦게 끝난 활성화가 최신 비활성 상태를 덮지 않게 했다. 재생 객체를 먼저 멈춘 뒤 세션을 비활성화하고, 활성화 성공 뒤 효과음과 음악을 재개한다. 게임 입력은 세션 완료를 기다리지 않는다.

실제 iPad 오디오·복귀·전투 검사 6개가 통과했고 실행 경고는 0건이었다. 1,800프레임의 대기·기관총·강화 무장·동시 교전 구간에서 간격 p99는 16.667ms, 25ms 초과는 0회였다. 이후 사용자가 발견한 효과음 복귀 누락은 아래 항목에서 다룬다. [코드 변경·기기 측정](evidence/audio-session-20261105.md).

## 백그라운드 복귀 후 효과음 소실 — 2026-11-05

OpenAL Soft 컨텍스트 처리 함수를 오디오 출력 장치 재시작으로 잘못 사용했다. 복귀 뒤 효과음 호출은 성공해도 실제 샘플은 진행하지 않았다. 장치 pause/resume 연결로 수정하고 iPad에서 수정 전 실패·수정 후 통과를 확인했다. 이전 검사는 효과음 호출 횟수만 확인해 누락을 발견하지 못했다. [재현·수정·검사](evidence/effects-resume-20261105.md).

## 안내·완료음·로딩 화면 누락과 복귀 후 입력 정지

포탑 안내, 생산 불가 딤 표시, 생산 완료 효과음, 다음 스테이지의 전투 일러스트를 새 코드에 연결하지 않았다. 생산·진행·저장 중심 검사는 이 누락을 잡지 못했다. 촬영 후 복귀 먹통은 오디오 중단 플래그가 게임 입력까지 막는 Apple 실행기 코드에서 발생할 수 있었다. 원작 함수와 새 코드의 대응, 수정 및 검사는 [정식 앱 피드백 수정 기록](evidence/source-ui-audio-lifecycle-20261104.md)에 정리했다.

## 기관총 발사 시 프레임 저하 — 2026-11-04

사용자는 iPad에서 적 탱크 포탄은 정상인데 기지 기관총이 발사될 때마다 화면이 끊기고 소리가 밀린다고 보고했다. 발사 때 파일을 쓰는지, 탄환을 계속 새로 할당하거나 이미지를 다시 만드는지 확인하도록 지시했다. HeavyMach 1처럼 Instruments와 프레임별 ms 측정으로 모든 무기를 검사하도록 요구했다.

새 Apple 오디오 구현은 효과음을 재생할 때 OpenAL 컨텍스트를 설정하고, 함수가 끝나면 이전 컨텍스트로 되돌렸다. 초기화가 끝난 뒤 이전 컨텍스트가 비어 있었으므로 효과음마다 컨텍스트를 설정했다가 해제했다. 이 과정에서 iPad의 오디오 출력이 시작·중단됐다. 원작은 초기화 때 컨텍스트를 설정한 뒤 유지했다. 새 구현에 추가한 수명 관리가 원작과 달랐다.

실제 iPad Air 13-inch M2, iPadOS 27.0.1의 Time Profiler에서 `MDAudio play` → `Scope` → `AudioUnitGraph` → `RemoteIO Start/Stop` → 시스템 응답 대기를 확인했다. 게임의 메인 스레드가 이 호출에서 기다렸다. 기록 길이는 184.14초이며 대기 스레드 수집을 켰다. 개별 발사 지연은 이 기록의 누적 샘플 가중치로 계산하지 않았다.

`MDAudio.mm`을 수정해 게임이 활성 상태일 때 컨텍스트를 유지한다. 같은 컨텍스트를 다시 설정하지 않으며, 효과음 재생의 불필요한 rewind도 제거했다. 비활성 전환에서 효과음·음악을 멈추고 컨텍스트를 해제하며 복귀할 때 연결한다. 음원과 OpenAL 버퍼·소스는 시작 시 준비해 재사용한다.

수정본을 iPad 치트 앱에 설치하고 기존 IPADTEST 슬롯의 2번 미션을 실행했다. 사용자는 이전 기관총 프레임 드랍이 개선된 모습을 보고 오디오 컨텍스트 원인과 일치한다고 확인했다.

### 수정 후 측정

프로파일러를 붙이지 않고 타이틀·슬롯·미션 진입·전투를 248.82초, 14,912프레임 수집했다. 측정값은 메모리에 모으고 홈 화면으로 나간 뒤 CSV 한 번으로 저장했다.

| 항목 | 결과 |
| --- | --- |
| 프레임 간격 p50 / p95 / p99 | 16.667 / 16.667 / 16.667 ms |
| 효과음 호출 | 644회, 406프레임 |
| 효과음이 있는 프레임의 오디오 호출 합계 p50 / p95 / p99 / 최대 | 0.045 / 0.161 / 0.204 / 0.340 ms |
| 게임 저장 파일 쓰기 | 0회 |
| 25ms 초과 프레임 간격 | 7회 |
| 가장 긴 프레임 간격 | 93.083 ms |

가장 긴 구간에는 텍스처 최초 업로드 35개, 게임 계산 44.365ms, 렌더 제출 49.051ms가 있었다. 해당 프레임의 오디오 호출은 0.135ms였다. 화면 전환과 새 효과의 첫 표시에서 발생하는 자원 준비 비용을 후속 검사한다. 기관총 반복 재생 문제와 별도로 남은 항목이다.

자동 검사는 효과음 100회 반복, 컨텍스트 유지, 비활성 해제·복귀를 포함한 오디오 XCTest 2개가 통과했다. 관련 코어 회귀 7개도 통과했다. 모든 무기·강화 단계의 실기기 측정과 오디오 중단 후 복귀 검사는 진행 중이다.

### 발사 경로에서 확인한 사항

- 기지 기관총은 직접 피해와 기존 256개 효과 슬롯을 사용한다. 기관총 발사마다 새 투사체를 만드는 경로가 아니다.
- 전투와 발사에서 저장 파일을 쓰지 않는다. 1,200 tick 회귀 검사와 위 실기기 측정에서 확인했다.
- 스프라이트는 OpenGL로 그리며 텍스처를 재사용한다. UIKit으로 매 발사 이미지를 만드는 경로는 없다.
- 전투 오류창·보상창에서 표·폰트 파일을 반복 읽던 별도 오류도 찾아 초기 로드로 옮겼다. [파일 접근 검사](evidence/render-save-audit-20261104.md).

관련 코드: `Sources/Platform/Apple/MDAudio.mm`, `MDApplication.mm`, `Apple/Tests/AudioTests.mm`. 원작 분석 위치: `SoundManager::init` 0x4aafc, 컨텍스트 초기화 0x48ddc, `SoundManager::play` 0x4af28.

로컬 측정 자료: `.local/ipad-source-audit/cheat-physical-cpu.trace`, `cpu-samples.xml`, `audio-fixed-frames.csv`, `audio-fixed-summary.json`. 원본 실행 파일과 분석 덤프는 저장소 밖에 보관한다.

## 점수·레이더 표시 누락

동일 저장으로 기지 강화 6종을 대조하면서 전투 HUD의 누적 점수와 레이더 표식 누락을 발견했다. GameSession은 누적 점수 대신 이번 전투의 점수를 넘겼고, GameHUD는 레이더 배경만 그렸다. 원본 슬롯 점수와 RaderMark·MovePath 표시를 연결했다. 원본 함수 주소, 같은 조건의 저장 비교와 검사 결과는 [대조 기록](evidence/port-source-parity-20261104.md)에 있다.

## 강화창 잔상

위메이드 포팅판과 같은 구매를 비교하던 중, 소스판의 CLOSE가 전투를 재개하면서 강화창 그림을 남기는 문제를 확인했다. GameSession의 hidden 상태가 UpgradeDialog에 전달되지 않았다. 닫는 처리에 표시·입력 상태 갱신을 추가했다. 유닛·특수기술 창의 닫기, 화면 제거, 전투 재개와 저장 횟수를 검사한다. 수정 전 실패와 수정 후 관련 3종 통과를 [포팅판 대조 기록](evidence/port-source-parity-20261104.md)에 남겼다.

## 완료 표시 오류와 UI 효과음 누락

원작의 누락된 CompleteMark.png를 새 코드에서 다른 도장으로 대신 그려 위치와 잘림이 발생했다. 포팅판 화면을 확인한 뒤 임의 대체를 제거했다. 로딩·구매·장착·패널 효과음의 누락도 원본 호출과 대조해 복구했다. [원인·수정·기기 검사](evidence/source-ui-audio-lifecycle-20261104.md).

핵폭탄 피해에 대한 추가 확인은 [별도 검사 기록](evidence/nuclear-damage-20261104.md)에 있다. 계산 오류는 발견하지 않았으며 피해량은 변경하지 않았다.

## 기지 강화 외형 시점과 오디오 복귀 — 2026-11-04

기지 강화 구매 때 차체·레이더까지 즉시 바뀌던 코드를 수정했다. 원본처럼 체력·무장을 먼저 반영하고 차체·레이더는 다음 스테이지에서 갱신한다. iPad에서 강화 실제 효과 108조건·456구매·외형 전환 30조건을 통과했다.

사진 촬영 뒤 게임 메뉴는 동작해도 소리가 사라지는 후속 경로는 복귀 이후 도착한 과거 오디오 중단 알림이었다. 지연 알림을 재현하고 활성화 성공 시 중단 상태를 해제했다. 미디어 서비스 재설정 때 기존 음악을 복원하고 재생 시간 증가도 검사했다. [수정과 iPad 결과](evidence/base-audio-followup-20261104.md).

원본의 개별 효과음·화면 연결 누락과 기존 검사에서 놓친 조건은 [복원 절차 점검](evidence/restoration-process-audit-20261104.md)에 정리했다. restore-machdefense 스킬에 동작별 원본 자원·조건·출력 비교와 강화 실제 효과 검사를 추가했다.

## 원본 오디오·텍스처 대조와 모듈 분리 — 2026-11-05

재구현판은 음악까지 PCM으로 풀어 OpenAL에서 재생했고 효과음은 일괄 16비트 변환했다. 원본 분석에서는 효과음의 원래 PCM 형식을 보존하고, 음악은 AudioFile/AudioQueue로 압축 패킷을 반복 재생했다. 이 절차로 수정하고 포팅판의 OpenAL Soft를 연결했다. 피격음의 카메라 상대 위치도 복원했다.

원본 Texture2D는 이미지 가장자리를 투명하게 패딩하고 콘텐츠 크기로 UV를 계산했다. NPOT 원본 크기를 바로 업로드하던 경로를 수정하고 스프라이트·메시를 함께 검사했다.

교체 중 XCTest에 OpenAL을 이중 연결해 서로 다른 컨텍스트 전역 상태를 읽는 문제가 나왔다. 테스트는 앱의 MDAudio를 통해 같은 컨텍스트를 확인하도록 고쳤다. 음악을 분리한 뒤 효과음 개수 기대값도 80에서 77로 수정했다.

이후 Core의 함수와 Audio 출력 모듈을 분리했다. [변경 근거·검사 결과](evidence/module-work-20261105.md), [모듈 구조](../Modules/README.md).

## 10레벨 확장 후 사거리 증가 누락

첫 확장안은 원작 최종 무기 행을 복사한 뒤 공격력·발수·발사 주기를 늘렸지만 `ShtRng`를 그대로 뒀다. 미사일 포탑뿐 아니라 포탑 6종과 기지 기관총의 새 단계에서 사거리가 늘지 않았다. 사용자가 강화창을 보고 지적했다. 화면은 실제 고정값을 표시하고 있었다.

원작 마지막 단계의 사거리 증가량을 이어 33개 값을 수정했다. 강화창 ATK.·Range·DEF.와 증가량을 글자 스프라이트까지 대조하고, 이전 단계의 사거리 밖에 둔 적을 다음 단계가 공격하는지 검사했다. 공용 검사 40개, Chrome·WebKit 치트 검사, 실제 iPad 강화·스크롤·전투 검사를 통과했다. [수정 전후 수치](evidence/level10-range-damage-20261107.md).
