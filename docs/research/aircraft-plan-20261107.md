# 공중유닛 구상

[현재 과제 27](../usability-todo.md). 2026-11-07 사용자 지시를 바탕으로 조사했다. 두 번째 시안의 화풍을 사용해 부품 제작과 원작 조립 절차 연결을 진행한다. 캠페인에 공중유닛을 아직 추가하지 않았다.

## 사용자 후속 지시와 재시안

첫 시안은 원작 텍스처·도트·마모와 다르다는 사용자 지적으로 **기각**했다. 원본 참조로 재사용하지 않는다. 헬기 형태 참고는 아머드코어6 첫 스테이지 헬기 보스와 엔드워 미국 진영 헬기다. 두 게임의 광택·렌더링·UI를 복사하지 않고, MachDefense의 원본 메크·탱커·탱크의 재질과 픽셀 표현을 따른다. 헬기 재시안을 기존 통합 보고서에 먼저 올린 후 타이틀·원본 iPad 화면·Tauri 검사·로컬 저장 처리 순으로 진행한다.


### 헬기·VTOL 추가 형태 참고 — 사용자 원문

- 아머드코어6 첫 스테이지 헬기 보스
- 엔드워 미국 진영 헬기
- 커맨드 앤 퀀커 시리즈에 나오는 오르카 모델들 전체
- 스타크래프트2의 밴시
- 에일리언2에 나오는 수송선
- 영화 아바타1에 나오는 대형 건쉽과 소형 건쉽

오르카는 한 모델로 축약하지 않고 작품별 파생형을 조사한다. 영화 기체는 해당 장면·공식 명칭과 대조해 식별한다. 동체·로터/덕트·추진기·무장 배치의 참고 목록이며, 이 작품들의 렌더링 질감을 MachDefense 화풍 대신 쓰지 않는다. 모든 참고를 한 기체에 합치는 것으로 해석하지 않는다.

[전체 참고 목록과 계열별 설계](aircraft-reference-library-20261107.md). 원작의 지상유닛처럼 체급·형태·무장 구성을 여러 계열로 나눈다. 현재 두 기체만으로 전체 디자인 범위를 닫지 않는다.

## 채택 화풍과 크기 기준 — 사용자 후속 지시

사용자가 두 번째 시안의 화풍을 채택했다. [채택 그림](../../Art/Aircraft/concepts/aircraft-v2.png)의 몸체·장갑·재질을 기준으로 부품을 만든다. 첫 시안은 계속 기각 상태다.

사용자 원문:

> 헬기는 이 화풍으로 원작자가 에셋, 유닛들 파츠 조립 한 절차를 준수해서 만들어본다. 만들기 전에, 소형헬기는 적 유닛중 빨간색 장갑차, 중량형 헬기는 적 유닛중 미션 40 후반부터 나오는 초대형 탱크로 각각 사이즈 표준을 맞춘다.

[크기 측정과 연결점 조사](aircraft-scale-20261107.md). 빨간 소형 장갑차 후보는 `E_Tank_01`, 미션 47에 처음 등장하는 초대형 탱크는 `E_Tank_32`다. 원작 조립과 같은 방향에서 몸체·무장 전체 그림 범위는 각각 57×32, 100×105 원본 픽셀이다. 그림자는 따로 측정한다. 기기 화면 배율을 적용하기 전 값이며 PNG 여백이나 충돌 반경을 크기로 쓰지 않는다.

## 기체와 부품

소형 헬기는 몸체·무장·중앙 로터, 중량형은 몸체·무장·좌우 로터를 나눈다. `MachInfo → PartsInfo → PartsList → TileList` 조립 구조에 연결점과 총구를 등록한다. 로터는 부모 몸체의 연결점에 붙이고 자체 각도로 회전한다. 그림자와 본체는 기존 `BattleModels::appendSprites`의 순서로 그린다.

몸체·무장·로터 전체를 조립한 뒤 기준 유닛과 같은 월드 배율로 비교한다. 로터의 회전 전체 범위를 포함하고 그림자는 별도 표시한다. 실제 게임 크기와 확대 화면을 함께 검수한다. 기체 길이와 폭을 따로 늘리지 않는다. 세부 비례가 기준 체급에 들어맞지 않으면 부품 배치를 수정한다. 각 부품을 별도로 꽉 차게 확대해서 조립 비율을 깨지 않는다.

기울임은 좌·중앙·우 상태의 그림으로 표현한다. 기울어질 때 총구와 로터 연결점도 같은 자세로 맞춘다. 화풍 채택·기준 유닛 측정과 기존 C++ 조립 함수의 몸체·로터 시험까지 진행했다. 별도 무장·총구·기울임과 실제 전투 앱 검사는 남았다. [조립 시험](aircraft-scale-20261107.md#부품-조립-시험)을 참고한다.

## 곡선 이동과 사격

새 기체 전용 경로 자료에 완만한 S자, 좌측 선회, 우측 선회 패턴을 둔다. 시작 위상·좌우 폭·구간 길이를 범위 안에서 고른다. 위치를 순간이동시키지 않고 기존 `AircraftMotion`에 다음 목적지를 준다. 원작 적 항공기의 ±600 목적지를 그대로 좁은 전장에 적용하지 않는다.

추가 생성과 곡선 선택은 별도 난수 상태를 쓴다. 새 기능이 원작 난수를 더 소비해 지상유닛의 생성·이동·보상을 바꾸지 않게 한다. 추가 생성 기능을 끄면 기존 스폰 결과와 난수 진행이 같아야 한다.

사격 중에도 경로 진행을 유지한다. 멈춰서 발사하는 지상 AI 분기가 적용되지 않는지 확인한다. 회피기동으로 기존 총탄이 빗나갈 수 있다. 명중시키려고 기존 무기의 속도·유도·충돌 반경·피해 계산을 바꾸지 않는다. 적군과 아군의 대상 선정은 기존 거리·진영 기준을 사용한다.

## 파일과 검사 순서

1. 공용 `Simulation`에 새 기체의 경로 자료와 상태만 분리한다. 아군 생산과 추가 스폰은 이 상태를 초기화한다. iOS·Android·Web 클라이언트에 항공기 규칙을 복제하지 않는다.
2. 원작 메크·탱크·포탑과 같은 화면에서 크기, 회전 중심, 총구·로터·엔진 연결을 본다. 헬기 로터의 정지/회전/피격과 좌우 기울임 프레임을 따로 검사한다.
3. 치트 앱에서 아군·적군을 각각 생성해 구덩이·원형 구조물·밀집 포탑 위를 지나고, 이동하며 사격·피격·파괴되는지 검사한다. 기존 지상유닛의 지형 충돌은 유지한다.
4. 80개 원작 스폰 표의 해시와 기존 행을 대조한다. 추가 생성만 끈 기준 실행과 원작 지상 이벤트를 비교한다. 새 유닛의 생산·해금·가격·스테이지 수량은 기체 설계와 함께 결정한다.
5. 웹 치트에서 기능과 그림을 확인하고, iPad·Galaxy에서 동시 교전 프레임·메모리·음향을 측정한다. 로터를 돌리거나 경로를 계산할 때 저장 호출·이미지 재생성·매 프레임 자원 로드를 넣지 않는다.

클라이언트에는 공용 Frame에 들어온 그림을 그리는 기존 기능을 사용한다. 새 무기나 표적 규칙이 필요하면 이 계획과 분리해 검토한다.
