# 공중유닛 구상

[현재 과제 27](../usability-todo.md). 2026-11-07 사용자 지시를 바탕으로 조사했다. 두 번째 시안의 화풍을 사용해 부품 제작과 원작 조립 절차 연결을 진행한다. 캠페인에 공중유닛을 아직 추가하지 않았다.

## 아군 4종 시험 — 2026-11-08

사용자 최신 지시: 로터는 이전 버전으로 복귀. 헬기 2종·VTOL 2종은 우선 아군으로 시험한다. VTOL 외형은 확정되지 않았으며 추후 변경 가능하다. 원작 아군 메크 색을 참고한 도색과 부품 조립을 적용했다. [구현·시험 수치·검증·남은 작업](../evidence/aircraft-allied-20261108.md). 정식 캠페인·해금·강화에 아직 넣지 않았다. 후속 사용자 지시에 따라 좌우 방향 전환에는 감속·정지·반대쪽 가속을 추가한다.

## 사용자 후속 지시와 재시안

첫 시안은 원작 텍스처·도트·마모와 다르다는 사용자 지적으로 **기각**했다. 원본 참조로 재사용하지 않는다. 헬기 형태 참고는 아머드코어6 첫 스테이지 헬기 보스와 엔드워 미국 진영 헬기다. 두 게임의 광택·렌더링·UI를 복사하지 않고, MachDefense의 원본 메크·탱커·탱크의 재질과 픽셀 표현을 따른다. 헬기 재시안을 기존 통합 보고서에 먼저 올린 후 타이틀·원본 iPad 화면·Tauri 검사·로컬 저장 처리 순으로 진행한다.


### 헬기·VTOL 추가 형태 참고 — 사용자 원문

- 아머드코어6 첫 스테이지 헬기 보스
- 엔드워 미국 진영 헬기
- 커맨드 앤 퀀커 시리즈에 나오는 오르카 모델들 전체
- 스타크래프트2의 밴시
- 에일리언2에 나오는 수송선
- 영화 아바타1에 나오는 대형 건쉽과 소형 건쉽

오르카는 한 모델로 축약하지 않고 작품별 파생형을 조사한다. 영화 기체는 해당 장면·공식 명칭과 대조해 식별한다. 동체·로터/덕트·추진기·무장 배치의 참고 목록이며, 이 작품들의 렌더링 질감을 MachDefense 화풍 대신 쓰지 않는다. 모든 참고를 한 기체에 합치는 것으로 해석하지 않는다.

[전체 참고 목록과 계열별 설계](aircraft-reference-library-20261107.md). 원작의 지상유닛처럼 체급·형태·무장 구성을 여러 계열로 나눈다. 현재 두 기체만으로 전체 디자인 범위를 닫지 않는다.

## 채택 화풍과 크기 기준 — 사용자 후속 지시

사용자가 두 번째 시안의 화풍을 채택했다. [채택 그림](../../Art/Aircraft/concepts/aircraft-v2.png)의 몸체·장갑·재질을 기준으로 부품을 만든다. 첫 시안은 계속 기각 상태다.

사용자 원문:

> 헬기는 이 화풍으로 원작자가 에셋, 유닛들 파츠 조립 한 절차를 준수해서 만들어본다. 만들기 전에, 소형헬기는 적 유닛중 빨간색 장갑차, 중량형 헬기는 적 유닛중 미션 40 후반부터 나오는 초대형 탱크로 각각 사이즈 표준을 맞춘다.

[크기 측정과 연결점 조사](aircraft-scale-20261107.md). 빨간 소형 장갑차 후보는 `E_Tank_01`, 미션 47에 처음 등장하는 초대형 탱크는 `E_Tank_32`다. 원작 조립과 같은 방향에서 몸체·무장 전체 그림 범위는 각각 57×32, 100×105 원본 픽셀이다. 그림자는 따로 측정한다. 기기 화면 배율을 적용하기 전 값이며 PNG 여백이나 충돌 반경을 크기로 쓰지 않는다.

## 기체와 부품

### 무장 분리와 후속 지시 — 2026-11-07

사용자가 현재 두 기체의 크기·전체 외형을 채택했다. 소형의 색은 유지한다. 중형(기존 파일명 AHeavy)은 원작 탱크를 참고해 일부 장갑에 위험 표식과 강조색을 더한다. 개별 로터 날개가 회전하는 모습이 보이는 현재 표현은 수정 대상이다. 고속 회전 상태를 실제 영상에서 확인한다.

이 지시를 받았을 때의 시험본은 몸체 PNG에 무기 그림이 붙어 있었다. 당시 `AircraftComparison.hpp`에는 몸체·로터만 있었고 비교 World는 무장을 비웠다. 그 시점에는 무기 파츠 조립·총구·사격을 완료하지 않았다. 이후 분리와 원작 무장 연결을 구현하고 [C++·웹 검사](../evidence/aircraft-modular-20261107.md)를 마쳤다. 원작의 `World::configureWeapons`는 조립 부품 이름으로 무기 행을 찾으며, `updateWeapons`는 그 부품의 총구에서 발사한다. 헬기도 별도 무기 그림과 연결점으로 이 경로에 연결한다.

| 기체 | 연결할 원작 무기 |
|---|---|
| 소형 | 흰색 히트스캔 총탄 + 가장 약한 미사일 계열 |
| 중형 | 고속 포탄 + 중간 데미지 미사일 2발 + 가장 약한 히트스캔보다 강한 히트스캔 총탄 |

무기 파츠의 외형은 기체에 맞춰 새로 그리되 탄환·미사일·사운드·데미지·발사 절차는 원작 것을 재사용한다. 해당 원작 행과 연사 간격을 확인한 뒤 연결한다. 몸체에 남은 무기 그림을 제거하고 조립된 무기 PNG가 실제 사격 위치를 결정하도록 한다. 기존 무기 수치를 바꿔 요구에 맞추지 않는다. [제작 스킬](../../.agents/skills/assemble-mach-aircraft/SKILL.md)에 절차를 정리했다.

이후 참고 목록을 사용해 다른 헬기·VTOL 시안을 만든다. 기존 두 기체의 채택을 새 시안의 채택이나 캠페인 배치 승인으로 확대하지 않는다.

소형 헬기는 몸체·무장·중앙 로터, 중량형은 몸체·무장·좌우 로터를 나눈다. `MachInfo → PartsInfo → PartsList → TileList` 조립 구조에 연결점과 총구를 등록한다. 로터는 부모 몸체의 연결점에 붙이고 자체 각도로 회전한다. 그림자와 본체는 기존 `BattleModels::appendSprites`의 순서로 그린다.

몸체·무장·로터 전체를 조립한 뒤 기준 유닛과 같은 월드 배율로 비교한다. 로터의 회전 전체 범위를 포함하고 그림자는 별도 표시한다. 실제 게임 크기와 확대 화면을 함께 검수한다. 기체 길이와 폭을 따로 늘리지 않는다. 세부 비례가 기준 체급에 들어맞지 않으면 부품 배치를 수정한다. 각 부품을 별도로 꽉 차게 확대해서 조립 비율을 깨지 않는다.

기울임은 좌·중앙·우 상태의 그림으로 표현한다. 기울어질 때 총구와 로터 연결점도 같은 자세로 맞춘다. 화풍 채택·기준 유닛 측정과 몸체·로터 시험에 이어 별도 무장·총구의 실제 World 전투 검사를 마쳤다. 기울임 그림과 캠페인·실기기 검사는 남았다. [조립 시험](aircraft-scale-20261107.md#부품-조립-시험)을 참고한다.

## 곡선 이동과 사격

### 회피기동 후속 연구 — 사용자 지시

추가 지시: 아군 헬기도 크로스파이어 스킬과 추후 자동락온 기능을 사용할 수 있다. 헬기는 지형을 무시하고 구덩이·구조물 위를 비행한다. 지상유닛의 지형 충돌을 완화하는 방식으로 구현하지 않는다. 현재 `World::activateSpecial`의 크로스파이어 발사자 조건은 `player && type==0`이므로 헬기에는 아직 적용되지 않는다. 후속 구현에서 공용 발사자 선택과 자동락온의 참여 조건을 함께 조사하고, 헬기와 메크가 같은 스킬 레벨의 기존 크로스파이어를 쓰는지 검사한다.

현재 무장·그래픽 조립과 보고를 마친 다음 진행한다. 실제 공격헬기의 기동을 형태 참고로 조사하되 게임에서는 좌·우·좌상단·우상단·좌하단·우하단 이동으로 추상화한다. 전투 판정에 고도는 추가하지 않는다. 모든 진영의 기존 유닛은 적대 진영의 헬기를 공격할 수 있다. 현재 그림자 간격은 시각 표현이며 공격 면역이나 사거리 제한이 아니다.

헬기는 같은 티어의 지상유닛보다 내구력이 낮지만 공격 중 계속 움직인다. 탄속이 있는 비유도 탄환은 기체와 탄환의 실제 위치·경로가 어긋나면 빗나간다. 별도 확률 회피 판정이나 명중 보정은 추가하지 않는다. 히트스캔은 기존 즉시 피해 규칙을 유지해 헬기의 상성 무기가 되도록 한다. 원작 무기별 실제 유도 여부·탄속·충돌·히트스캔 코드는 조사 단계에서 먼저 대조한다. 사용자의 무기 분류 설명을 근거로 기존 무기의 동작을 바꾸지 않는다.

| 체급 | 사용자 지정 회피 범위 |
|---|---|
| 소형 | 자기 몸체를 기준으로 월드 맵 폭의 절반 정도를 좌우 회피기동에 사용 |
| 중형 | 소형보다 15% 작음 |
| 중대형 | 중형보다 **10+ 작음** — 원문 보존, 단위 미정 |
| 대형 | 소형의 절반 |

조사할 항목: 맵 폭과 HUD를 제외한 화면 폭의 차이, 반경과 전체 이동 폭의 구분, 맵 끝에서의 궤적, 사거리 유지, 여러 헬기의 경로 중복, 회피 중 발사·조준, 체급별 회전과 가속, 일시정지·재개, 프레임·메모리 비용. 원작 탄도와 히트스캔 규칙을 고쳐 헬기를 맞히게 하지 않는다. 아군 헬기의 레벨링·공격력·내구력·가격·업그레이드 비용은 지상 메크와 같은 정책을 적용하며, 같은 티어 대비 낮은 내구력은 별도 수치 비교에서 함께 맞춘다.

사용자 원문:

> 헬기 유닛이 공격시 좌 + 우 + 좌상단 + 우상단 + 좌하단 + 우하단 으로 회피기동 하는 행동패턴 — 실제 공격헬기의 좌우기동과 복잡한 기동을 기술적 레퍼런스로 삼아 게임에서 추상화 하여 구현할 방법론(고도개념은 게임에서 적용하지 않음. 모든 적 유닛과 모든 적 아군 유닛은 적대진영의 헬기 유닛을 공격할 수 있음)
>
> 이 패턴의 컨셉: 맥디펜스의 모든 무기는 비유도에 탄속이 있는 무기이거나, 쏘면 바로 맞는 히트스캔 무기임 --> 종래의 타워디펜스 계열 게임들이 유닛 자체의 탱킹과 고화력에만 의존 --> 헬기는 같은 티어의 지상유닛에 비해 내구력은 떨어지지만 공격시 회피기동을 하며 공격을 해 비유도에 탄속이 있는 무기는 자연스럽게 생성된 확률적인 요인으로 회피하여 다른 유닛들이 발사한 탄환을 안 맞음으로써 안맞는 탱커 역할을 할 수 있음 + 히트스캔 무기는 쏘면 맞는 무기 컨셉상 그냥 맞으므로 히트스캔 무기가 더 게임 벨런스의 관점에서 상성 유닛이 됨 + 모든 헬기유닛은 각자 회피 반경이 다름, 가령 소형은 자기 몸체를 기준으로 월드 맵 폭의 절반 정도를 좌 우로 회피 기동 시 사용 + 중형은 그보다 15% 작음 + 중대형은 중형보다 10+ 작음 + 대형은 소형의 절반
>
> 추가 기록: 아군 헬기 유닛의 경우 레벨링 정책과 공격력, 내구력, 가격, 업그레이드 비용 정책은 지상 메크 유닛과 동일

새 기체 전용 경로 자료에 완만한 S자, 좌측 선회, 우측 선회 패턴을 둔다. 시작 위상·좌우 폭·구간 길이를 범위 안에서 고른다. 위치를 순간이동시키지 않고 기존 `AircraftMotion`에 다음 목적지를 준다. 원작 적 항공기의 ±600 목적지를 그대로 좁은 전장에 적용하지 않는다.

추가 생성과 곡선 선택은 별도 난수 상태를 쓴다. 새 기능이 원작 난수를 더 소비해 지상유닛의 생성·이동·보상을 바꾸지 않게 한다. 추가 생성 기능을 끄면 기존 스폰 결과와 난수 진행이 같아야 한다.

사격 중에도 경로 진행을 유지한다. 멈춰서 발사하는 지상 AI 분기가 적용되지 않는지 확인한다. 회피기동으로 기존 총탄이 빗나갈 수 있다. 명중시키려고 기존 무기의 속도·유도·충돌 반경·피해 계산을 바꾸지 않는다. 적군과 아군의 대상 선정은 기존 거리·진영 기준을 사용한다.

## 파일과 검사 순서

1. 공용 `Simulation`에 새 기체의 경로 자료와 상태만 분리한다. 아군 생산과 추가 스폰은 이 상태를 초기화한다. iOS·Android·Web 클라이언트에 항공기 규칙을 복제하지 않는다.
2. 원작 메크·탱크·포탑과 같은 화면에서 크기, 회전 중심, 총구·로터·엔진 연결을 본다. 헬기 로터의 정지/회전/피격과 좌우 기울임 프레임을 따로 검사한다.
3. 치트 앱에서 아군·적군을 각각 생성해 구덩이·원형 구조물·밀집 포탑 위를 지나고, 이동하며 사격·피격·파괴되는지 검사한다. 기존 지상유닛의 지형 충돌은 유지한다.
4. 80개 원작 스폰 표의 해시와 기존 행을 대조한다. 추가 생성만 끈 기준 실행과 원작 지상 이벤트를 비교한다. 새 유닛의 생산·해금·가격·스테이지 수량은 기체 설계와 함께 결정한다.
5. 웹 치트에서 기능과 그림을 확인하고, iPad·Galaxy에서 동시 교전 프레임·메모리·음향을 측정한다. 로터를 돌리거나 경로를 계산할 때 저장 호출·이미지 재생성·매 프레임 자원 로드를 넣지 않는다.

클라이언트에는 공용 Frame에 들어온 그림을 그리는 기존 기능을 사용한다. 새 무기나 표적 규칙이 필요하면 이 계획과 분리해 검토한다.

## 아군 다중 무장 후속 조사

사용자 원문:

> 다 되면, 아군 유닛도 적 유닛처럼 무기 2, 3종을 쓰는 유닛이 있는지, 만약 없다면 그런 유닛을 추가해서 동작 시킬수 있는지 확인도 해봐야 한다

현재 헬기 무장·그래픽 보고를 마친 뒤 조사한다. 원작 아군 메크·포탑의 각 강화 단계에 연결된 무기 행, 실제 조립 부품, 런타임 무장 목록을 대조한다. 같은 무기의 총구 2·3개, 같은 무기 여러 부품, 서로 다른 무기 2·3종을 구분한다. 기지 무장은 생산 유닛과 따로 표시한다.

원작 아군에 사례가 없다면 기존 `configureWeapons`와 `updateWeapons`로 서로 다른 무기 부품을 연결한 아군 시험 유닛을 만든다. 각 무기의 독립 재장전·조준·총구·반동·사거리·탄환·소리와 실제 피해를 치트 World에서 검사한다. 생산·강화·부품 조립에 새 행을 추가하는 것만으로 가능한지, 아군 전용 분기가 무기를 하나로 제한하는지 확인한다. 헬기 2·3무장의 시험 성공을 원작 아군 전체의 조사 결과로 대신하지 않는다. 기존 메크의 무기나 스폰 표는 변경하지 않는다.

생산 표 대조 완료: 원작 117단계·현재 150단계의 아군 조립은 모두 무기 종류 1종이었다. 다중 무장 추가는 공용 발사 경로에서 가능하며 아군 헬기 2·3무장 시험으로 확인했다. 기존 메크의 무기 단일 칸, 아군 항공기 표적 획득 조건, 마지막 무장의 대표 사거리, 생산·강화·복원 연계를 후속 편입 계획에서 다룬다. [조사 결과와 전체 행](../evidence/aircraft-modular-20261107.md#아군의-다중-무장-조사).

## 미션 55 관측 후 수정 지시 — 2026-11-08

사용자가 소형 헬기의 빠른 사망, 중앙 생산, 동시 생산 기체의 동일 회피를 지적했다. 앞서 정한 여섯 방향은 적을 중심으로 한 열두 시계 방향으로 확장한다. 개별 시작 위상과 방향·전환 시간, 분산 생산을 사용한다. 체력과 소형 속도를 올려 결과를 맞추지 않고, 비유도탄의 착탄 시 실제 위치·폭발 피해와 히트스캔을 나눠 검사한다.

[구현과 전후 비교](../evidence/aircraft-allied-20261108.md#미션-55의-헬기-밀집과-피격--2026-11-08). 수정 후에도 미션 55 소형 3대 검사는 전멸했으므로 생존력 균형 검사는 남았다.

## 긴급회피 후속 합의 — 2026-11-08

우선순위는 기존 크기·색 수정이다. 이후 긴급회피를 검토·구현한다. 적 발사체 접근을 감지하면 위험 구역을 벗어나는 방향을 선택하고, 회피 목적지 도착 또는 최대 회피 시간 도달 때 회피 무적을 끝낸다. 원래 선회 경로에 돌아갈 때까지 무적을 늘리지 않는다. 최신 수정: 히트스캔의 탄환 궤적과 피격 효과는 유지하되 긴급회피 무적 구간에는 피해를 주지 않는다. 회피 종료 후 개체별 재사용 대기 동안에는 정상 피해를 받는다.

재사용 대기는 헬기 개체마다 독립적이며 회피 종료 후 0.25~0.5초 범위에서 각각 정한다. 전역 재사용 대기나 OS 타이머·스레드를 개체마다 생성하지 않는다. 기체 상태와 시뮬레이션 종료 시각으로 처리한다. 개체 수가 늘면 객체·렌더·무장 비용도 증가하므로 무제한 생산의 메모리 안전을 보장하지 않는다. 치트앱의 단계별 대량 생산·회피·파괴·재생산, Instruments의 Allocations/Leaks와 프로세스 메모리 및 프레임 시간 측정이 필요하다. 투사체 위협 탐색이 헬기 수×탄환 수로 과도하게 늘어나는지도 측정한다.

## 긴급회피 시각 효과 후속 연구 — 2026-11-08

사용자 지시: 앞선 크기·색 수정과 긴급회피를 마친 뒤, 긴급회피 시작 시 기체 양옆에서 플레어·채프 파티클 2~3개를 사출하는 방법과 스프라이트 제작 방법을 연구한다. 기체와 그림자가 함께 급격히 기울거나 변동해 급기동이 드러나는 연출을 구상하고 기존 통합 보고서에 추가한다. 2~3개가 전체 수인지 각 측면 수인지 미확정이므로 시안에서 전체 2개·3개와 양쪽 각 2개를 비교한다.

기존 파티클 풀·효과 텍스처·부품 연결점·기울임 투영을 재사용할 수 있는지 확인한다. 회피 시작 한 번당 생성하며 매 프레임 새 그림·텍스처·타이머를 만들지 않는다. 플레어·채프가 원작 무기의 유도나 명중 판정을 바꾸는 기능은 현재 요구에 없다. 기체와 그림자·로터·무장·총구의 동일 투영, 효과 종료 및 대량 동시 회피 비용을 검토한다. 연구·시안 과제이며 아직 구현하지 않았다.
