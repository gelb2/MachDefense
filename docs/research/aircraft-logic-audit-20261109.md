# 헬기 전체 로직과 원본 절차 대조

2026-11-09. 조사 기준은 `26da2db`다. [소스 목록](../evidence/aircraft-repair-20261109/source-inventory.json)은 헬기 이름·상태·호출을 가진 30개 소스 파일의 위치와 해시를 보존한다. 아래는 정의부터 생성·전투·표시·저장·파괴까지의 정적 대조다. 모든 플랫폼 실기기 동등성을 완료한 기록은 아니다.

원본 함수 근거는 [기존 분석](../evidence/source-analysis-20261104.md), [텍스처·오디오 대조](../evidence/module-work-20261105.md)를 재사용했다. 원본 의사 코드를 제작 소스라고 부르지 않는다. 원본 제작 도구·작업용 레이어 파일이 확보된 것은 아니다.

## 변경 금지 범위와 검사

[보호 파일 목록](../evidence/aircraft-repair-20261109/protected-files.json)에 공통 소스·플랫폼 소스·원본 자원 2,652개의 SHA-256을 고정했다. 모든 공통 소스 파일을 포함한다. 헬기 전용 소스·이미지와 원본이 아닌 Level10 추가 MCB 컨테이너만 별도로 다룬다. 추가 컨테이너에서도 기존 파츠·모델 노드는 보존한다. 원본 PartsInfo/MachInfo·원본 그림·표는 변경하지 않는다.

원본 유닛만 있는 phone/pad 각 80개 미션에서 동일 난수·360틱의 상태·그리기 명령·음원 호출·저장 결과를 수집하는 [회귀 도구](../../tools/aircraft_original_regression.cpp)를 추가했다. 수정 전후 결과를 대조한다. 이것은 해당 재현 조건의 회귀 검사이며, 모든 가능한 플레이의 무오류를 보장하는 표현으로 사용하지 않는다.

최초 선택한 과거 빌드 폴더에는 테스트가 꺼져 있어 CTest가 0개를 찾았다. 이를 통과로 계산하지 않고 BUILD_TESTING=ON인 별도 폴더를 구성했다. [코어 기준 검사](../evidence/aircraft-repair-20261109/baseline-core.txt)와 [원본 유닛 기준 출력](../evidence/aircraft-repair-20261109/original-baseline.txt)을 후속 수정의 비교 기준으로 남긴다.
