# 헬기와 원작 유닛의 파일·렌더링 경로

2026-11-09. **원작 탱크·메크도 PNG를 쓴다. 헬기 제작·조립·렌더링의 모든 절차가 원작과 같다는 확인은 아직 완료하지 않았다.** 사용자가 요청한 전체 대조를 `MD-AIRCRAFT-ASSET-PARITY-01`에 등록했다.

## 원본 패키지에서 확인한 PNG

원본 WeMade MachDefense 1.0.3 IPA의 SHA-256을 저장된 원본 명세와 대조했다. 값은 `882fe8efa9a0c3d51c23da190ee3d30376a1b6766e16cc6b87daf09b98dc92b1`이다. 아래 파일은 복원 저장소에만 있는 이름이 아니라 **원본 IPA 내부에도 존재한다.** 파일 서명·PNG 청크·크기·픽셀 형식을 직접 읽었다. [검사 기록](../evidence/aircraft-followup-20261109/original-png-audit.json).

| 원본 파일 | 역할 | 크기 | 내부 형식 |
|---|---|---|---|
| `E_Tank32_Body.png` | 적 탱크 차체 | 100×105 | 8비트 RGBA, CgBI PNG |
| `E_Tank32_Wpn.png` | 적 탱크 포탑 | 67×65 | 8비트 RGBA, CgBI PNG |
| `P_Body_18.png` | 메크 몸체 | 64×64 | 8비트 RGBA, CgBI PNG |
| `P_Wpn_Gun_106.png` | 메크 무장 | 64×16 | 8비트 RGBA, CgBI PNG |
| `P_Foot_32x16.png` | 메크 발 타일 시트 | 256×64 | 8비트 RGBA, CgBI PNG |

현재 헬기 이미지 28개도 PNG 서명과 IHDR을 검사했다. 모두 일반 8비트 RGBA PNG다. [헬기 파일 목록·해시·실제 조립 사용 여부](../evidence/aircraft-followup-20261109/asset-format-audit.json). 원본의 `CgBI`는 아이폰용 PNG 인코딩이며 입체 모델·그림자 레이어를 담는 형식으로 확인된 것은 아니다. 현재 Apple 로더는 CgBI 변환과 알파 복원 옵션을 켜고 이미지를 읽은 뒤 렌더링용 텍스처를 만든다. 확장자는 같지만 원본 파일 바이트·인코딩이 모두 같다는 의미는 아니다.

## 확인한 공통점과 차이

| 항목 | 원작·원작 유닛 경로 | 현행 헬기 경로 | 판정 |
|---|---|---|---|
| 기본 그림 | 투명도를 가진 2D PNG, 일부는 타일 시트 | 투명도를 가진 2D PNG, 파츠별 개별 파일 | 같은 이미지 계열, 분할 방식 차이 |
| 기체 조립 정의 | `PartsInfo.mcb`·`MachInfo.mcb`에서 읽음. 아군 메크는 장비 표로 조립 | `AircraftModels.hpp`가 메모리에서 같은 Chunk 구조를 생성해 추가 | 읽는 공통 구조는 같고 정의 저장 방식은 다름 |
| 부모·자식과 소켓 | 공통 모델의 위치·회전·층 순서 | 같은 공통 모델 사용 | 공통 경로 확인 |
| 파츠 그림자 | 각 이미지의 검은 실루엣을 옮겨 그림 | 같은 처리 후 비행 높이·알파 조정 | 기반은 같고 헬기 추가 처리 존재 |
| 필터 | 일반 파츠는 기본 필터 사용 | 비행 파츠는 nearest 지정 | 차이 존재, 화면 영향 대조 필요 |
| 좌우 선회 | 유닛별 부품 회전·이동 | 동일 정면 이미지의 네 꼭짓점 변형 | 헬기 전용 경로, 각도별 그림 부재 |
| 표면 입체 조명 | 확인한 현재 Apple·웹 경로에 별도 입체 조명 없음 | 같은 렌더러, 추가 표면 조명 없음 | 확인한 경로의 공통점 |
| 앱 포함과 실제 사용 | 파츠·타일 참조로 결정 | PNG 28개 중 현재 조립의 고유 참조 17개 | 파일 수와 소비 수를 구분해야 함 |

헬기에서 현재 조립에 쓰지 않는 11개는 네 기체의 `BodyBankL/R` 8개와 벨루가 `WingL/R`·`Engine` 3개다. 이번 도장 반영은 28개 파일을 대상으로 했지만, 실제 기체가 28개를 모두 그린다는 의미는 아니다. 몸체에 합쳐진 무장·날개와 별도 파츠의 차이는 [입체감 조사](aircraft-depth-20261109.md)에 기록했다.

근거는 [모델 로더](../../Sources/Core/Simulation/MachineModels.cpp), [헬기 조립 정의](../../Sources/Core/Simulation/AircraftModels.hpp), [파트 표시](../../Sources/Core/Presentation/MachineSprites.cpp), [월드 합성](../../Sources/Core/Presentation/WorldPresentation.cpp), [Apple](../../Sources/Platform/Apple/MDRenderer.mm)·[웹](../../Web/src/Renderer.cpp) 렌더러다.

## 남은 전체 대조

네 기체 각각의 제작 원본·분할 과정·실제 소비 파일과 조립 노드를 한 목록으로 연결한다. 원작과 같은 배율에서 명암·알파·필터·그림자·피벗·가림을 비교하고, Apple·웹·Android의 실제 표시 결과를 대조한다. 원작 편집 도구의 레이어 구성은 현재 PNG·실행 데이터만으로 확인되지 않았으므로 같은 제작 절차를 거쳤다고 단정하지 않는다. 원작 코드·에셋을 보존하면서 헬기 전용 수정안을 보고한다.

이번 추가 조사는 파일 읽기와 문서 기록이다. 게임 이미지·렌더러를 추가 수정하지 않았다.
