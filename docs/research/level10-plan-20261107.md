# 10레벨 확장안

2026-11-07 · 수치 제안과 코드 점검 · 게임 적용 전

모든 플레이어 강화 항목의 상한을 10으로 맞춘다. 새 단계를 추가할 대상은 포탑 6종, 기지 공격·방어, 특수공격 5종이다. 총 13개 항목에 59단계를 추가한다. 이미 10레벨인 메크·탱커·생산 시간·크레딧 연구·셀 연구·셀 저장량은 현재 값을 유지한다.

상한 10과 원작 최종 레벨 자원 재사용은 확정 요구다. 아래 성장 수치는 첫 제안이다. 기존 최종 단계의 다음 강화 가격을 연결하고 새 행을 추가한다. 기존 단계의 성능·생산 가격·외형·소리는 유지한다.

## 수치를 정한 방법

- 포탑 체력은 원본 5개 행에 모두 맞는 기존 후보식을 연장한다. 아래 체력은 실제 게임 적용값이다. 원본 `MachList.HP`는 로더가 두 배로 적용하므로 표에 기록할 값은 이 체력의 절반이다.
- 라이플·레이저는 단계당 피해 +5, 연사 +2발. 미사일은 피해 +20, 두 단계마다 연사 +1발을 추가한다. 발사 간격과 재장전은 아래 표만큼 줄인다.
- 벌컨은 피해 +5, 연사 +10발을 추가하되 발사 간격 0.04초와 재장전 1.9초를 유지한다. 0.01초씩 계속 줄여 0이 되는 확장은 사용하지 않는다.
- 이온·플라즈마는 1발형을 유지한다. 피해는 각각 +40·+30, 재장전은 각각 0.08·0.04초씩 줄인다. 이온의 주변 피해 조건과 플라즈마의 지속 피해 파라미터는 최종 단계 값을 유지한다.
- 기지 공격은 피해 +5, 연사 +2발, 발사 간격 -0.005초, 재장전 -0.05초다. 방어 체력은 단계마다 30,000을 더한다. 기지에는 무기가 두 개 있으므로 아래 무기 수치와 발사 검사는 무기 하나 기준이다.
- 폭격·미사일 특수공격은 피해 +100, 발사 수 +1, 범위 +10을 추가한다. 핵폭탄은 1발을 유지하며 피해 +1,000, 범위 +10을 추가한다.
- EMP는 1발을 유지한다. 피해 +50, 범위 +10, 정지 지속 시간 +2초를 제안한다. 최종 지속 시간은 48초다. 크로스파이어는 피해 300을 유지하고 발사 수 +1, 범위 +5를 추가한다.
- 기존 발사체 속도·분산·일반 사거리는 최종 단계 값을 유지한다. 새 단계의 이미지만 같고 탄도까지 달라지는 변경은 이번 안에 넣지 않았다. 범위 공격 반경은 아래 표에서 별도로 증가한다.

## 가격

강화 가격은 Cr이다. 포탑 생산 가격은 셀이고, 특수공격 1회 구매 가격은 Cr이다. 표의 강화 가격은 **해당 레벨에서 다음 레벨로 올라갈 때의 기본 가격**이다.

포탑은 마지막 유효 강화 가격부터 두 배씩 잇는다. 기지는 기존 600×2^(레벨−1)을 Lv.9까지 잇는다. 폭격·미사일·핵·EMP는 현재 상한에 이미 적힌 강화 가격에서 두 배씩 잇는다. 크로스파이어 Lv.8→9는 기존 20,000, Lv.9→10은 32,000을 제안한다. Lv.10에서는 다음 강화가 없다.

특수공격의 실제 강화 결제에는 원작의 `기본 강화 가격 + 보유 횟수 × (다음 구매 단가 − 현재 구매 단가)`를 유지한다. 예를 들어 폭격 5→6은 8,000Cr에 보유 폭격 1회당 100Cr가 더해진다. 새 단계 구매 단가는 폭격 +100, 미사일 +150, 핵 +200, EMP +300, 크로스파이어 +300Cr다.

포탑 생산 단가는 라이플·미사일 +30셀, 벌컨 +100셀, 이온 +300셀로 잇는다. 레이저는 원작의 200셀 고정을 유지한다. 플라즈마는 기존 +30,+40,+50,+60 다음으로 +70,+80,+90,+100,+110셀을 적용한다. 최고 생산 가격은 이온 Lv.10의 3,300셀이다. 기존 Cell Storage Lv.10의 기본 용량 4,700셀 안에 든다. 모든 단계가 초반 저장량에서도 생산 가능하다는 뜻은 아니다.

높은 단계의 강화 비용과 실제 미션 보상·긴급지원 수령량을 대조하는 플레이 검사는 남았다. 수학적 패턴만으로 게임 난이도를 확정하지 않는다.

`PartsInfo.mcb`와 `MachInfo.mcb`의 원본은 보존한다. 새 부품과 조립 정의는 **같은 Chunk 형식의 추가 파일**로 생성해 공용 모델 로더가 원본 다음에 읽는 방안을 사용한다. 이름 중복은 오류로 처리한다. 원본 정의를 바꿔 덮어쓰지 않는다. 새 코드가 필요한 부분은 추가 정의를 합치는 로딩 연결이다. 회전·반동·총구 순환·부품 조립 계산은 기존 코드를 사용한다.

단순히 `Turret_msl_10`의 그림 파일만 복사하면 연결점과 조립 정의가 없어 실패한다. 반대로 무기 이름까지 `Turret_msl_05`로 고정하면 새 피해·연사 수가 적용되지 않는다. 새 성능 이름과 최종 단계 그림을 각각 연결해야 한다. 데이터 로드, 장비 미리보기, 월드 생성, 치트 검사에서 같은 모델 목록을 사용하도록 묶는다.

특수공격의 새 ItemInfo Code 02006~02010, 02016~02020, 02026~02030, 02035~02040, 02109~02110은 현행 표에서 사용하지 않음을 확인했다. 기존 아이콘 번호를 그대로 참조하며 없는 레벨 아이콘을 만들지 않는다. 비활성 Laser·Flame 공격은 활성화하지 않는다.

## 실행한 수치 검사

`tools/plan_level10.py`로 130행과 무기 정의 120행을 생성했다. 원본 무기 행의 모든 필드 일치, 열 구조, 새 ItemInfo 번호 충돌, 수치 범위, 최종 레벨 시각·음향 필드 일치를 확인했다. 게임 Resources와 Sources는 변경하지 않았다.

기존 C++ DataTable·WeaponDefinition·WeaponController·AirStrike·crossfireProjectiles를 별도 검사 실행기에 연결했다. phone/pad 좌표 조건에서 120개 무기 정의씩 **240조건**을 실행했다. 일반 무기는 3,600틱(게임 시간 59.76초) 동안 고정 표적을 향해 쐈다. 폭격·크로스파이어는 한 번 사용했을 때 표에 적힌 탄수를 모두 생성했다. 일반 무기는 한 틱에 최대 1회씩 발사했다. 크로스파이어 Lv.10은 원래 동시 발사 방식으로 11발을 생성했다.

## 적용 후 검사

1. 원본 상한까지 모든 단계의 전투·가격·외형·소리를 기존 빌드와 대조한다. 상한에서 새 단계로 넘어가는 가격 연결은 별도로 비교한다.
2. 각 포탑의 새 레벨 구매→생산→운반→설치→공격→저장을 검사한다. 총구 위치·발사음·탄환 타일·아이콘은 최종 원본과 비교한다.
3. 기지 Cannon/Defense 10×10 조합을 검사한다. 전투 중 강화 때 교체되는 무기와 다음 미션에 적용되는 몸체·레이더를 원작 순서대로 확인한다.
4. 특수공격은 0·1·다수 보유 상태의 강화 비용, 발사 수·범위·정지·지속 피해를 검사한다. 폭발 그림 재사용 시 실제 피해 범위를 설명할 수 있는지도 화면에서 확인한다.
5. 포탑 1기·여러 기와 특수공격을 함께 사용하는 치트맵에서 프레임 시간·동시 탄환·입자·음향 호출·메모리를 잰다. 느려지는 경우 새 수치의 탄수·발사 주기를 먼저 조정한다.
6. iPhone·iPad·Android·Web/PWA에서 모든 새 단계의 구매·저장·재실행·MD1 왕복을 검사한다. 설치 상태·진척·자금과 나머지 슬롯을 비교한다.
