## 목표와 기존 구현

복원 코드 생성·해석·검증·적용 절차를 별도 C++ 모듈로 만든다. 같은 코드를 Apple·Android에서는 네이티브 라이브러리로, 웹에서는 WebAssembly로 빌드한다. 웹·설치형 PWA·Tauri Mac은 웹 실행 코드와 게임 산출물을 함께 사용한다. Mac의 PWA는 브라우저가 설치한 웹앱이며 Tauri Mac과 구분한다. 별도 AppKit 네이티브 Mac 개발은 이번 범위에 넣지 않는다.

현재 `Sources/Core`에는 전투·이동·강화·경제·세이브·메뉴·HUD·터치 판정이 있다. `Sources/Audio`에는 효과음 재생 구현이 있다. Apple·Android는 화면 출력, OS 입력 전달, 파일 저장, 배경음과 생명주기를 연결한다. 새 플랫폼 때문에 이 경계를 전부 다시 나누지 않는다.

인게임 복원 화면도 `Core/Presentation`에서 원작 버튼·글꼴·그리기 명령으로 만든다. UIKit·Android View·HTML 버튼으로 따로 구현하지 않는다. OS 키보드·클립보드·파일 접근만 플랫폼 서비스로 연결한다. 표시 문구는 영어다.

## HeavyMach1에서 가져올 절차

HeavyMach1의 웹판 기여와 후속 오류 수정본을 고정한 다음, 웹 산출물을 Tauri와 PWA에서 사용한 절차를 참고한다. 당시 첫 Tauri 구현 기록은 보호 파일 2,190개와 게임 산출물 10개의 바이트 일치를 남겼다. 이후 복원 코드와 인게임 버튼 추가 때는 승인된 연결부 변경이 있었다. 전체 기간에 걸쳐 웹 소스가 전혀 바뀌지 않았던 것은 아니다.

참고 경로는 HeavyMach 저장소의 다음 문서다. MachDefense 빌드가 옆 저장소를 요구하게 만들지 않는다.

- `docs/desktop-web-plan-20261031.md`: 웹판 고정, Tauri 파일 저장, PWA 포장 순서.
- `docs/design.md`: Core·플랫폼 실행기·공용 버튼의 실제 경계.
- `Modules/SaveTransfer/README.md`: 코드 형식, 슬롯 선택, 복원 중단 처리, 네이티브/Wasm 대조.
- `docs/reviews/mac-web-pwa-comparison-20261101.md`: 저장·오프라인·종료·입력·GPU 복구 검사.

MachDefense 웹 실행기는 기존 공용 Frame을 소비한다. Mac Chrome·WebKit 로컬 검사를 마쳤으며 모바일 PWA 실기기 검사는 남았다. 그 산출물을 고정한 뒤 PWA와 Tauri가 사용한다. HeavyMach1의 게임별 메뉴·HUD 복사본이나 세 슬롯 규격은 가져오지 않는다. 재사용하는 도구 코드에는 출처와 해당 파일의 라이선스를 남긴다.

Web·Distribution/Web·Modules/SaveTransfer는 구현했다. Desktop/Tauri는 예정 위치다.

## 복원 코드 데이터와 모듈

기준은 `Sources/Core/Session/SaveData.hpp`의 원본 5슬롯, 전체 42,496바이트(`0xa600`), 슬롯 시작 `0x408`, 간격 `0x2064`다. 원본 저장의 미확인 바이트도 보존한다. 메모리의 C++ 객체를 그대로 직렬화하지 않는다.

담을 항목은 프로필·미션 진행·클리어 횟수·누적 점수와 성장값·크레딧·기지 강화·보유 메크/터렛·특수공격의 단계/수량·장착 상태다. SaveData 전체 바이트를 보존하고, 항목별 해석은 실제 접근자와 원본 데이터로 대조한다. 전투 중 셀 잔량이나 현재 적·탄환·진행 중 생산처럼 기존 슬롯 저장에 없는 순간 상태를 복원 코드에 임의 추가하지 않는다. 긴급지원 대기 상태도 기존 정책처럼 전투 종료와 함께 끝난다.

생산 HUD 순서·확장 설정은 기존 저장에서 표현 가능한지 먼저 검사한다. 표현할 수 없으면 원본 저장과 분리된 버전 있는 확장 데이터로 담는다. 원본의 미확인 바이트를 임의 필드로 전용하지 않는다. 향후 10레벨 확장은 규격 버전·지원 기능과 함께 검사하여 구버전 앱이 값을 조용히 낮추거나 덮어쓰지 않게 한다.

코드 형식 초안은 `MD1-` 접두사, 형식 버전, 저장/확장 데이터, 압축 전 길이, 손상 검사값, 압축, Base64url이다. 해시만 담는 것이 아니라 복원할 값 자체를 담는다. 별도 서버·계정·암호화·salt는 넣지 않는다. 첫 구현은 전체 저장 42,496바이트, 입력 120,000자 상한, PackBits·CRC32를 사용한다. 확장 데이터는 아직 없다. 빈 저장과 실제 아이폰 저장으로 네이티브/Wasm 왕복을 대조했다. 생성 결과는 같은 입력이면 같아야 한다.

플랫폼 UI는 코드 형식을 해석하지 않는다. 공용 모듈이 문자·길이·압축 해제 한도·버전·손상·슬롯·데이터 범위를 검사하고, 플랫폼은 결과를 전달한다. 틀린 게임의 코드, 지원하지 않는 버전, 잘린 코드와 과도한 입력은 저장 전에 거부한다.

## 슬롯 화면에서의 조작과 저장

코드 생성·복원은 전환이 끝난 슬롯 선택 화면에서만 제공한다. 전투 중 새 저장 시점을 만들지 않는다. 공용 UI는 전체 5슬롯 또는 선택한 원본 슬롯→대상 슬롯, 확장 설정 포함 여부, 교체될 슬롯의 미리보기와 확인/취소를 제공한다. 첫 버전부터 모든 플랫폼의 선택 범위를 같게 한다. 단일 슬롯 복원에서 다른 슬롯과 공통 헤더를 어떻게 유지할지는 필드 소유 관계를 확인한 뒤 공용 코드로 구현한다.

1. 플랫폼 저장 읽기가 끝난 뒤 기존 값과 적용할 값을 검사한다.
2. 사용자가 확인하면 기존 값과 복원 대기 기록을 저장한다.
3. 목표 저장과 확장 설정을 적용한다.
4. 저장 완료 후 다시 읽어 목표값과 대조한다.
5. 대조 성공 뒤 대기 기록을 지우고 게임 세션이 새 저장을 읽게 한다.

복사·미리보기·취소는 게임 저장을 쓰지 않는다. 중간 종료 후에는 대기 기록으로 작업을 재개한다. 실패하면 기존 백업을 보존하고 성공 화면을 띄우지 않는다. 오래된 세션이 복원 직전 메모리를 다시 저장하지 못하게 진입·종료·재로드 순서를 공용으로 정한다. 사용자 저장은 테스트용 복사본으로 검사한다.

기존 `HostServices::writeSave`는 동기 `bool` 반환이다. 웹의 비동기 저장에 메모리 복사만 끝낸 뒤 성공을 반환하면 영구 기록 실패를 놓친다. 이 경계는 웹 시작 전에 해결한다. 복원 모듈에는 작업 ID와 저장 완료/실패를 받는 인터페이스를 둔다. 일반 저장은 기존 호출 지점을 유지하면서 완료 통지를 추가할지, 웹의 비동기 연결 기능으로 동기 계약을 보존할지 최소 실행 예제로 비교한다. 선택 근거와 영향 파일을 기록한 뒤 별도 커밋으로 검증한다. Apple·Android의 저장 구현을 선제적으로 전면 교체하지 않는다.

## 웹에서 필요한 연결과 모듈 점검

| 항목 | 점검·구현 방법 | 공유 범위 |
|---|---|---|
| C++ 실행 | 기존 Core를 Emscripten으로 빌드하고 동일 초기값·입력·난수·틱 수로 네이티브와 대조한다 | 게임 계산은 한 벌 |
| 렌더 | Frame의 sprite/mesh/clip/UV/pivot/회전/색상/블렌드/레이어를 WebGL2로 옮긴다. ES1 호출을 브라우저에 그대로 넘길 수 있다고 가정하지 않는다 | 웹·PWA·Tauri는 같은 렌더러 |
| 자원 | Resources의 동일 명세·해시를 사용한다. 디코딩·알파·투명 패딩·필터를 Apple/Android 출력과 대조한다 | 원본 에셋 한 벌 |
| 입력 | 터치·포인터·창 크기·안전영역을 공용 Touch/resize에 연결한다. 터치 취소·멀티터치·창 이탈을 검사한다 | 버튼 판정과 HUD 배치는 Core |
| 음향 | 공용 효과음의 Emscripten/OpenAL 연결과 브라우저 출력 지원을 시험한다. 필요 시 출력 어댑터를 추가한다. 음원 선택·재생 시점은 유지한다 | 웹 계열 음향 연결 한 벌 |
| 프레임 | requestAnimationFrame에서 기존 tick 계약을 유지한다. 60/120Hz·숨김 탭·복귀에서 게임 속도를 비교한다 | 추가 보정 계산이 필요하면 웹 실행기에서 공유 |
| 생명주기 | 숨김·복귀·음향 허용·WebGL context loss를 기존 setActive/렌더 재생성에 연결한다 | 세 웹 환경에서 같은 처리 |
| 저장 | 브라우저 저장 완료·실패, Tauri 파일 저장 완료·실패를 같은 서비스 결과로 전달한다 | 형식·복원 상태 전이는 공용 |

복원 기능 추가에 필요한 Core/UI 연결은 사전에 목록을 정한다. 전투·데미지·이동·강화 계산을 복원 모듈에 의존시키지 않는다. 웹 포팅 중 공용 변경이 필요하면 그 이유와 파일을 분리해 기존 플랫폼 검사를 먼저 통과시킨다. 정상 기준을 고정한 뒤 PWA/Tauri 포장 단계에서는 게임 산출물을 수정하지 않는다.

## PWA와 Tauri 저장·배포

웹·PWA는 IndexedDB에 진행을 저장하고 설치 파일 캐시와 분리한다. 저장 읽기 완료 전 빈 슬롯으로 시작하지 않는다. 동시 탭/설치 앱의 오래된 값 덮어쓰기를 막는다. 영구 저장 요청 결과를 확인하고 복원 코드로 외부 백업을 제공한다. 사용자 사이트 데이터 삭제나 브라우저 저장 회수까지 무조건 보존한다고 안내하지 않는다.

PWA는 버전별 자원 다운로드·해시 검증·오프라인 시작·진행을 보존하는 업데이트를 구현한다. 설치 유도와 다운로드 상태는 게임 시작 전 화면에 둔다. 설치 API와 안내는 Safari/Chrome 차이에 맞추되 같은 기능에 접근할 수 있게 한다. 게임 실행 중 버튼은 공용 게임 UI만 사용한다.

Tauri는 같은 웹 빌드를 앱에 포함하고 앱 데이터 폴더에 정상 저장과 복원 대기 기록을 둔다. 브라우저 저장만을 유일한 원본으로 삼지 않는다. 시작 때 파일을 읽은 뒤 게임을 열고, 명시적 저장 완료 후 파일을 검증한다. 웹뷰 저장 삭제·종료 중 쓰기·중단된 복원을 검사한다. Quit 메뉴·Cmd+Q·창 닫기의 동작을 각각 확인한다. 개인 웹브라우저의 저장소와 Tauri 저장소가 자동으로 같다고 가정하지 않는다.

2026-11-06 사용자가 공개 전환과 PWA 배포를 승인했다. GitHub Pages 주소는 https://gelb2.github.io/MachDefense/ 이다. 원본 IPA는 빌드·배포·웹 다운로드에 포함하지 않는다.

## 작업 순서와 완료 기준

1. **기준 보존:** develop에서 기능 브랜치를 만든다. Apple·Android·Core·Resources의 해시와 일반/치트 저장을 보관한다. 현재 버그는 별도 목록으로 유지한다.
2. **데이터 계약:** 생산 HUD 전체 목록·순서 확장과 저장 범위를 함께 정한다. 저장 실패·경계값 문제를 먼저 재현한다. 레벨10 전체 아트 제작은 웹 착수 조건으로 두지 않는다.
3. **공용 복원 모듈:** 코드·5슬롯·설정·복원 상태 전이와 공용 UI를 구현한다. Apple·Android에서 생성/복원/취소/중단 후 재실행을 확인한다. 웹용 Wasm 시험 벡터도 이 단계에서 만든다.
4. **웹 실행기:** 공용 Core와 Frame을 연결한다. 렌더·음향·입력·저장의 기존 API 적합성을 점검한다. 동기 저장 경계 변경이 필요하면 별도 검증 후 반영한다. 재현된 게임 진행 방해 버그는 공용 수정으로 한 번 해결하고 각 클라이언트에 우회 코드를 넣지 않는다.
5. **웹 기준 고정:** 게임·복원 코드·에셋 산출물 해시를 고정한다. PWA와 Tauri 모두 이 산출물을 사용한다.
6. **Tauri Mac·PWA:** Tauri 파일 저장/종료와 PWA 설치/오프라인/업데이트를 연결한다. Mac 설치형 PWA도 같은 웹 빌드로 검사한다. 두 배포 방식에 별도 게임 코드를 만들지 않는다.
7. **교차 검사·배포 판단:** 다음 표를 검사하고 결과를 정본·TODO·릴리스 노트에 연결한다. feature→develop→main을 따른다. 구현·병합·공개 배포는 각각 기록한다.

| 검사 | 확인할 결과 |
|---|---|
| 복원 코덱 | 빈/가득 찬 5슬롯, 높은 진행도, 순서/강화/수량, 미확인 바이트의 왕복 일치. 네이티브/Wasm 코드 일치 |
| 잘못된 입력 | 다른 게임/버전·손상·잘림·초대형 입력·범위 초과를 저장 전에 거부하고 기존 데이터 보존 |
| 교차 복원 | iPhone→Android→웹→PWA→Tauri→iPad 및 역방향, 전체/단일 슬롯과 설정 선택, 재시작 후 실제 UI/전투 상태 일치 |
| 공용 규칙 | 80미션 승패·진행, 모든 생산/강화/무기·스킬·긴급지원, 동일 입력·난수의 상태 추적 대조 |
| 화면·입력 | 슬롯·생산·배치·강화·정지·복원 버튼 직접 누르기. iPhone/iPad/Galaxy와 Mac 창 크기별 화면/터치 대응 |
| 저장 중단 | 저장 단계별 종료·용량 실패·손상 파일·중복 창에서 마지막 정상값 또는 대기 복원 유지. 성공 오보고 없음 |
| 웹 배포 | 최초 다운로드·오프라인 재실행·새 버전 업데이트·이전 캐시 제거 뒤 진행 유지. 설치 PWA와 일반 탭 각각 확인 |
| 플랫폼 회귀 | 기존 iOS/iPadOS/Android 일반·치트 빌드, 기존 저장 바이트·게임 상태·음향 복귀·프레임/메모리 비교 |
| 종료 | 검사 앱 종료와 홈/데스크톱 복귀 확인. Tauri 종료 메뉴·Cmd+Q·창 닫기와 저장 대기 구분 |

현재 MachDefense 네이티브 Mac 앱은 없으므로 HeavyMach1 때처럼 Mac 두 버전을 대조했다고 기록하지 않는다. Mac에서는 웹/PWA/Tauri끼리 비교하고 게임 결과는 기존 Apple·Android와 대조한다.

## 개발 중 모듈 문제가 발견됐을 때

증상만 보고 Core를 고치지 않는다. 같은 저장·입력·난수·틱을 네이티브 검사와 Wasm 검사에 넣고, 게임 상태와 Frame 출력을 대조한다. 상태와 Frame은 같은데 화면·소리·저장 결과만 다르면 해당 출력 연결부터 조사한다. 상태가 다르면 컴파일 조건·자료형·수치 처리·시간 전달을 확인한 다음 공용 계산을 조사한다.

| 발견한 문제 | 수정 위치와 절차 | 재검사 |
|---|---|---|
| WebGL 알파·크롭·레이어, 포인터 좌표, 브라우저 음향 허용 | Web 렌더/입력/음향 어댑터. Core나 기존 Apple/Android에 보정식을 넣지 않는다 | 웹·설치 PWA·Tauri의 같은 장면/버튼/음원 |
| PWA 자원 다운로드·오프라인·업데이트 | Distribution/Web. 진행 저장소와 자원 캐시를 분리한다 | 신규 설치·이전 버전 업데이트·오프라인 재실행 |
| Tauri 저장 파일·Quit·창 복원 | Desktop/Tauri. 게임 파일을 수정하지 않고 OS 서비스 연결을 고친다 | 메뉴 종료·Cmd+Q·창 닫기·강제 종료 후 재실행 |
| 같은 입력에서 네이티브/Wasm의 게임 상태 차이 | 컴파일/호출 경계부터 확인한다. 공용 코드 결함이 입증되면 작은 별도 수정으로 처리한다 | 같은 상태 추적, 관련 기능, Apple/Android 회귀 |
| 원본부터 있던 게임 규칙과 재개발의 차이 | 원본·포팅판 증거를 대조하고 Core에서 한 번 수정한다 | 원본 대조 + 네이티브/Wasm 동일 조건 |
| 저장 완료 통지·복원 중단 같은 공용 계약 부족 | Contracts/SaveTransfer와 필요한 어댑터만 별도 커밋으로 바꾼다. 소비 플랫폼을 함께 갱신한다 | 성공·실패·늦은 완료·중단·재시작·오래된 메모리 덮어쓰기 |
| 이미 공유한 코드를 웹으로 복사해야 할 것처럼 보이는 경우 | 먼저 의존성을 조사한다. OS 의존부만 인터페이스로 빼고 게임 구현은 기존 모듈에서 사용한다 | 기존 호출 순서·게임 상태·Frame·저장 바이트 비교 |
| 게임 진행과 무관한 기존 타이틀 그림·문서 후속 | TODO에 근거와 범위를 남긴다. 이번 웹 코드에 임시 처리를 넣지 않는다 | 해당 과제에서 별도 검사 |

공용 수정이 필요한지는 웹 실행기 최소 구현 단계에서 확인한다. 플랫폼 완성 뒤 한꺼번에 모듈을 재설계하지 않는다. 한 문제가 확인될 때마다 위치를 판별하고 해당 단계에서 해결한다. 공용 API가 바뀌면 기존 소비자의 컴파일과 관련 회귀 검사를 마친 뒤 웹 구현을 이어간다.

### 브랜치와 수정 기록

- 현재 구현은 develop `ae08521`을 기반으로 문서 작업 다음에 분기한 `feat/web-pwa`에서 진행한다. 공용 복원 연결과 웹 어댑터의 변경·검사를 구분해 기록한다. develop/main에 직접 작업하지 않는다.
- 생산 HUD와 저장 확장 계약을 먼저 정리하고 복원 모듈에 반영한다. 웹 저장 연결의 작은 실행 예제는 이 계약을 검토하는 데 함께 사용한다. 복원 코덱 검사를 위해 전체 웹 게임 완성을 기다릴 필요는 없다.
- 이미 develop에 있는 코드의 결함은 develop 기반 `fix/...` 브랜치에서 수정·검사한 뒤 develop을 거쳐 작업 브랜치에 가져온다. 작업 브랜치 안에서 새로 만든 코드의 결함은 그 브랜치에서 별도 커밋으로 수정한다.
- Core/Contracts의 변경이 필요하면 변경 이유, 이전/이후 호출 절차, 영향 파일과 플랫폼, 저장 호환성, 검사 결과를 기록한다. 무관한 리팩터링을 함께 넣지 않는다.
- 검증된 웹 실행기를 develop에 반영한 뒤 PWA·Tauri 포장 작업을 별도 브랜치에서 진행한다. main에는 검증한 develop만 병합한다. 배포 시점은 사용자의 공개/배포 지시를 따른다.
- 기존 iOS·iPadOS·Android를 사용하는 파일은 기본 보존 목록에 둔다. 복원 UI·서비스 연결처럼 승인된 기능에 필요한 변경은 파일별로 공개하고 검사한다. 기존 게임 계산의 변경과 플랫폼 연결의 추가를 한 항목으로 숨기지 않는다.
- 기여자 소스를 재사용하면 원래 작성자·라이선스·참고 커밋과 수정 파일을 기록한다. HeavyMach1 저장소나 기여자의 원래 커밋은 수정하지 않는다.

각 이슈 기록에는 재현 환경, 기대/실제 결과, 책임 모듈, 수정 파일, 기존 플랫폼 영향, 검사 결과, 남은 조건을 남긴다. TODO와 트러블슈팅, 이 통합 보고서에서 같은 이슈 ID를 참조한다. 실패한 조건은 완료로 표시하지 않는다.

### 단계별 중단·진행 기준

| 단계 | 다음 단계로 넘어갈 조건 | 실패했을 때 |
|---|---|---|
| 공용 복원 | 네이티브/Wasm 동일 코드, 5슬롯 왕복, 잘못된 입력 거부, 기존 저장 보존 | 코덱/저장 계약만 수정하고 관련 검사 반복 |
| 웹 실행기 | 슬롯 생성부터 실제 생산·교전·승리/실패·강화·저장 재실행, 80미션 자동검사, UI 직접 입력 확인 | 상태 계산/Frame/출력 차이로 나누어 해당 경계 수정 |
| 웹 기준 고정 | 기존 Apple·Android 회귀와 웹 저장 실패·GPU/음향 복구 검사 통과 | 문제 해결 전 산출물 고정과 배포 보류 |
| Tauri Mac | 같은 게임 산출물 해시, OS 파일 저장·재실행·종료, 실제 전투·복원 확인 | Tauri 연결부 수정. Core 문제면 공용 수정 절차로 복귀 |
| PWA | 같은 게임 산출물 해시, 설치·오프라인 재실행·업데이트 후 저장 유지 | 배포/캐시 연결부 수정. 게임 데이터 자동 초기화 금지 |
| 배포 | 기기별 일반/치트 결과, 설치/복원 안내, 릴리스 노트와 실행 파일 버전 일치 | 통과 범위와 남은 조건을 보고하고 실패한 배포를 완료로 표시하지 않음 |
