# 검사 결과

iOS·iPadOS·Android 네이티브 앱과 웹·PWA가 같은 C++ 게임 코드를 사용한다.

일반 앱과 별도 저장을 쓰는 치트 앱으로 조건을 만든다. 전체 유닛·강화·무장·미션을 자동 검사하고, 실제 버튼 입력과 기기의 중단·복귀를 함께 확인한다.

## PWA 배포 후보 검사

2026-11-06 정식 빌드에서 Chrome 설치형 PWA의 독립 창·오프라인 재실행을 확인했다. Chrome·WebKit에서 코드 복원·Stage 36 진입·저장 재실행·GPU 복구·저장 실패 검사를 통과했다. [배포 검사와 Tauri 착수 조건](../evidence/pwa-release-20261106.md).

## 복원 코드 기기 간 이전

2026년 11월 6일 iPhone 저장을 iPad 치트 앱과 Galaxy 치트 앱에 복원하고 전체 42,496바이트를 대조했다. Galaxy 정식 앱은 코드 생성·복사·입력·취소 후 기존 저장이 유지됐다. Galaxy Chrome과 설치형 PWA에서도 같은 코드의 생성·복원을 확인했다. Galaxy PWA는 오프라인 새 실행·전투·재실행 후 저장 전체 바이트가 유지됐다.

나는 아이폰에서 만든 코드로 아이패드 PWA를 복원해 한 미션을 클리어했다. 아이패드 PWA에서 새 코드를 만들고 아이폰에 재복원한 뒤 스테이지에 들어가는 것까지 직접 확인했다.

## GitHub에서 새로 받은 소스로 빌드

v0.3을 인증 없이 새 폴더에 clone하고 iOS 일반·치트 시뮬레이터 앱, iOS 실기기용 Release 앱, Android 일반·치트 APK를 빌드했다. 새 Xcode 빌드 폴더와 빈 Gradle 캐시를 사용했다. 각 앱에 실행 자원 1,387개가 모두 들어 있었고 소스 저장소의 파일과 SHA-256이 같았다.

원본 IPA나 기존 제작 폴더의 파일을 복사하지 않았다. 새 시뮬레이터·에뮬레이터의 빈 저장에서 게임 진입과 생산도 확인했다. [새 클론 검사](../evidence/clean-clone-build-20261106.md) · [필요 도구와 빌드 방법](build-and-install.md)

## v0.5 강화·그림·운영 검사

웹 치트에서 생산 280·배치 120·특수공격 100조건과 HUD·강화·복원 130행을 검사했다. Chrome·WebKit 각각 포탑 144자세를 비교했고 실제 iPad에서도 조립·구매·저장·복원을 검사했다. iPhone·iPad·Galaxy에 정식·치트 v0.5를 설치했다.

운영 웹의 새 브라우저에서는 그림 44개·테이블 3개가 저장소와 일치했다. 구버전 캐시에서 첫 재진입할 때 실행 테이블이 이전 값으로 남는 경우가 있었다. 두 번째 실행에서 최신값을 확인했으며 첫 갱신 문제는 TODO에 남겼다. [기기별 검사와 배포 결과](../evidence/v05-release-20261107.md).
