# MachDefense GitHub 문서 정리 계획

2026-11-06. 문서 작업 브랜치 `docs/public-manuscripts-20261106`. main의 최신 릴리스는 v0.1이다. 웹·PWA 구현은 개발 브랜치에 있으며 게임 공개 배포와 Tauri Mac 구현은 아직 하지 않았다.

## 확인한 상태

README와 설치·아키텍처·검사 안내는 v0.1의 Apple·Android 상태를 설명한다. 개발 브랜치에서는 웹·PWA가 실행되지만 README에는 미구현으로 남아 있다. 현재 개발자의 변은 구매 경험과 복원 과정을 짧게 기록한 초안이다.

Chrome·WebKit의 실제 게임 실행에서 생산·전투·실패·재도전·승리·다음 미션과 저장 복원을 검사했다. 승패 조건은 치트 기능으로 만들어 검사했고 메뉴 입력도 실행했다. Safari 정식 웹판에서는 타이틀·슬롯·복원 버튼을 직접 눌렀다. Mac Chrome 설치형 PWA의 실행·종료도 확인했다. 실제 iPhone·iPad·Galaxy 설치형 PWA 검사는 남아 있다. [검사 근거](../evidence/web-pwa-20261106.md).

## 개발자의 변

[인터뷰 원문](developer-interview-20261106.md)에 후속 답변을 모은다. 첫 답변에서 시리즈 전체 복원이 처음 목표였고, HeavyMach2의 복원 범위를 고려해 MachDefense를 먼저 택했다고 설명했다. 원고의 도입에 이 순서를 반영한다.

본문은 [docs/RESTORATION.md](../RESTORATION.md)에 쓴다. HeavyMach 1의 개발자의 변을 바탕으로 개인적 배경과 화자의 어조를 이어 쓰고, 게임별 경험과 개발 내역을 MachDefense에 맞게 바꾼다. 새 원고를 여러 파일로 나누지 않는다.

참고본은 HeavyMach 1의 원격 main에서 확인한 [개발자의 변](https://github.com/gelb2/HeavyMach/blob/main/docs/RESTORATION.md)이다. 2026-11-06 fetch 후 이 파일의 마지막 변경은 `1360e657`이다. 오래된 작업 폴더의 수정본으로 덮어쓰지 않는다. 집필 직전에 원격 수정 여부를 다시 확인한다.

| 순서·소제목 초안 | 담을 내용 |
|---|---|
| HeavyMach에서 MachDefense로 | 2015년 잡지사, 2016년 필리핀 근무, 2017년 7월 개발자 전업과 HeavyMach가 준 영향. HeavyMach 1을 복원한 뒤 MachDefense로 이어진 순서 |
| 다시 실행하고 싶었던 게임 | 캐나다·미국 앱스토어에서 구매해 영어로 플레이했던 MachDefense의 기억. Internet Archive의 시리즈 모음에서 원본을 확보한 과정 |
| 직접 플레이하며 고친 것 | 포팅판과 재개발판의 가격·아이콘·선택 효과·음향 차이, 기지 발사 시 프레임 저하와 복귀 후 효과음 소실. 작성자가 발견한 현상과 Codex가 수정·검사한 결과 |
| 원작 위에 더한 것 | 화면 대응, 공통 모듈, 광고·결제 없는 반복 긴급지원, Android·웹 실행과 복원 코드. 실제 구현한 범위에 맞춰 설명 |
| 마지막 단락 | 사용자가 후속으로 제공할 문장이나 시를 별도 단락에 추가. 현재 본문에는 넣지 않음 |

- 화자는 사용자 본인인 ‘나’로 통일한다. 원작 제작진, 작성자의 기획·직접 플레이, Codex의 구현을 구분한다.
- HeavyMach의 진로 영향과 9년 3개월이라는 개인적 의미를 MachDefense에서 새로 생긴 사건으로 바꾸지 않는다.
- HeavyMach 1의 꿈·검색·발견 경위는 첫 복원의 계기로 쓴다. MachDefense도 같은 꿈과 검색으로 처음 발견했다고 쓰지 않는다.
- 럭스루나에·자동조준·새 항공기는 HeavyMach 1의 기능이다. MachDefense 추가 기능 목록에 옮기지 않는다.
- HeavyMach 1에서 받은 외부 PR을 MachDefense에 직접 받은 PR로 쓰지 않는다. 웹 구조를 참고한 내역과 기여자 출처는 크레딧에서 연결한다.
- 기존 사용자 원문과 별도로 제공한 글감은 보존한다. 새 개인사·대사·결말을 만들어 덧붙이지 않는다. ‘어제’처럼 작성 당시를 가리키는 말은 날짜와 맥락을 확인한다.
- 이미 있는 제작진·출처·배포 의향은 MachDefense의 실제 출처 및 사용자 발언과 대조한다. 게임 이름만 치환해 붙이지 않는다.

### 인터뷰 후속 반영 — 비영리와 추가 기능

[세 번째 답변](developer-interview-20261106.md#3-비영리-복원과-긴급지원락온의-기획-의도)의 개인적 시간 인식·비영리·이해관계자 연락 시 게시 중단 의사를 보존한다. 수익을 얻지 않겠다는 이유는 자신에게 개발자의 길을 알려준 소프트웨어와 제작진의 작업에 대한 태도로 설명한다. 기존 사용자 원문 밖의 개인사나 결말을 추가하지 않는다.

‘원작 위에 더한 것’에는 긴급지원의 두 목적을 함께 쓴다. 작동하지 않는 결제 버튼을 대체하고, 결제 없이 난관을 넘을 수 있도록 자원을 공급했다. 락온은 별도의 구상으로 설명한다. 원작의 적 배치·공격력·행동을 유지하면서 플레이어가 화면을 보고 판단할 기회를 더하려는 기능이다. 기존 크로스파이어를 보존하고 그 에셋·조준·사거리 로직을 재사용한다.

사용자는 기억하던 게임이 돌아왔다고 느낀 대상을 “모든것”이라고 답했다. 독자에게 바라는 것은 개발자의 변을 읽는 것이다. [네 번째·다섯 번째 답변](developer-interview-20261106.md#4-기억하던-게임이-돌아온-순간)을 반영해 특정 장면이나 독자별 메시지를 새로 만들지 않는다. 개발자의 변은 별도 전문으로 유지하고 README에서 연결한다.

## 방문자가 읽을 순서

README는 기술 배지 → 다시 만든 이유와 개발자의 변 링크 → Quick Play → 원작의 전투·성장 → 추가 기능 → 플랫폼별 설치·실행 → 검사·트러블슈팅·남은 과제 → 크레딧 순서로 정리한다.

Quick Play에는 배포를 확인한 게임 주소와 PWA 설치 방법을 놓는다. 브라우저에서도 바로 실행할 수 있게 안내한다. Tauri 다운로드는 실제 설치 파일을 제공할 때 추가한다. 기술 배지와 플랫폼 표는 출시된 버전과 개발 중인 버전을 구분한다. WebAssembly 실행을 arm64 전용으로 표시하지 않는다.

현재 Apple·Android의 복원 UI 서비스는 연결하지 않았다. 공용 코덱 완성을 모든 앱에서 복원 버튼을 쓸 수 있다는 설명으로 넓히지 않는다. 웹 복원은 전체 5슬롯을 교체하며 단일 슬롯·확장 설정은 후속 과제다.

## 작성과 배포 순서

1. 공개 안내의 기능·상태 표와 개발자의 변을 작성하고 위 문서들을 연결한다. 계획 등록은 현재 기능 브랜치에서 하고, 릴리스 원고 작성은 별도 문서 브랜치로 분리한다.
2. 원고를 처음부터 끝까지 읽어 인칭·수치·기능·플랫폼·날짜를 대조한다. 불필요한 면책·자기평가·작은 기능을 과장하는 제목을 삭제한다. 링크·이미지·배지·빌드 명령을 확인한다.
3. 사용자 진행 파일·복원 코드·원본 패키지·비공개 타 프로젝트 자료가 공개 문서나 첨부에 섞이지 않았는지 확인한다.
4. 공개 배포 범위가 정해지면 원격 main의 사용자 수정과 대조하고 작업 브랜치→develop→main 순서로 병합한다. 버전·태그·CHANGELOG·GitHub Release를 함께 맞춘다.
5. Pages 배포 후 실제 URL에서 다운로드·시작·PWA 설치·오프라인 재실행·진행 저장·코드 복원을 확인한다. 실제 모바일 결과와 배포 주소를 문서에 반영한다.
