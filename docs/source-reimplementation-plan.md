# 소스 재구현 · 2026-11-04

사용자 지시로 `feat/source-reimplementation`에서 재구현을 시작한다. 위메이드 1.0.3 포팅판을 비교 기준으로 사용한다. 기존 포팅판 검사의 남은 항목도 계속 확인한다. HeavyMach 1에서 검증한 C++20 공용 코어·Objective-C++ Apple 실행기·GPU 스프라이트·재사용 음향 자원 구성을 따른다.

## 구현 순서 — 2026-11-04 사용자 수정

현재 원본 분석·자원 준비·저장·메뉴·전투 연결과 일반/치트 빌드를 진행했다. 이후 작업은 다음 순서로 한다. **80개 미션의 진행·보상·저장 검사는 원작 기능 완성 단계에 포함한다. 전체 검증을 마친 뒤 iPhone·iPad 화면 크기 대응을 시작한다.**

1. **치트앱 준비.** 일반 앱과 같은 게임 코드를 사용하면서 검사 시작 조건을 설정하는 화면을 만든다. 미션·자금·강화·장비·특수공격·유닛·체력을 조절하고 모든 게임 버튼을 직접 검사할 수 있게 한다.
2. **원작 기능 완성과 80개 미션 검사.** 부품 조립·생산·진형·이동·표적·발사·피격·연출·강화·보상·승패를 구현하면서 해당 기능을 포팅판과 대조한다. 80개 미션 각각의 진입·승리·실패·해금·보상·다음 미션·저장·재실행을 이 단계에서 검사한다. 마지막 미션 처리와 새 프로필부터의 연속 진행도 포함한다.
3. **전체 검증.** 앞 단계에서 확보한 결과를 기준으로 기능 간 간섭, 치트를 끈 비용·피해·진행, 앱 중단·복귀, 장시간 전투·저장·재실행, 메모리·프레임·음향을 검사한다. [전체 무기·효과 프레임 검사](validation-plan.md#전체-무기와-효과의-프레임-검사)를 치트앱에서 반드시 수행하고, 기지·아군·적 무장과 특수기술의 강화 단계별 측정 누락을 확인한다. 제품 자원만으로 새 checkout에서 빌드되는지도 확인한다. 80개 미션 검사를 이 단계까지 미루지 않는다.
4. **iPhone·iPad 화면 대응.** 검증한 원작 논리 좌표를 기준으로 메뉴·도움말·전장·HUD·버튼과 터치 위치를 화면 크기에 맞춘다. 사거리·이동 속도·생산 시간·적 활성화 조건은 보존한다.
5. **화면 변경 후 재검사.** 기기별 배치·가독성·부품 연결·터치·모달·스크롤·생명주기를 확인한다. 앞 단계와 같은 조건으로 전투·진행·저장을 비교하고, 화면 변경이 영향을 준 범위를 다시 검사한다.
6. **후속 플랫폼.** Apple 버전 비교를 마친 뒤 공용 코어·자원에 웹·PWA·Tauri 실행기를 연결한다.

## 재개발판 치트앱

현재 일반·치트 앱의 식별자와 저장 컨테이너는 분리돼 있다. 5쪽 검증 화면을 구현했고 시뮬레이터에서 직접 조작했다. [치트·캠페인 검사](evidence/source-cheat-campaign-20261104.md)에 결과를 기록했다. 포팅판 치트 검사와 재개발판 치트 검사는 앱·저장 형식을 구분한다.

- 80개 미션 선택, 크레딧·셀·기지/장비 강화 단계·보유 장비와 장착 상태·특수공격 수량을 설정한다.
- 원본 정의의 아군·적 유닛을 선택해 생성하고 체력을 조절한다. 기지 파괴로 승리·패배 분기와 결과 화면을 재현한다.
- 생산·강화·장비 교체·특수공격·진형·일시정지·도움말·저장 종료 등 실제 버튼을 눌러 검사한다. 상태를 직접 바꾸는 검사만으로 버튼 동작을 확인했다고 기록하지 않는다.
- 일반 앱과 동일한 전투·UI·저장 코드를 사용한다. 치트는 시작 조건과 진단 명령을 제공하며 별도 전투 규칙을 만들지 않는다. 검증용 조작은 일반 앱에서 사용할 수 없게 한다.
- 검증 버튼도 원작 스프라이트·공통 렌더·입력 절차를 사용하고 영문으로 표시한다. 실제 텍스트 입력에 필요한 경우만 OS 입력을 사용한다.
- 사용자 실제 저장과 분리한 시험 슬롯을 쓴다. 설정 변경 전 조건, 변경한 값, 실행 결과, 저장 후 재실행 결과를 기록한다.
- 전체 해금·즉시 파괴 검사와 원래 해금·교전·보상 검사를 따로 수행한다. 치트로 열린 미션 목록이 정상 해금 검사를 대신하지 않는다.

## 80개 미션 완료 기준

원본 미션 ID와 표를 기준으로 미션별 검사 결과를 남긴다. 각 기록에는 시작 슬롯·장비·강화·사용한 치트, 포팅판 비교 결과와 실패 증거를 연결한다.

진입·적 배치·생산·교전·승리/실패 화면·보상·해금·다음 미션·저장 후 앱 종료/재실행을 확인한다. 80번째 미션의 최종 처리, 이미 완료한 미션 재플레이, 실패 후 재도전, 프로필 간 분리도 검사한다. 배열·맵 로딩 검사와 실제 게임 진행 검사를 구분한다. 강제 기지 파괴 검사는 상태 전환을 검사하며 자연 교전 승패는 별도로 확인한다.

## 공용 코드와 플랫폼 경계

`Sources/Core`는 게임 상태·메뉴·버튼·그리기 명령·저장 직렬화를 소유한다. `Resources`는 공용 에셋을 소유한다. `Apple` workspace 아래 앱과 `Modules`의 공용 모듈이 이를 사용한다. 전투 중 파일 쓰기와 프레임마다 이미지 생성은 추가하지 않는다. 인게임 버튼을 UIKit·XML·DOM으로 따로 만들지 않는다.

후속 웹판은 같은 C++ 코어를 WebAssembly로 빌드하고 WebGL·브라우저 입력·음향·저장 어댑터를 연결한다. 웹/PWA/Tauri 소스는 각각 Web·Distribution·Desktop/Tauri에 둔다. 웹 구현은 Apple 버전의 동작 비교 이후 진행한다. HeavyMach 1의 웹 기여 코드를 맥디펜스 게임 로직으로 복사하지 않는다.

## 검사 기준

- 원본 데이터 수·ID·수치, 표 해독, 저장 체크섬과 5슬롯 왕복을 확인한다.
- 메뉴 그림과 버튼의 눌림·해제·취소·모달 입력 차단을 비교한다.
- 생산 가격·에너지 소비·대기 시간·부품 조립·피해·보상·강화 비용을 같은 조건에서 비교한다.
- 실제 승리·패배 화면, 다음 미션, 저장 후 앱 종료·재실행을 검사한다.
- 이름 입력·영문 표시·유닛 자글거림은 기존 관측 ID와 연결한다.
- 전체 게임 완성, 한 화면 실행, 코어 검사 통과를 각각 기록한다. 미구현 기능을 임시 동작으로 채워 완료라고 쓰지 않는다.
