# 헬기·VTOL 부품 제작

`mach-series-art`로 원작 화풍과 참조를 고른 뒤 적용한다. HeavyMach1의 `integrate-game-art`에서 채택본 추적·원본과 같은 크기 비교 절차를 가져왔다. HeavyMach1의 측면 좌표나 무기 수치를 MachDefense에 복사하지 않는다.

## 채택본과 원작 비교

- 실제 소비 PNG에서 제작 원본·크롭·배율·SHA를 역추적한다. 기각된 aircraft-v1과 미채택 16색 시안을 참조로 쓰지 않는다.
- 원작 탱크·메크 세 종 이상에서 밝은 금속, 중간톤, 틈, 위험 표식, 마모의 크기와 면적을 확인한다. 외부 기체는 형태 참고이며 재질·도트 참고는 MachDefense 원작이다.
- 색 수를 임의로 16개로 줄이거나 알파를 이진화하지 않는다. 원작처럼 다단계 색과 부분 알파를 보존한다. 색 수만 같다고 화풍 일치로 판단하지 않는다.
- 생성 원본과 게임 크기를 모두 비교한다. 축소는 제작 시 한 번 처리하고, 실행 중 PNG 재생성이나 텍스처 재업로드를 하지 않는다. 필터는 실제 출력으로 선택한다. 새 기체 때문에 기존 유닛의 필터를 바꾸지 않는다.

## 몸체·무장 분리

1. 몸체에 무기 그림이 붙은 시안은 조립 완료본으로 취급하지 않는다. 별도 무기 PNG를 만들고 몸체에 남은 중복 포신·발사관을 제거한다. 회전축 아래의 지지 구조는 몸체에 남긴다.
2. 몸체, 각 무기, 로터의 이미지 크기·그림 범위·기준 방향·결합점·총구를 기록한다. 원작 `PartsInfo`의 socket 0은 결합 기준이며, `MachInfo` 자식의 parentSocket이 부모 연결점을 선택한다. 원작 무기 부품 type 4와 로터에 사용하는 독립 회전 부품 type 7의 동작은 소비 코드에서 대조한다.
3. `World::configureWeapons`는 조립 부품 이름으로 무기 표를 찾는다. 무기 그림만 붙이고 별도 좌표에서 발사하지 않는다. 새 부품 이름과 재사용할 원작 무기 행의 대응을 자료로 남기고, 원작 행을 수정하지 않는다.
4. `World::updateWeapons` → `BattleModels::pose` → `PartPose::muzzle`로 총구 위치를 구한다. 조준·반동·총구 효과·사운드·탄환 생성·데미지는 원작 경로를 사용한다. 몸체의 그림 방향 보정이 표시 좌표와 발사 좌표에 동일하게 적용되는지 검사한다.
5. 무기별 발사 방향을 독립적으로 확인한다. 좌우 무장 복제 시 이미지 반전만 하고 총구가 반대편에 남지 않게 한다. 두 발 발사 요구는 원작 행의 연사 수·간격과 총구 순환을 확인해서 구현한다.

## 로터·그림자·비례

- 2026-11-08 사용자가 회전 원반을 기각하고 직전 로터로 되돌리도록 지시했다. 현재 채택은 `rotor-light-v2.png`·`rotor-heavy-v2.png`와 원래 부품 알파다. 회전 원반을 임의로 다시 적용하지 않는다. 각속도와 실제 영상은 함께 확인하고 이후 로터 변경은 최신 사용자 검수를 따른다.
- 몸체에 바닥 그림자를 구워 넣지 않는다. 기존 부품 그림자 경로에서 동일 실루엣·회전·이동을 사용하고 비행 높이에 따른 지면 간격을 적용한다. 로터 그림자도 회전 표현과 일치시킨다.
- PNG 여백·그림자·충돌 반경을 크기로 삼지 않는다. 원작 기준 유닛과 같은 World 배율에서 조립된 몸체·무장·로터의 전체 범위를 측정한다. 무장 조준과 로터 회전 중 최대 범위도 확인한다.
- 기울임 자세마다 연결점과 총구가 몸체에서 분리되지 않는지 본다. 일반 제작은 균일 배율을 사용한다. 소형 헬기 폭만 +20%는 이 기체에 대한 사용자 예외이며 다른 기체에 확장하지 않는다.

## 검사와 기록

실제 World에 원작 기준 유닛과 새 기체를 함께 둔다. 몸체 단독·무장 단독·조립본, 이동·조준·발사·피격·파괴·일시정지·그림자를 검사한다. 새 기체의 탄환·총구·발사음과 실제 피해를 함께 확인한다. 원작 스폰 표·무기 행의 보존, 전투 중 추가 저장 0회, 준비 후 추가 텍스처 업로드 유무도 확인한다. 정적 조립 그림을 전투 검증으로 보고하지 않는다.

현재 채택 크기·변환·측정은 [aircraft-scale](../../../docs/research/aircraft-scale-20261107.md), 무장과 후속 제작은 [aircraft-plan](../../../docs/research/aircraft-plan-20261107.md), 실행 자원은 [manifest](../../../Art/Aircraft/runtime/manifest.json), 포장은 [pack_aircraft_art.sh](../../../tools/pack_aircraft_art.sh)를 읽는다. 현행 포장 스크립트는 무장 분리본 9개를 내보낸다. `WeaponCatalog::addAlias`는 원작 정의를 새 파츠 이름에 복사하고 원작 이름 덮어쓰기를 거절한다. 첫 구현의 [실행 결과](../../../docs/evidence/aircraft-modular-20261107.md)와 [360각도 측정 도구](../../../tools/measure_aircraft_bounds.py)를 재사용한다. 로터 교체 뒤 조립 크기가 달라지지 않는지 측정한다.

## 아군 VTOL 시험본

2026-11-08 사용자 지시에 따라 VTOL 외형은 임시 시험용이다. 아군 원본 P_Body_01/03/05/10/13/18/21/23/30/31/33/34를 도색 참고로 사용했다. 몸체·팬·날개·엔진·무기별 크롭과 균일 축소는 `tools/pack_vtol_trial.sh`에 있다. 실행 자원 19개와 SHA·조립 크기는 manifest를 확인한다. 새 시안을 만들 때 시험용 그림을 최종 승인본으로 취급하지 않는다. 기울임 그림과 자세별 총구는 후속 작업이다.

좌우 이동 방향을 바꿀 때에는 속도를 즉시 반전하지 않는다. 새 기체의 속도 벡터를 서서히 줄여 0을 거친 뒤 반대로 가속한다. 위치 차분·속도 로그·실제 전투 영상으로 양쪽 전환을 확인한다. 기울임 그림과 이동 속도 처리를 별도로 검사한다.

## 승인 형상 복구 — 2026-11-08

크기·색 보정 요청을 새 기체 디자인 생성으로 확대하지 않는다. 현행 입력은 `tools/pack_aircraft_approved.py`와 `runtime/approved-restoration.json`이다. `pack_aircraft_body_revision.py`의 v2/v3 몸체는 사용자가 기각했다. 승인한 원본 몸체를 직접 축소하며, 몸체 두께와 날개 포함 전체 폭을 구분해 표기한다. 회색으로 바꿨다는 이유만으로 질감 일치를 주장하지 않는다. 기울임 중 다른 생성 그림으로 바뀌는지 실제 게임에서 확인한다.

## 중앙 동체·미리보기 검사 — 2026-11-08

최신 기준은 소형·Orca 중앙 동체 두께 = Lv.10 MachineGun 몸체 41의 2/3, 건쉽 중앙 동체 폭 = E_Tank32_Body 104의 3/4다. 로터 지지부 포함 전체 폭으로 대체하지 않는다. 그림 원본의 중앙 동체 경계는 수동 측정이고 포장 결과에는 픽셀 반올림이 있다. 측정 경계·목표·전체 조립 범위를 구분한다.

날개형 로터를 유지하되 확대 포장은 heavy-body-v4.png의 보존된 고해상도 날개에서 한다. ALightRotor 60×60, AHeavyRotor 66×66이며 원반형으로 교체하지 않는다. 현행 크롭·배율·해시는 pack_aircraft_approved.py와 approved-restoration.json이 정본이다. 과거 rotor-light-v2/rotor-heavy-v2의 작은 PNG를 그대로 복사하지 않는다.

항공기 기울임 메시는 Sprite의 nearest 설정을 Apple·Android·Web까지 전달한다. 승인 몸체와 다른 생성 그림으로 교체하지 않는다. 총구에도 같은 기울임 변환을 적용한다. 확대 후 포신 끝을 네 기체 모두 검사한다.

전장의 크기를 키우면 생산·강화·획득 아이콘도 확인한다. 기존 조립 출력의 경계를 캐시해 원래 아이콘 칸에 맞추며 세계 좌표의 기체 크기를 축소하지 않는다. 실제 GameSession 큐로 생산한 iPad 화면을 보고 가격·이름·테두리와 겹치면 다시 수정한다. [실행 기록](../../../docs/evidence/aircraft-visual-repair-20261108.md).
